# Android driver

Does: emulators in an owned AVD home behind Simlock's own adb server, and USB phones on the default adb server.
Entry: `index.ts` → `AndroidDriver.create(options)`; also `androidPrerequisites`, `hostAbiFor`, `ANDROID_PASSTHROUGH_TOOLS`.
Uses: core, ports, `../installer-process.ts`. Never imports: bus, leasing, daemon.
Parent: [drivers](../AGENTS.md). Flows: [device selection](../../../docs/internal/flows/device-selection.md).

## How it works

Start — `AndroidDriver.create`:

1. `locateSdk`: first of `ANDROID_HOME`, `ANDROID_SDK_ROOT`, `~/Library/Android/sdk` (on Windows
   `%LOCALAPPDATA%\Android\Sdk`, and the tools are `adb.exe`, `emulator.exe`, `avdmanager.bat`, `sdkmanager.bat`) with
   `avdmanager` + `sdkmanager` (newest `cmdline-tools/*/bin`, else `tools/bin`), `emulator`,
   `platform-tools/adb`. None → `SdkMissingError`: Android absent, no rejection.
2. `ensureOwnedRoot`: the AVD home, default `$SIMLOCK_HOME/devices/android`.
3. `AdbServerSupervisor.start`. Failure → `AdbServerUnavailableError` → `driver.adb-server-rejected`.
4. Announce every console port 5586–5682 to that server, so emulators that outlived the last daemon reattach.

`androidPrerequisites` runs `emulator -help` (30 s) and reports `android-emulator` when a flag every launch passes is missing. Every `adb`, `emulator`, `avdmanager` call carries `ANDROID_AVD_HOME=<root>` (seed making: `<root>/sources/<source id>`; a copy's boot: `<root>/<device id>`) and `ANDROID_ADB_SERVER_PORT=<port>`.

Simlock's adb server — `adb -P <port> nodaemon server`, env `ADB_EMU=0` (no scanner),
`ADB_USB=0`, `ADB_MDNS=0`, `ADB_REJECT_KILL_SERVER=1`, `ADB_LOCAL_TRANSPORT_MAX_PORT=5683`:

1. Port listening + live record → adopt. Listening, no record → `occupied`.
2. Record alive, port silent → reap. Then spawn, write the record, wait for the port → else `start-failed`.
3. Reap = its command line (`ProcessSupervisor.commandLine`) must show `adb` or `adb.exe`, `-P <port>`, `nodaemon`; SIGTERM, then SIGKILL. An unreadable one keeps the record.
4. `dispose` reaps it, unless `adb devices` still lists an emulator: then it leaves the server and its record for the next daemon to adopt, because an emulator whose server is gone starts an adb `fork-server` on the port, which the next start refuses as `occupied`. Emulators are spawned unref'd and outlive the daemon.

Provision — `provision`: every device is a copy of a seed, or of the ready baseline source named by `options.source` (a lease naming a baseline): then steps 1–3 are skipped and step 4 copies that source's folder.

1. Profile from `Catalog.profileFor`: the `resolveSpec` cache, else `DeviceProfileRegistry.resolve`. Image: installed, fitting, at the spec's API level. Order: host-ABI `google_apis` → host ABI → `google_apis` → any. With an image tag: that tag only, host ABI first.
2. Seed for `<model>|<system image package>`: a `ready` row recomputed on each provision (`emulator -version`, installed images). Stale (`system image … is not installed` / `changed from revision …`, `emulator changed from … to …`, `android.emulator launch settings changed`) → destroyed and made again; the reason is stored by `listSources` and clears when things match. One make per kind at a time (lock); a `making` row of an earlier process, or older than 900 s, is swept (its emulator stopped by its path) at the next listing or make of that kind.
3. Making: row `making` → `avdmanager create avd -n simlock -k <package> -d <profile>` in `<root>/sources/seed_<id>/` (SDK profile id, else the first `avdmanager list device`; devices.xml / library profiles write `config.ini` and `boot.prop`) → cold boot → `shell sync` + `shell reboot -p` (60 s) → cold boot → `emu avd snapshot save simlock_boot` (60 s) + `snapshot list` → `emu kill` → row `ready` with `configHash` and size. Any failure removes folder and row.
4. Copy: `Filesystem.copyTree` (600 s) of the seed's `simlock.avd` into `<root>/<device id>/`, `simlock.ini` written with its `path=`; failure removes the folder. `configHash` = image path@revision, `emulator -version`, the `config.ini` `hw.*` / `image.sysdir.1` / `disk.dataPartition.*` lines (not `hw.device.hash2`), `headless`/`gpu` when not default; it is kept only to judge a seed stale.

Boot — `makeReady` (lock per AVD folder). Output goes to `emulator.log` in the device's AVD folder (0600, truncated at each start); an emulator that exits before it is ready fails the boot with `DriverCrashError` quoting that log's last 10 lines:

1. A copy: `-snapshot simlock_boot`; the emulator cold-boots the same disk itself when the snapshot does not load (`snapshot-cold-boot` with `deviceId`, past 12 s). Never `-wipe-data`, except a device made before copies (once). Always `-no-snapshot-save`, and `-grpc <console port + 3000> -grpc-use-token` (without `-grpc`, `-port` leaves the emulator with no gRPC endpoint and no `avd/running` discovery file), and `-crash-report-mode never` (a stale crash dump otherwise opens a modal consent dialog that blocks the boot; `never` deletes the dumps in the database it reads, so the spawn env sets `ANDROID_EMU_CRASH_REPORTING_DATABASE` to `<root>/emu-crash.db`, never the user's shared `/tmp/android-<user>/emu-crash-<version>.db`).
2. Console port reserved at the first `prepare` boot in this process: even 5586–5682, not in
   `adb devices`, not reserved, port, port+1 and port+3000 (gRPC) not listening.
3. Ready = `sys.boot_completed` 1, `init.svc.bootanim` stopped or unset, `adb emu avd path`
   names the device's own AVD folder (or the same `realpath`), else `DriverCrashError`, and
   `adb shell pm path android` exits 0 printing `package:` (else keep polling). Silent serial past 5 s → re-announce.
4. Write the mark: `simlock.mark=<token>` in `config.ini` and `/data/local/tmp/simlock-mark.json`.
5. `purpose: "recover"`: cold boot only (`-no-snapshot-load`), on the recorded port. No wipe.

Reclaim — `reclaim`: physical only (uninstall every user app not on the enrollment list; returns `ready` / `uninstall`). A virtual device is destroyed at release, so `reclaim` and `reclaimStrategy` of one throw `virtual devices are not reclaimed`.

Ownership gate: before any `emu kill`, `adb emu avd path` (5 s timeout, asked every time, never cached) must name this device's own AVD folder; unreachable, timed out or another path → nothing is sent. The shared AVD name `simlock` is never evidence.

`shutdown`: gate, then `adb emu kill`, wait, SIGKILL. `destroy`: kills the emulator this process started, or after a restart each attached emulator whose bounded `emu avd path` names this AVD (a serial that cannot answer → refuse; another path → left alone), then deletes `<root>/<id>/` (a device made before copies: `avdmanager delete avd`), frees the port and its tunnel ports. `listManaged`: `<root>/<id>/simlock.avd` and `<root>/*.avd` (never `<root>/sources/`) + `adb devices` + `ro.boot.qemu.avd_name` + `emu avd path` per serial; a serial counts for the device whose own folder it answers.

Sources — `listSources`: every `ready` seed (model, API level, tag, size, `staleReason`), a sources folder no row names as an orphan. `destroySource`: stops the emulator by path, deletes folder and row. `removeComponent` destroys that image's seeds after the uninstall; one that fails stays, listed stale.

Profiles — library (`profiles/`), SDK (`avdmanager list device`), devices.xml
(`$ANDROID_USER_HOME/devices.xml`, else `.android/devices.xml` under `ANDROID_PREFS_ROOT`, `ANDROID_SDK_HOME`
or home). First case-insensitive name match wins and classes the model by the profile its name resolves to. A
devices.xml name the library shadows → advisory `device-profile-hidden`. SDK class from `Tag`: none `phone`,
`android-tv` `tv`, `android-wear` `watch`, `android-automotive*` `auto`, `android-desktop` `desktop`.

Fit — `fits(profile, image)`: API range, image kind (tag), Play Store, tablet. The catalog's
`modelRuntimes` lists only API levels with a fitting image.

Components — a component is an API level. `installComponent` runs
`sdkmanager --install system-images;android-<api>;google_apis;<hostAbi>`. A license refusal
runs `sdkmanager --licenses` only under `downloads.acceptAndroidLicenses` (false), else
`AndroidLicenseNotAcceptedError`. Reserves 2 GiB on the SDK root. `removeComponent`:
`sdkmanager --uninstall` (then its seeds are destroyed), refused while an AVD in the user's AVD home names the image.

Physical — port 5037, USB transports only. Before every command `DefaultAdbServerGate.check`:
the 5037 server's protocol must equal Simlock's `adb version`; nothing listening is open.
Mismatch or unreadable → no command, advisory `adb-protocol-mismatch`. Enrol reads model,
`ro.build.version.sdk`, current user, `pm list packages -3`. Class is always `phone`.

Passthrough — virtual: `adb -P <port> …`; with a device that has an address (`device.exec`) `-s <serial>` goes
first unless the subcommand is on the no-device list (ADR 0047). Refused: another `-s`, `-e`, `-d`, `-t`,
`adb` on a non-Android lease, `kill-server`, `disconnect`, `emu kill`, `emu avd stop`, every `emu avd snapshot` except `list`, other
globals (a lone `--version`/`--help` passes), a bare `shell` with no terminal. Physical: `adb -P 5037 -s <serial> …`;
refuses any leading flag, server and transport verbs, `reboot` to bootloader/recovery/sideload/fastboot.

Lease environment: virtual `ANDROID_ADB_SERVER_PORT=<port>`; physical `ANDROID_ADB_SERVER_PORT=5037`, `ANDROID_SERIAL=<serial>`.

No slim: `resolveSpec` ignores `mode` and returns a full spec. `fresh` is core's.

Screen — `screenCapture` and `input`, only when `create` got `scrcpyServerPath` and `tcpStreamConnector`: [screen](screen/AGENTS.md), [input](input/AGENTS.md).
Tunnels — `deviceTcp` (`device-tcp.ts`), only when `create` got `tcpListener`: `reverse` listens on a free loopback port in 47000-47999 (busy ones skipped; none free → `TUNNEL_FAILED`) and runs `adb reverse --no-rebind tcp:<device> tcp:<port>` on the device's own server (an emulator's on Simlock's port, a phone's on 5037 behind the gate), 10 s per call; `cannot rebind existing socket` → `TUNNEL_PORT_IN_USE`, any other failure → `TUNNEL_FAILED` (message cut to 200 characters). `connect` (needs `tcpStreamConnector`, else `TUNNEL_FAILED`) opens `tcp:<port>` through `openDeviceSocket` on the screen's target, with no `adb forward`: an emulator's configured server port, a phone's 5037 behind the gate (a closed gate rejects with its message); both answers share 5 s, then `timeout`, and `FAIL` rejects with its reason. `close` removes the rule, then the listener; a removal that fails keeps the listener, closing every connection at once, and the driver's `destroy` of an emulator (its `reclaim` of a phone) frees every port still held for it (`release`); a phone's reclaim reads its `reverse --list` first and frees only the ports no rule there points to (a failed read frees none). The refusal messages name the call (`reverse <port>: the device port is already reversed; remove that rule first`, `reverse <port>: <adb's message>`). Cleanup: an emulator's rules die with its folder at `destroy` (a virtual device is never reclaimed); a phone's reclaim runs no `reverse --remove-all` or `forward --remove` (safety rule 1: only the tunnel's own `reverse --remove` at socket close touches a phone). `deviceTcp.sweep` (only with `tcpListener`), called by the daemon before any request is served, removes on every present idle owned emulator the `reverse --list` rules whose host side is `tcp:47000`-`tcp:47999`; on a leased emulator it removes nothing and keeps the ports those rules point to from the next `reverse` until its destroy; on a phone, idle or leased, it only reads the rules and keeps those ports the same way. A failed removal is a `warn`; reclaim and start go on.

Plain facts: `listCatalog`, a resolve of a model the library lacks and a library provision (seed) share one `AvdmanagerDeviceList`: `avdmanager list device` runs again only when the size or modified time of a file it reads profiles from changed, or one appeared or went: the tools package's `lib/sdklib/sdklib.core.jar` (legacy `tools/lib/sdklib*.jar`) and `source.properties`, the user's devices.xml, `devices.xml` in each `system-images/*/*/*` and `add-ons/*` directory (a new image is a new path), and `devices.xml` and `source.properties` in each `extras/*/*` directory (avdmanager reads an extra whose `source.properties` says `Extra.Path=DeviceProfiles`).
Otherwise the last good answer is served; a failed run is not kept; concurrent callers share one run. The sdkmanager catalog is never read. Existing devices are not re-checked for fit.

Reads only: the user's AVD home, devices.xml, the SDK.

## Rules

- Ownership is root membership, proven at boot and in running observations by `emu avd path` against the device's own folder, never a name.
- The 5037 server is never started, stopped or adopted on purpose; physical commands pass the gate first.
- A recovery boot never wipes and never loads a snapshot. A seed is never leased or booted after its snapshot save.
- A stored port is not trusted after a restart (#52); pinned by `two-instances.test.ts`.

## Known gaps

- **Simlock's adb server is stopped by pid only.** `ADB_REJECT_KILL_SERVER=1` refuses its `kill-server`.
  No record → `occupied`: find it with `lsof` (Windows: `Get-NetTCPConnection -LocalPort <port>`; the message names `lsof` only), or move `drivers.android.adbServerPort` (one per instance).
- **A physical command can restart a 5037 server of another protocol (ADR 0022 §5).** One started between the gate and the command is restarted by adb's client. Run every adb on the host from one platform-tools.
- **Port checks are partial.** A port handed out but not yet booted reads free to another instance.
