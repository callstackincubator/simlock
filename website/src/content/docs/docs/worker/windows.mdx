A Windows PC can be an Android worker, alone or behind a gateway. When you finish this page, `simlock doctor` reports nothing missing and you have leased an Android emulator, run an `adb` command on it and released it.

Every command here is for PowerShell. The page was written for Windows 11 and Windows PowerShell 5.1, the one Windows ships. iOS simulators need a Mac.

## What works on Windows

| Works | Notes |
| --- | --- |
| Android emulator leases | Cold and warm. A cold lease on a fresh data folder can take four minutes, because Simlock first makes the seed emulator it copies from. |
| `simlock adb`, `simlock release`, `simlock nuke`, `simlock update` | `simlock update` needs Simlock installed with `npm i -g simlock`. |
| `simlock component install android <api-level>` | Installs a system image through `sdkmanager`. |
| A gateway, and a Windows worker joined to one | See [Join a worker to a gateway](#join-a-worker-to-a-gateway). |
| The web console | The worker's and the gateway's. |
| Screen streaming | Watching an emulator's screen in the console, also through a gateway. |
| Tunnels | `simlock tunnel` with `emulator adb`, `forward` and `reverse`. |
| agent-device | Through the worker's local profile. |
| `simlock setup` and `simlock mcp` | The skill file and the MCP server. |
| Start at login | `simlock daemon install` registers a Task Scheduler task that starts at login and restarts the daemon after a crash. See [Start it at login](/simlock/docs/worker/running-the-daemon#start-it-at-login). |

| Does not work | What you see |
| --- | --- |
| iOS simulators and iPhones | A lease for iOS fails with `NO_DRIVER` (exit 12). |

| Not checked yet | |
| --- | --- |
| Physical Android phones | Nobody has enrolled one on Windows. |
| `simlock cleanup` | Not run on Windows. |
| `simlock setup --mcp` registering Simlock with Claude Code or Codex | The skill file is written, but the registration has not been run on Windows. |

## Set up the machine

<Steps>

1. Install Node.js 22.13 or later with the installer from [nodejs.org](https://nodejs.org/en/download). It puts `node` and `npm` on your `Path`. Open a new PowerShell and check:

   ```powershell
   node --version
   ```

2. Let PowerShell run npm's scripts. Windows 11 refuses them under its default policy with `npm.ps1 cannot be loaded because running scripts is disabled on this system`. Allow scripts you wrote or that come signed, for your account only:

   ```powershell
   Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
   ```

   If you would rather not change the policy, write `npm.cmd` and `simlock.cmd` where this page says `npm` and `simlock`. The `.cmd` files are not scripts to PowerShell.

3. Install Simlock:

   ```powershell
   npm i -g simlock
   simlock --help
   ```

4. Turn on the Windows Hypervisor Platform, which the Android emulator uses to run fast. Without it the emulator does not start. In a PowerShell opened as administrator:

   ```powershell
   Enable-WindowsOptionalFeature -Online -FeatureName HypervisorPlatform
   ```

   Restart when it asks. Virtualization must also be on in the PC's firmware settings (often called Intel VT-x, AMD-V or SVM).

5. Install the Android SDK. Either install [Android Studio](https://developer.android.com/studio), which puts the SDK in `%LOCALAPPDATA%\Android\Sdk`, or unpack the [command-line tools download](https://developer.android.com/studio#command-line-tools-only) so that `sdkmanager.bat` is at `<sdk>\cmdline-tools\latest\bin`. With the command-line tools, tell Simlock where the SDK is:

   ```powershell
   [Environment]::SetEnvironmentVariable("ANDROID_HOME", "D:\Android\Sdk", "User")
   ```

   Without `ANDROID_HOME` or `ANDROID_SDK_ROOT`, Simlock looks in `%LOCALAPPDATA%\Android\Sdk`.

6. Add the SDK's tool folders to your `Path`. Neither Android Studio nor the command-line tools download does it, and the next steps need `sdkmanager` and `emulator`. Change `$sdk` if your SDK is elsewhere:

   ```powershell
   $sdk = "$env:LOCALAPPDATA\Android\Sdk"
   $tools = "$sdk\cmdline-tools\latest\bin;$sdk\platform-tools;$sdk\emulator"
   $path = [Environment]::GetEnvironmentVariable("Path", "User")
   [Environment]::SetEnvironmentVariable("Path", "$path;$tools", "User")
   ```

   Open a new PowerShell so it sees the change.

7. Install the `emulator` and `platform-tools` packages, and install a JDK 17 or later that `sdkmanager` can run on, for example from [adoptium.net](https://adoptium.net). Point `JAVA_HOME` at the JDK's folder, then open a new PowerShell:

   ```powershell
   [Environment]::SetEnvironmentVariable("JAVA_HOME", "C:\Program Files\Eclipse Adoptium\jdk-17.0.13.11-hotspot", "User")
   sdkmanager --install emulator platform-tools
   ```

   Use the folder name your JDK installed. `sdkmanager` asks you to accept licenses the first time you use it; Simlock's own license setting comes below.

8. Check that the emulator can use the Hypervisor Platform:

   ```powershell
   emulator -accel-check
   ```

   It prints a line like `WHPX(10.0.22631) is installed and usable.` Anything else means step 4 is not done.

</Steps>

## Check the machine

```powershell
simlock doctor
```

When nothing is missing, stderr is empty and the report has no findings:

```json
{"findings":[],"sources":[]}
```

For each missing tool, doctor prints a line on stderr with the command that fixes it. Fix it, run `simlock daemon stop`, and run `simlock doctor` again: Simlock looks for tools only when its daemon starts. See [Install and check your machine](/simlock/docs/getting-started#check-your-machine).

If other users can open the data folder, the daemon log warns at each start and prints an `icacls` command that fixes it. See [The data folder](#the-data-folder).

## Install a system image and lease

Doctor does not check for a system image, and a lease without one fails with `RUNTIME_MISSING`. Accept the Android SDK licenses in Simlock's configuration, restart the daemon so it reads them, and install an image:

```powershell
simlock config set downloads.acceptAndroidLicenses true
simlock daemon stop
simlock component install android 35
```

Then lease an emulator. The first lease on a new data folder also makes the seed emulator, which takes a few minutes. Later leases are quicker, and a warm one takes seconds.

```powershell
$lease = simlock lease --platform android --detach | ConvertFrom-Json
$lease.device.address
```

`device.address` is the emulator's `adb` serial. Run an `adb` command on it:

```powershell
simlock adb -s $lease.device.address shell getprop ro.build.version.release
```

```text
15
```

Release the lease when you finish:

```powershell
simlock release $lease.lease.id
```

If the emulator does not boot, run `emulator -accel-check` again. See [Troubleshooting a worker](/simlock/docs/worker/troubleshooting).

## Write JSON values for Windows PowerShell 5.1

Windows PowerShell 5.1 drops the `"` inside a single-quoted argument it passes to a program, so a JSON value reaches Simlock without its quotes and is refused with `expected an object`. Write each `"` as `\"`:

```powershell
simlock config set gateway '{\"url\":\"wss://gateway.example.com\",\"token\":\"slk_...\",\"label\":\"win-worker\"}'
```

PowerShell 7.3 and later take the form the rest of this site shows, with plain quotes. Setting `gateway.url` and `gateway.token` one at a time is refused in both: set the object in one command.

## Join a worker to a gateway

A Windows PC can join a gateway on any system, and can run a gateway itself. Make the join token on the gateway as [Add a worker to a gateway](/simlock/docs/gateway/joining-workers) describes, then on the Windows worker set the gateway with the escaped form above, and restart the daemon:

```powershell
simlock daemon stop
simlock daemon start
```

## The data folder

Simlock keeps its files in `%USERPROFILE%\.simlock`, or in the folder `SIMLOCK_HOME` names:

```powershell
$env:SIMLOCK_HOME = "D:\simlock"
```

[Run the daemon](/simlock/docs/worker/running-the-daemon#where-files-live) lists the files. There is no `daemon.sock`: on Windows the CLI reaches the daemon over a named pipe whose name comes from the data folder's path. See [Programmatic client](/simlock/docs/using-devices/programmatic-client).

If other users can open the data folder, the daemon log says so at each start, with the `icacls` command that closes it. It looks like this, with your folder and your account's security identifier:

```text
data directory D:\simlock is accessible to other users (BUILTIN\Users); run icacls "D:\simlock" /inheritance:r /grant:r "*S-1-5-21-...:(OI)(CI)F" "*S-1-5-18:(OI)(CI)F" "*S-1-5-32-544:(OI)(CI)F"
```

Read the log with `simlock daemon logs` and run the command it prints. Run Simlock on Windows only on a machine that one user account uses: the folder's permissions do not protect the named pipe. See [Run the daemon](/simlock/docs/worker/running-the-daemon#where-files-live).

## How the daemon lives

The first command that needs the daemon starts it, and it keeps running after the terminal that started it closes. Run `simlock daemon install` to start it at login and again 10 seconds after a crash: see [Start it at login](/simlock/docs/worker/running-the-daemon#start-it-at-login).

Without the service, a daemon started in an SSH session stops when that session ends. With the service installed and the user logged in at the screen, a command over SSH starts the daemon in the desktop session, and it outlives the SSH session. If nobody is logged in at the screen, the command starts the daemon without the service, and it still stops with the SSH session.

A machine runs one worker per user. A second one, started from another `SIMLOCK_HOME`, refuses with `another Simlock worker runs for this user`: stop the first one.
