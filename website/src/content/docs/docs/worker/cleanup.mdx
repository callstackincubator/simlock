Simlock deletes its simulators and emulators on its own, so a worker does not fill its disk with devices nobody uses. You only clean up by hand when you want the space back now, or want to start over.

Cleanup only ever touches simulators and emulators Simlock created. It never touches a leased device, your own simulators and emulators, or a physical phone or tablet.

## When Simlock deletes devices on its own

- **When a lease ends**, its simulator or emulator is deleted. The next lease gets a new one.
- **A booted device nobody leases** (for example, one the warm pool started) is shut down after `idle.shutdownAfterMs`, 10 minutes by default. Devices the [warm pool](/simlock/docs/worker/capacity#keep-devices-booted-the-warm-pool) is keeping ready, and devices a waiting request is about to get, are not shut down.
- **A shut-down device** is deleted `idle.deleteAfterMs` after it was shut down, 60 minutes by default.

To keep devices longer, raise the timers and restart the daemon:

```sh
simlock config set idle.shutdownAfterMs 1800000
simlock config set idle.deleteAfterMs 14400000
simlock daemon stop
simlock daemon start
```

`daemon stop` returns once the old daemon has exited, so `daemon start` can follow at once.

## When the disk runs low

When free space on the disk that holds `~/.simlock` drops below `diskPressure.freeBytesThreshold` (10 GiB by default), Simlock deletes shut-down devices sooner: after 10 minutes (`idle.shutdownAfterMs`) instead of 60.

Each time free space drops below the threshold, Simlock records a `disk.pressure-detected` event. See [Monitoring](/simlock/docs/worker/monitoring) to watch for it.

Low disk never removes runtimes or system images. To free that space, remove the ones you no longer need; see [Runtimes and images](/simlock/docs/worker/runtimes-and-images#remove-a-runtime-or-image).

## Free disk space now

Preview what cleanup would do:

```sh
simlock cleanup --dry-run
```

```json
[{"action":"destroy","reason":"idle 95m > T2=60m","rule":"idle-destroy","target":"dev_3f1c9a52-6b0e-4d7a-9c21-8e4f5b7a2d10"},{"action":"shutdown","reason":"idle 14m > T1=10m","rule":"idle-shutdown","target":"dev_a81e44d0-2c9b-4f6e-b3a7-51d0c8e9f264"}]
```

Each entry names the device (`target`), whether it is shut down (`shutdown`) or deleted (`destroy`), and why. `T1` is the shutdown timer and `T2` the delete timer. `[]` means nothing is due.

Then run it for real:

```sh
simlock cleanup
```

It prints the same list for what it did. To run only the shutdowns or only the deletions, add `--rule idle-shutdown` or `--rule idle-destroy`.

Cleanup still waits for the timers: it does not delete a device that has been shut down for less than the delete time. To delete every device at once, use [nuke](#reset-a-machine-with-nuke).

Run `cleanup` on the worker itself, from the user account that runs the daemon. On a gateway it fails with `UNSUPPORTED_IN_GATEWAY_MODE`.

## Where devices live

Simlock keeps its devices in its own folders:

| Platform | Folder | Config key |
| --- | --- | --- |
| iOS | `~/.simlock/devices/ios` | `drivers.ios.deviceRoot` |
| iOS, with `drivers.ios.deviceSet` set to `default` | Xcode's own device set | none |
| Android | `~/.simlock/devices/android` | `drivers.android.deviceRoot` |

If you set `SIMLOCK_HOME`, the folders move with it.

What this means for your own devices:

- Simlock never touches the emulators in `~/.android/avd`.
- By default, Simlock never touches the simulators in Xcode's own device set.
- With `drivers.ios.deviceSet` set to `default`, Simlock keeps its simulators in Xcode's set, marks each one, and touches only those. Your simulators are left alone. See [Build and run your app](/simlock/docs/using-devices/build-and-run#switch-the-device-set) for when you need this and how to switch.

### Move the device folders

Point the key at an absolute path that does not exist yet, then restart the daemon so Simlock creates it:

```sh
simlock config set drivers.ios.deviceRoot /Volumes/Devices/simlock-ios
simlock daemon stop
simlock daemon start
```

Simlock uses only a folder it created itself, so it can never delete someone else's files. If it refuses the folder, that platform stays off, and `simlock doctor` names the reason:

| Reason | Meaning | Fix |
| --- | --- | --- |
| `not-absolute` | The path is relative. | Use an absolute path. |
| `missing-marker` | The folder exists, but Simlock did not create it. | Remove the empty folder and restart, or pick a path that does not exist. |
| `non-empty-unowned-root` | The folder has files in it, and Simlock did not create it. | Pick another path. |
| `invalid-marker`, `wrong-instance` | The folder belongs to another Simlock installation, or its marker is damaged. | Pick another path. |
| `symlink` | The path is a symbolic link. | Point the key at the real folder. |
| `wrong-owner`, `wrong-permissions` | Another user owns the folder, or other users can read it. | Fix the owner, or run `chmod 700` on it. |

Other reasons iOS can stay off, also shown by `simlock doctor`:

- `invalid-device-set`: `drivers.ios.deviceSet` is not `simlock` or `default`; or it is `default` and `drivers.ios.deviceRoot` is set too; or `ios.simulator.headless` is `false` without `drivers.ios.deviceSet` set to `default`.
- `device-set-changed`: you switched device sets while simulators were left in the old one. The message lists them and the steps to take.

Restart the daemon after a fix.

Devices in Simlock's folders that Simlock has no record of, usually left by a daemon that stopped while creating one, are **orphans**. `simlock doctor` reports them, and `simlock doctor --purge-orphans` deletes them. See [Troubleshooting](/simlock/docs/worker/troubleshooting#orphaned-devices).

## Reset a machine with nuke

Use `simlock nuke` when leases or devices are stuck and you want to start over on this machine.

<Aside type="danger" title="Nuke ends every lease on this machine">
Every agent holding a device here loses it at once, and every waiting request is cancelled. With `--delete-devices`, every simulator and emulator Simlock created is deleted, with its apps and data. There is no undo.
</Aside>

```sh
simlock nuke
```

```text
Nuke Simlock-managed devices? [y/N] y
{"deletedDevices":[],"releasedLeaseIds":["lse_7d2c41e8-93a5-4b1f-8e60-2fa9c3d5b174"]}
```

`simlock nuke`:

- ends every lease, including leases on physical devices, whose apps are uninstalled as after any lease,
- cancels every waiting request,
- shuts down every simulator and emulator Simlock created,
- makes the warm pool forget what it learned, so it does not boot those devices again by itself. Your `warmPool.targets` stay.

To also delete every simulator and emulator Simlock created, and every baseline:

```sh
simlock nuke --delete-devices
```

Nuke never touches devices Simlock did not create, and never deletes or unenrols a physical device.

In a script, pass `--yes`; without a terminal and without `--yes`, the command stops with `nuke requires confirmation or --yes`.

Nuke resets one machine. On a gateway it fails with `UNSUPPORTED_IN_GATEWAY_MODE`: run it on each worker you want to reset.
