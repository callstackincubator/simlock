**Result:** the iOS runtimes and Android system images your agents use are installed, so a lease does not wait for a download or fail with `RUNTIME_MISSING`.

Every iOS simulator needs an iOS runtime on the machine, and every Android emulator needs a system image. Simlock calls both **components**. Each takes several gigabytes.

## Before you start

- Installing and removing need the admin role, such as your own terminal on the worker. An agent session gets `FORBIDDEN`. Anyone can list.
- Free disk: about 8 GiB for an iOS runtime, 2 GiB for an Android image.
- iOS 16.0 is the oldest runtime Simlock can install. Install older ones from Xcode.
- On a gateway, install on its workers instead: see [Maintain workers](/simlock/docs/gateway/maintain-workers).

## See what agents can lease

```sh
simlock catalog --platform ios
```

```text
Platform: ios
  Runtimes: 18.4, 26.0 (default: 26.0)
  Models:
    phone (default: iPhone 16):
      iPhone 16: 18.4, 26.0
      iPhone 17 Pro: 26.0
    tablet (default: iPad Pro 11-inch (M4)):
      iPad Pro 11-inch (M4): 18.4, 26.0
```

- The default runtime is the newest one installed.
- Models are grouped by class. Each class shows the model a lease for that class gets.
- A model works only with the runtimes on its own line. `(no paired runtime)` means no installed runtime works with it.
- For Android, the output also lists each installed system image with its API level, tag and CPU type. A listed tag is what `simlock lease --image-tag` accepts. Models you made in Android Studio are marked `(custom)`.
- When the worker sets `android.defaultImageTag`, a `Default image tag: <tag>` line follows the `Runtimes` line. Through a gateway it shows only when every Android worker reports the same tag. `--json` carries it as `defaultImageTag` under the same rule.
- A platform whose tools are missing is not listed. Run `simlock doctor` to see why.

`catalog` shows only what is installed and never downloads. Add `--json` for the structured form.

## Install a runtime or image

<Steps>

1. Install by iOS version or Android API level:

   ```sh
   simlock component install ios 26.0
   simlock component install android 35
   ```

   On Android, Simlock installs the `google_apis` image for the machine's CPU. Progress prints on stderr, the result on stdout:

   ```text
   {"stage":"waiting"}
   {"stage":"downloading","fraction":0.41}
   {"stage":"downloading","fraction":1}
   {"platform":"android","component":"35","outcome":"installed","version":"35"}
   ```

</Steps>

**Check:** `outcome` is `installed`, or `already-installed` if it was there already, so running the command twice is safe. `simlock catalog` lists the new runtime, and agents can lease it at once.

- **Time.** An install gets `downloads.timeoutMs` (20 minutes by default), including time spent waiting its turn.
- **One download per platform at a time.** A second install prints `{"stage":"waiting"}` and waits. A lease or install that needs a component already downloading waits for that download.
- **Stopping the daemon cancels an install.** Run the command again afterwards.
- **Another Android image tag**, such as `google_apis_playstore`, installs with `sdkmanager`. An Android lease with `--image-tag` uses only an image of that tag that is already installed.

## Decide when Simlock may download

Simlock downloads a component only when someone allows it: you, with `simlock component install`, or an agent, with `simlock lease --allow-download`. `downloads.policy` decides which may start a download:

| `downloads.policy` | Lease without `--allow-download` | Lease with `--allow-download` | `simlock component install` |
| --- | --- | --- | --- |
| `never` | refused | refused | refused with `DOWNLOADS_DISABLED` |
| `on-request` (default) | refused | allowed | allowed |
| `always` | allowed | allowed | allowed |

For example, on a machine where only you install components:

```sh
simlock config set downloads.policy never
simlock daemon stop
simlock daemon start
```

**Check:** `simlock config get downloads.policy` prints `"never"`.

A lease that needs a component it may not download fails with `RUNTIME_MISSING`, and the message says what is missing:

```text
iOS 26.0 is not installed; pass --allow-download (or set downloads.policy) to download it
```

The warm pool never downloads anything.

## Accept the Android SDK licences

An Android system image installs only after its SDK licence is accepted. Allowing downloads does not accept it. Do one of these:

- Accept the licences yourself once, then install again:

  ```sh
  sdkmanager --licenses
  ```

- Let Simlock accept them for you:

  <Aside type="caution">
  `downloads.acceptAndroidLicenses: true` accepts every Android SDK licence on your behalf. Read them first with `sdkmanager --licenses` if you need to.
  </Aside>

  ```sh
  simlock config set downloads.acceptAndroidLicenses true
  simlock daemon stop
  simlock daemon start
  ```

**Check:** `simlock component install android 35` ends with `"outcome":"installed"`.

## List installed components

```sh
simlock component list --platform android
```

```json
{"components":[{"platform":"android","version":"35","variant":"google_apis/arm64-v8a","sizeBytes":4201234567,"installedBySimlock":true,"installedAt":1790864071200,"devices":2,"foreignDevices":0}]}
```

It lists every runtime and image on the machine, whoever installed it.

| Field | Meaning |
| --- | --- |
| `version` | The version, as `simlock catalog` shows it. |
| `variant` | Tells two components of one version apart: an iOS runtime's build, or an Android image's tag and CPU type. |
| `sizeBytes` | The disk space it takes. Missing when it cannot be read. |
| `installedBySimlock` | `true` if Simlock installed it and it has not changed. Only these can be removed with Simlock. |
| `devices` | Simlock's devices that use it. |
| `foreignDevices` | Your own simulators or emulators, made outside Simlock, that use it. |

## Remove a runtime or image

Simlock never removes a component on its own, even when the disk runs low.

<Aside type="caution">
Removing a component deletes it from the machine. Run with `--dry-run` first.
</Aside>

<Steps>

1. Check what would be removed. A dry run answers `would-remove` when the removal would go ahead:

   ```sh
   simlock component remove ios 26.0 --dry-run
   ```

2. Remove it. The command asks you to confirm; in a script, pass `--yes`.

   ```sh
   simlock component remove ios 26.0
   ```

   ```text
   {"platform":"ios","version":"26.0","outcome":"removed","sizeBytes":9103456789}
   ```

</Steps>

**Check:** `simlock component list --platform ios` no longer lists `26.0`.

On iOS, the result's `residue` field names what can stay behind:

- Your own simulators of that runtime that were never booted become unavailable. Clear them with `xcrun simctl delete unavailable`.
- macOS keeps its own copy of the runtime download, often more than 8 GiB. To get that space back, remove the platform in Xcode's **Settings > Platforms**.

## When it fails

| Error | Exit | Cause | Fix |
| --- | --- | --- | --- |
| `INSUFFICIENT_DISK_SPACE` | 12 | Less free disk than the install needs. Nothing was downloaded. The message says how much is needed and free. | [Free disk space](/simlock/docs/worker/free-disk), then install again. |
| `DOWNLOAD_TIMEOUT` | 10 | The install took longer than `downloads.timeoutMs`, waiting included. | Run it again; the download may be further along. Or raise `downloads.timeoutMs`. |
| `DOWNLOADS_DISABLED` | 12 | `downloads.policy` is `never`. | Set it to `on-request`, or install from Xcode or `sdkmanager`. |
| `LICENSE_NOT_ACCEPTED` | 12 | The Android SDK licence is not accepted. | [Accept the licences](#accept-the-android-sdk-licences). |
| `COMPONENT_NOT_OWNED` | 12 | `remove`: Simlock did not install it, or it changed since. | Remove it with Xcode or `sdkmanager`. |
| `COMPONENT_IN_USE` | 12 | `remove`: a device uses it, Simlock's or yours. The message counts each. | Delete those devices first. |
| `COMPONENT_BUSY` | 11 | `remove`: another install or removal runs on that platform. | Try again when it has finished. |
| `FORBIDDEN` | 1 | The session lacks the admin role. | Run it on the worker as the user that runs the daemon. |

The licence error reads:

```text
sdkmanager refused to install system-images;android-35;google_apis;arm64-v8a: an Android SDK license is not accepted. Set "downloads.acceptAndroidLicenses": true in config to accept automatically, or run `sdkmanager --licenses` manually.
```
