Every iOS simulator needs an iOS runtime on the machine, and every Android emulator needs a system image. Simlock calls both **components**. They are several gigabytes each, so install the ones your agents use ahead of time: otherwise the first lease that needs one waits for the download, or fails.

The [AgentDeviceCloud backend](/simlock/docs/worker/agent-device-cloud) gets its Android runtime
from the service. It does not install or remove local Android system images.

Installing and removing components needs an admin session, such as your own terminal on the worker. An agent session gets `FORBIDDEN`. Anyone can list them.

## See what agents can lease

`simlock catalog` lists the installed runtimes, the device models, and which runtimes each model works with:

```sh
simlock catalog --platform ios
```

```text
Platform: ios
  Runtimes: 18.4, 26.0 (default: 26.0)
  Models:
    phone (default: iPhone 16):
      iPhone 16: 18.4, 26.0
      iPhone 17 Pro: 26.0
    tablet (default: iPad Pro 11-inch (M4)):
      iPad Pro 11-inch (M4): 18.4, 26.0
```

- The default runtime is the newest one installed.
- Models are grouped by class. Each class shows the model a lease for that class gets.
- A model works only with the runtimes on its own line. `(no paired runtime)` means no installed runtime works with it.
- For Android, the output also lists each installed system image with its API level, tag and CPU type. A listed tag is what `simlock lease --image-tag` accepts. Models you made in Android Studio are marked `(custom)`.
- A platform whose tools are missing is not listed. Run `simlock doctor` to see why.

`simlock catalog` shows only what is installed and never downloads anything. Add `--json` for the structured form.

## Install a runtime or image

```sh
simlock component install ios 26.0
simlock component install android 35
```

Give an iOS version, or an Android API level. On Android, Simlock installs the `google_apis` image for the machine's CPU.

Progress prints on stderr and the result on stdout:

```text
{"stage":"waiting"}
{"stage":"downloading","fraction":0.41}
{"stage":"downloading","fraction":1}
{"platform":"android","component":"35","outcome":"installed","version":"35"}
```

`outcome` is `installed`, or `already-installed` if it was there already, so running the command twice is safe. Agents can lease the new runtime at once.

Before you start:

- **Free disk.** You need about 8 GiB free for an iOS runtime and 2 GiB for an Android image. With less, the install fails with `INSUFFICIENT_DISK_SPACE` and downloads nothing.
- **Time.** An install gets `downloads.timeoutMs` (20 minutes by default), including time spent waiting its turn. Running out fails with `DOWNLOAD_TIMEOUT`.
- **One download per platform at a time.** A second install prints `{"stage":"waiting"}` and waits. A lease or install that needs a component already downloading waits for that download.
- **iOS 16.0 is the oldest runtime Simlock can install.** Install older ones from Xcode.
- **Stopping the daemon cancels an install.** Run the command again afterwards.

To install on workers behind a gateway, see [Manage workers](/simlock/docs/gateway/managing-workers).

## Decide when Simlock may download

Simlock downloads a component only when someone allows it: you, with `simlock component install`, or an agent, with `simlock lease --allow-download`. `downloads.policy` decides which of these may start a download:

| `downloads.policy` | Lease without `--allow-download` | Lease with `--allow-download` | `simlock component install` |
| --- | --- | --- | --- |
| `never` | refused | refused | refused with `DOWNLOADS_DISABLED` |
| `on-request` (default) | refused | allowed | allowed |
| `always` | allowed | allowed | allowed |

For example, on a machine where only you install components:

```sh
simlock config set downloads.policy never
```

Restart the daemon to apply it.

When a lease needs a component that is not installed and may not download it, it fails with `RUNTIME_MISSING`, and the message says what is missing:

```text
iOS 26.0 is not installed; pass --allow-download (or set downloads.policy) to download it
```

The warm pool never downloads anything. An Android lease with `--image-tag` uses only an image of that tag that is already installed; install it with `sdkmanager`.

## Accept the Android SDK licences

An Android system image installs only after its SDK licence is accepted. Allowing downloads does not accept it. Until it is accepted, installs fail with `LICENSE_NOT_ACCEPTED`:

```text
sdkmanager refused to install system-images;android-35;google_apis;arm64-v8a: an Android SDK license is not accepted. Set "downloads.acceptAndroidLicenses": true in config to accept automatically, or run `sdkmanager --licenses` manually.
```

Fix it one of two ways:

- Accept the licences yourself once, then install again:

  ```sh
  sdkmanager --licenses
  ```

- Let Simlock accept them for you:

  ```sh
  simlock config set downloads.acceptAndroidLicenses true
  simlock daemon stop
  simlock daemon start
  ```

<Aside type="caution">
`downloads.acceptAndroidLicenses: true` accepts every Android SDK licence on your behalf. Read them first with `sdkmanager --licenses` if you need to.
</Aside>

## List installed components

```sh
simlock component list --platform android
```

```json
{"components":[{"platform":"android","version":"35","variant":"google_apis/arm64-v8a","sizeBytes":4201234567,"installedBySimlock":true,"installedAt":1790864071200,"devices":2,"foreignDevices":0}]}
```

This lists every runtime and image on the machine, whoever installed it.

| Field | Meaning |
| --- | --- |
| `version` | The version, as `simlock catalog` shows it. |
| `variant` | Tells two components of the same version apart: an iOS runtime's build, or an Android image's tag and CPU type. |
| `sizeBytes` | The disk space it takes. Missing when it cannot be read. |
| `installedBySimlock` | `true` if Simlock installed it and it has not changed. Only these can be removed with Simlock. |
| `devices` | Simlock's devices that use it. |
| `foreignDevices` | Your own simulators or emulators, made outside Simlock, that use it. |

## Remove a runtime or image

<Aside type="caution">
Removing a component deletes it from the machine. Run with `--dry-run` first to check what would be removed.
</Aside>

```sh
simlock component remove ios 26.0 --dry-run
simlock component remove ios 26.0
```

The command asks you to confirm; in a script, pass `--yes`. The result looks like this:

```text
{"platform":"ios","version":"26.0","outcome":"removed","sizeBytes":9103456789}
```

A dry run answers `would-remove` when the removal would go ahead. Simlock refuses to remove a component when:

| Error | Why | What to do |
| --- | --- | --- |
| `COMPONENT_NOT_OWNED` | Simlock did not install it, or it changed since. | Remove it with Xcode or `sdkmanager`. |
| `COMPONENT_IN_USE` | A device uses it, Simlock's or yours. The message counts each. | Delete those devices first. |
| `COMPONENT_BUSY` | Another install or removal runs on that platform. | Try again when it has finished. |

Simlock never removes a component on its own, even when the disk runs low.

On iOS, two things can stay behind after a removal. The result's `residue` field names them:

- Your own simulators of that runtime that were never booted become unavailable. Clear them with `xcrun simctl delete unavailable`.
- macOS keeps its own copy of the runtime download, often more than 8 GiB. To get that space back, remove the platform in Xcode's **Settings > Platforms**.
