A worker runs fine with no config file. To change a setting, run `simlock config set`, then restart the daemon. This page covers the settings most people change; the [configuration reference](/simlock/docs/reference/configuration) lists every key.

## Change a setting

<Steps>

1. Set the key:

   ```sh
   simlock config set idle.shutdownAfterMs 1800000
   ```

   ```text
   Updated idle.shutdownAfterMs in /Users/dana/.simlock/config.json; takes effect on daemon restart.
   ```

2. Restart the daemon:

   ```sh
   simlock daemon stop
   simlock daemon start
   ```

   `daemon stop` returns once the old daemon has exited, so `daemon start` can follow at once.

</Steps>

Times are in milliseconds and sizes in bytes. Keys are written with dots: `idle.shutdownAfterMs` is the `shutdownAfterMs` key inside `idle`.

Values are read as JSON when they can be, so `true`, `4`, `["iPhone 16"]` and `{"phone":"iPhone 16"}` become a boolean, a number, a list and an object. Anything else is stored as text. Put quotes around JSON values so your shell passes them as they are.

### When a value is refused

`config set` checks the whole file before it saves anything. A wrong value, or an unknown key, is refused with exit code 2, and the file stays as it was:

```json
{"error":{"code":"USAGE","message":"Invalid config after setting idle.shutdownAfter: Unknown config key: \"idle.shutdownAfter\""}}
```

## Edit the file by hand

The file is `~/.simlock/config.json` (or `config.json` in `SIMLOCK_HOME`). It is plain JSON:

```json title="~/.simlock/config.json"
{
  "http": { "enabled": true },
  "idle": { "shutdownAfterMs": 1800000 }
}
```

The daemon checks the file when it starts:

- **A wrong value** stops the daemon from starting. The command that tried to start it prints an error that names the key, such as `Invalid config value for "http.port": expected ...`.
- **An unknown key** is ignored, with a warning in the daemon log. Check `simlock daemon logs` after you edit the file.
- **Invalid JSON** fails with `Invalid JSON in config file`.
- **A `mode` key** is refused. It is not a setting: a daemon started with `--gateway` is a gateway, and any other daemon is a worker.

`simlock config set` saves the file readable by your user only, because it can hold secrets such as a gateway join token. A file you create yourself keeps the permissions you give it.

## See the settings the daemon uses

```sh
simlock config                        # every setting, as one JSON line
simlock config get idle               # one group
simlock config get lease.maxTtlMs     # one value
```

```text
14400000
```

These commands show what the running daemon uses: your values plus the defaults. A value you set but have not restarted for still shows the old value. To see what you wrote, open `~/.simlock/config.json`.

<Aside type="caution">
The output includes secrets from the file, such as `gateway.token`. Do not paste it anywhere public.
</Aside>

## Settings most machines change

| You want to | Key | Default |
| --- | --- | --- |
| Turn off the HTTP API and the console | `http.enabled` | `true` on a standalone worker |
| Change the address and port for HTTP | `http.host`, `http.port` | `127.0.0.1`, `4701` |
| Keep idle devices booted longer | `idle.shutdownAfterMs` | `600000` (10 min) |
| Keep shut-down devices on disk longer | `idle.deleteAfterMs` | `3600000` (60 min) |
| Let Simlock download runtimes and images | `downloads.policy` | `on-request` |
| Accept the Android SDK licences | `downloads.acceptAndroidLicenses` | `false` |
| Let one agent hold more than one device | `lease.maxPerRequester` | `1` |
| Change how long a lease lasts when the agent names no time | `lease.defaultTtlMs` | `900000` (15 min) |
| Change the longest lease anyone can ask for | `lease.maxTtlMs` | `14400000` (4 h) |
| Run more or fewer devices | `capacity.strategy`, `capacity.config` | `resource`, sized from this machine |
| Keep some devices booted and ready | `warmPool.targets` | none |
| Make iOS devices slim by default | `ios.defaultMode` | `full` |
| Choose which model a class such as `phone` gets | `ios.defaultModels`, `android.defaultModels` | none |
| Run Android emulators without a window | `android.emulator.headless` | `false` |
| Watch iOS simulators in a window | `ios.simulator.headless`, with `drivers.ios.deviceSet` | `true` (no window) |
| Give a busy Mac longer to copy, boot, shut down or delete an iOS simulator | `ios.simulator.lifecycleTimeoutMs` | `30000` (30 s) |
| Write more or less to the log | `log.level` | `info` |

Every change below needs a daemon restart.

### Turn off HTTP

A standalone worker serves the HTTP API and the [web console](/simlock/docs/worker/console) on `127.0.0.1:4701`. Both ask for a token. To turn them off:

```sh
simlock config set http.enabled false
```

A worker that has joined a gateway always has HTTP off and refuses `true`: use the gateway instead.

<Aside type="caution">
By default HTTP listens on `127.0.0.1`, so only this machine can reach it. Setting `http.host` to `0.0.0.0` lets any machine that can reach the port try to connect. Simlock does not do HTTPS: put a reverse proxy in front of it for that. See [Remote agents](/simlock/docs/using-devices/remote-agents).
</Aside>

### Let one agent hold several devices

By default each agent holds one lease at a time, and a second request fails with `REQUESTER_ALREADY_LEASED`. To allow two leases of any platform:

```sh
simlock config set lease.maxPerRequester 2
```

To allow one iOS and one Android lease, but never two of the same platform, set a limit per platform. A platform you leave out keeps a limit of `1`:

```sh
simlock config set lease.maxPerRequester '{"ios":1,"android":1}'
```

With a per-platform limit, an agent can also wait for an iOS and an Android device at the same time.

### Choose default models

When an agent asks for a class such as `phone` instead of a model, Simlock tries your list first, in order:

```sh
simlock config set ios.defaultModels '{"phone":["iPhone 16","iPhone 15"],"tablet":"iPad Air 11-inch (M2)"}'
```

Each key must be a device class: `phone`, `tablet`, `watch`, `tv`, `vision`, `auto` or `desktop`. `simlock catalog` shows which models belong to each class. See [Choose a device](/simlock/docs/using-devices/choosing-a-device).

### Run Android emulators without a window

```sh
simlock config set android.emulator.headless true
```

This suits a machine nobody watches. It applies the next time each emulator boots.

### Watch iOS simulators in a window

```sh
simlock config set drivers.ios.deviceSet default
simlock config set ios.simulator.headless false
```

After a restart, every simulator Simlock gets ready shows on the Mac: in DeviceHub when it is installed, otherwise in a Simulator.app window. The window opens in the background, so the app you are typing in keeps focus. If a window cannot open, the lease still works and the daemon log says `Could not open a window for iOS simulator`.

You need both settings. With `ios.simulator.headless: false` but Simlock's own device set, iOS turns off and `simlock doctor` shows `invalid-device-set`.

What to expect:

- DeviceHub's main window shows the newest simulator; the others are in its list. If you close the main window, DeviceHub stops showing new simulators until you restart it.
- If Simlock opened DeviceHub or Simulator.app, closing a window or quitting the app leaves the simulators running.
- If you opened DeviceHub or Simulator.app yourself, quitting DeviceHub or closing a Simulator.app window shuts the simulator down. Simlock boots it again within about a minute, and whatever was running on it is lost.

## Go back to a default

There is no command that removes a key. Set the default value with `simlock config set`, or delete the key from `~/.simlock/config.json`. Then restart the daemon.

`config get` with a key that does not exist fails with `Unknown config key: <key>`.
