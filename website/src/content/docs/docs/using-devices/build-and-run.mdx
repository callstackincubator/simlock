Once you hold a lease, you build your app for the leased device, install it and run it. On iOS, how you point the build at the simulator depends on the worker's `drivers.ios.deviceSet` setting, which an admin chooses. You can tell which one you are on from the grant's `environment`:

- `SIMLOCK_IOS_DEVICE_SET` is present: the setting is `simlock` (the default).
- `SIMLOCK_IOS_DEVICE_SET` is absent: the setting is `default`.

## iOS with the `simlock` setting (the default)

Simlock keeps its simulators where Xcode doesn't look, so `xcodebuild` can't find the simulator by its UDID alone.

On Xcode 27 or later, tell `xcodebuild` where Simlock's simulators are:

```sh
xcodebuild build \
  -destination "platform=iOS Simulator,id=$UDID" \
  -DVTSimulatorSetLocation="$SIMLOCK_IOS_DEVICE_SET"
```

On an older Xcode, or with a tool that doesn't let you add `xcodebuild` arguments, build for any simulator and install the result through Simlock:

```sh
xcodebuild build -destination 'generic/platform=iOS Simulator'
simlock simctl install "$UDID" ./build/Debug-iphonesimulator/MyApp.app
```

`agent-device install` does the same install through [agent-device](/simlock/docs/using-devices/agent-device).

## iOS with the `default` setting

Simlock's simulators live alongside your own in Xcode, so the usual tools find a leased simulator by its UDID:

```sh
xcodebuild build -destination "platform=iOS Simulator,id=$UDID"
```

The React Native CLI, Detox and agent-device's test runner work the same way. Name your UDID every time: Xcode also lists your own simulators and other agents' simulators.

<Aside type="caution">
With the `default` setting, `xcrun simctl shutdown all` stops every leased simulator. Simlock starts each one again under its lease, but its holder loses the apps it had running. A simulator erased while stopped ends its lease. Name your own UDID in every command.
</Aside>

## Android

Take `ANDROID_ADB_SERVER_PORT` from the grant's `environment`, and name the emulator with `-s`:

```sh
export ANDROID_ADB_SERVER_PORT=5038
adb -s emulator-5556 install ./app/build/outputs/apk/debug/app-debug.apk
```

Setting `ANDROID_SERIAL` works in place of `-s`.

## Switch the device set

This is for an admin, on the worker.

1. Set the key and restart the daemon:

   ```sh
   simlock config set drivers.ios.deviceSet default
   simlock daemon stop
   simlock daemon start
   ```

2. If iOS doesn't come back, run `simlock doctor` and look for one of these reasons:

   - **`device-set-changed`**: simulators from the old setting are still there. Set the key back, run `simlock nuke --delete-devices` and `simlock doctor --purge-orphans`, then switch again. The message names any simulator that remains, with the `xcrun simctl delete` command for it.
   - **`invalid-device-set`**: the value isn't exactly `simlock` or `default`, or it clashes with another setting: `drivers.ios.deviceRoot` set together with `default`, or `ios.simulator.headless` set to `false` with `simlock`. Remove one of them, or set `drivers.ios.deviceSet` to `default`.

If you set `drivers.ios.deviceRoot`, keep it set while you run the two cleanup commands, and remove it only when you switch to `default`. The leftover check only looks in the default folder, `~/.simlock/devices/ios`, so simulators in a custom folder are cleaned up by those commands, not reported by the check.

See the keys in [Configuration](/simlock/docs/reference/configuration) and the folders in [Cleanup](/simlock/docs/worker/cleanup#where-devices-live).
