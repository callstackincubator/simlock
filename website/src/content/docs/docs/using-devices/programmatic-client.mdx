A Node.js program on the machine that runs the Simlock daemon can lease devices directly, without running `simlock` commands. The `simlock` package has two entry points:

| Import | For | Can |
| --- | --- | --- |
| `simlock/client` | Agents and tools that need devices | Lease, renew and release devices, run commands on a leased device, read the catalog and status |
| `simlock/admin` | Operator tools | All of the above, plus every lease and device, tokens, cleanup, events, updating the daemon and stopping it |

Both only work on the same machine as the daemon. A program on another machine uses the [HTTP API](/simlock/docs/using-devices/remote-agents) instead.

## Before you start

- Node.js 22.13 or later.
- The daemon is running on this machine. The client never starts it. Start it with `simlock daemon start`, or run any `simlock` command, which starts it if needed.
- The package is installed in your project:

  ```sh
  npm i simlock
  ```

## Connect

```ts
import { homedir } from "node:os";
import { join } from "node:path";
import { connectSimlock } from "simlock/client";

const client = await connectSimlock({
  endpoint: join(homedir(), ".simlock", "daemon.sock"),
  principal: "build-bot-1",
});
```

**`endpoint`** is where the daemon listens:

- `~/.simlock/daemon.sock` by default, or `$SIMLOCK_HOME/daemon.sock` if you set `SIMLOCK_HOME`.
- A gateway's is `~/.simlock/gateway/daemon.sock`.
- On Windows it is a named pipe: `\\.\pipe\simlock-` followed by the first 16 hex characters of the SHA-256 of the data folder's full path in lower case (for `~/.simlock`, of `c:\users\<you>\.simlock`).

**`principal`** is your requester id. The leases you take belong to it, and by default it can hold one lease at a time (see `lease.maxPerRequester`). It can be at most 256 characters, with no control characters; otherwise a lease request fails with `BAD_REQUEST`.

<Aside type="caution">
Give every agent or worker process its own `principal`. Every client that leaves it out shares the daemon's default id, and so shares one lease.
</Aside>

One client is one connection, and it doesn't reconnect. If the daemon stops, every call in progress fails with `DAEMON_CONNECTION_LOST`, and you connect again. A lost connection doesn't release your lease.

## A complete example

This program leases an iPhone simulator, keeps the lease alive, installs and launches an app, and releases the device:

```ts title="lease-and-launch.mts"
import { homedir } from "node:os";
import { join, resolve } from "node:path";
import { connectSimlock, isSimlockError } from "simlock/client";

const client = await connectSimlock({
  endpoint: join(homedir(), ".simlock", "daemon.sock"),
  principal: "build-bot-1",
});

try {
  const grant = await client.requestLease(
    { platform: "ios", model: "iPhone 16", ttlMs: 10 * 60_000, timeoutMs: 5 * 60_000 },
    { onProgress: (progress) => console.error("waiting:", progress.stage) },
  );
  const { lease, device } = grant;
  console.error(`leased ${device.spec.model} ${device.driverDeviceId} as ${lease.id}`);

  // The client never renews for you. Renew every third of the TTL.
  const renewal = setInterval(() => {
    client.renewLease({ leaseId: lease.id }).catch((error) => console.error("renew failed:", error));
  }, lease.ttlMs / 3);
  client.onLeaseLost((push) => {
    if (push.leaseId === lease.id) console.error(`lease lost: ${push.reason}`);
  });

  try {
    const run = async (args: string[]) => {
      const { exitCode } = await client.exec(
        { leaseId: lease.id, tool: "simctl", args },
        { onOutput: ({ stream, chunk }) => (stream === "stdout" ? process.stdout : process.stderr).write(chunk) },
      );
      if (exitCode !== 0) throw new Error(`simctl ${args[0]} exited with ${exitCode}`);
    };
    await run(["install", device.driverDeviceId, resolve("build/Debug-iphonesimulator/MyApp.app")]);
    await run(["launch", device.driverDeviceId, "com.example.myapp"]);
  } finally {
    clearInterval(renewal);
    await client.releaseLease({ leaseId: lease.id });
  }
} catch (error) {
  if (!isSimlockError(error)) throw error;
  console.error(`${error.code}: ${error.message}`);
  process.exitCode = 1;
} finally {
  await client.close();
}
```

Run it with a TypeScript runner, for example `npx tsx lease-and-launch.mts`.

## What the client can do

| Call | Does |
| --- | --- |
| `requestLease(request, { onProgress, signal })` | Waits for a device and resolves with the grant: `device`, `environment`, `lease` and `timing`, the same fields `simlock lease` prints. |
| `renewLease({ leaseId, ttlMs? })` | Moves the deadline to now plus the TTL. Resolves with the lease, including the new `ttlDeadline`. |
| `releaseLease({ leaseId })` | Ends the lease. A simulator or emulator is then deleted; a physical device is cleaned. |
| `exec({ leaseId, tool, args, stdin?, stdinFile? }, { onOutput })` | Runs `simctl` or `adb` (or `devicectl` on a physical iPhone or iPad) on the device, and resolves with `{ exitCode }`. `stdin` holds at most 8,388,608 characters. `stdinFile` names a file of the lease's folder to send on stdin instead; give one of the two. |
| `rotate(leaseId, orientation)` | Turns an iPhone or iPad simulator. See [Rotate without a socket](/simlock/docs/using-devices/watching-the-screen#rotate-without-a-socket). |
| `listLeases()` | Your leases. |
| `getCatalog({ platform? })` | What you can ask for, as `simlock catalog --json` prints it. |
| `onLeaseLost`, `onDeviceUnhealthy`, `onDeviceRecovered` | Tell you what happens to a lease this client took. Each returns a function that stops listening. |
| `close()` | Closes the connection. It doesn't release your leases. |

`requestLease` takes the same choices as `simlock lease`, under these names: `platform`, `model` or `class`, `osVersion` (an exact version or a range), `mode`, `imageTag`, `baseline`, `physical`, `ttlMs`, `timeoutMs`, `noWait`, `allowDownload`, `leaseId` and `metadata`, an object of text values for a gateway's admission command (see [Ranking or refusing requests](/simlock/docs/gateway/routing#ranking-or-refusing-requests-with-an-admission-command)). See [Choosing a device](/simlock/docs/using-devices/choosing-a-device).

For `exec`:

- Leave the device out of the command; Simlock adds the lease's device. A command that names a different device is refused with `PASSTHROUGH_REFUSED` before it runs.
- Use absolute paths. The command runs in the daemon's process, not in your program's working folder.

## Stop waiting

Pass an `AbortSignal` to stop waiting for a device:

```ts
const controller = new AbortController();
setTimeout(() => controller.abort(), 60_000);
const grant = await client.requestLease({ platform: "android", class: "tablet" }, { signal: controller.signal });
```

- Aborting takes the request out of the queue and rejects with `CANCELLED`.
- If Simlock was already creating or starting the device, it finishes, and the client releases the device as soon as it is granted.
- An abort after the grant does nothing. Release the lease yourself.

## Handle errors

Every failure the daemon reports is a `SimlockError` with a `code` and a `message`. Check for it with `isSimlockError`:

```ts
try {
  await client.requestLease({ platform: "ios", model: "iPhone 16", noWait: true });
} catch (error) {
  if (!isSimlockError(error)) throw error;
  if (error.code === "NO_CAPACITY") console.error("No device is free right now; try again later.");
  else if (error.code === "REQUESTER_ALREADY_LEASED") console.error(error.message);
  else throw error;
}
```

The message of `REQUESTER_ALREADY_LEASED` names the lease you already hold. The codes are the same ones the CLI prints; see [Errors](/simlock/docs/using-devices/errors).

## The admin client

`simlock/admin` gives an operator tool control of the whole daemon: every lease and device, releasing any lease, tokens, configuration, events, cleanup and stopping the daemon. It has every method of the agent client too.

```ts
import { readFile } from "node:fs/promises";
import { homedir } from "node:os";
import { join } from "node:path";
import { connectSimlockAdmin } from "simlock/admin";

const home = join(homedir(), ".simlock");
const admin = await connectSimlockAdmin({
  endpoint: join(home, "daemon.sock"),
  credential: (await readFile(join(home, "admin.token"), "utf8")).trim(),
  principal: "ops-dashboard",
});

const leases = await admin.list({ kind: "leases" });
console.log(leases);
await admin.close();
```

The `credential` is one of:

- **The contents of `~/.simlock/admin.token`.** The daemon writes this file, readable only by its own user, with a new secret each time it starts, and deletes it when it stops. Read it again after a restart.
- **The secret of an operator token**, from `simlock token create --role operator`.

A missing or wrong credential fails the connection with `ADMIN_AUTHENTICATION_FAILED`.

<Aside type="caution">
The admin credential lets a program release every agent's lease and stop the daemon. Keep it away from agents; give them `simlock/client` instead.
</Aside>

### Warm pool and baselines

Each of these does what the matching `simlock` command does:

| Call | Command | Answers |
| --- | --- | --- |
| `forgetWarmKind({ platform, model, osVersion?, mode?, imageTag? })` | `simlock warm forget` | `{ forgotten: [{ platform, model, osVersion, mode, imageTag?, baseline? }] }`: every kind of that model the warm pool learned, narrowed by the fields you give. A gateway refuses it with `UNSUPPORTED_IN_GATEWAY_MODE`. |
| `saveBaseline({ leaseId, name, note? })` | `simlock baseline save` | `{ baseline, leaseId }`. Ends the lease and keeps a copy of its device under the name. `baseline` is `{ name, version, platform, model, osVersion, mode, imageTag?, note?, sizeBytes?, savedAt, staleReason? }`. |
| `listBaselines()` | `simlock baseline list` | `{ baselines }`: the newest version of each name. On a gateway it covers every worker, each entry with its `workerId`. |
| `removeBaseline({ name, workerId? })` | `simlock baseline remove` | `{ name, versions, deletedDevices }`. On a gateway, `workerId` is required and names the worker to remove it from. |

The baseline calls can throw `UNKNOWN_LEASE`, `BASELINE_SAVE_FAILED`, `UNKNOWN_BASELINE` and `BASELINE_IN_USE`; `removeBaseline` can also throw `DEVICE_BUSY`; see [Baselines](/simlock/docs/worker/baselines).

### Update the daemon

`admin.updateDaemon({ version?, force?, query? })` does what `simlock update` does. It finds the version on npm, starts the update and answers at once. The daemon then takes no new leases, waits for its leases to end (unless `force`), installs and restarts.

```ts
const answer = await admin.updateDaemon({ version: "0.4.0" });
// { started: true, upToDate: false, resolved: "0.4.0", version: "0.3.0", health: "running",
//   update: { stage: "waiting", leases: 2, from: "0.3.0", to: "0.4.0", forced: false, startedAt: 1760000000000 },
//   lastUpdateFailure: null, latestVersion: null }
```

- **`version`** must be an exact version, such as `0.4.0` or `0.4.0-rc.1`.
- **`started`** is true only for the call that began the update. A call while an update runs follows that update (`started: false`, whatever `version` it names). `force` on a waiting update installs it now.
- **`upToDate`** is true when nothing was needed: the version found is the running one, or the running one is newer than `latest` and you named no `version`.
- **`latestVersion`** is npm's newest Simlock version, as the daemon last checked it (at start, then every 24 hours). It is `null` when the daemon hasn't checked, or `update.check` is `false`.
- **`{ query: true }`** starts nothing and returns the same answer. Call it repeatedly to follow the update; reconnect while the daemon restarts.
- **It works across versions.** A daemon on a different protocol version still accepts `updateDaemon()` (and `stopDaemon()`), so a client that gets `PROTOCOL_VERSION_UNSUPPORTED` for every other call can still update it.
- **Refusals**: `UPDATE_RESOLVE_FAILED`, `UPDATE_UNSUPPORTED_INSTALL` and `UPDATE_SHARED_INSTALL` (see [Errors](/simlock/docs/reference/errors#updating-simlock)).

On a gateway:

- `admin.updateDaemon()` updates the gateway itself. A gateway holds no leases, so it installs straight away.
- `admin.updateWorker({ workerId, version?, force? })` updates one worker, as `simlock worker update` does. It answers like `updateDaemon()`, plus the `workerId`. A worker that isn't connected, or doesn't answer within 90 seconds, fails it with `WORKER_NOT_CONNECTED`.
- To follow a worker's update, call `admin.listWorkers()`: the worker's `version`, `latestVersion`, `update` and `lastUpdateFailure` show it, and `update` is `null` once it is over.

On a worker, `updateWorker()` fails with `UNSUPPORTED_IN_WORKER_MODE`.
