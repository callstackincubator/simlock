A lease gives you one device until you release it or its time to live (TTL) runs out. Only renewing keeps a lease alive. Closing a connection or killing a process doesn't release anything by itself, except the held `simlock lease` command described below.

## Get a device and keep it

```sh
simlock lease --platform ios --device "iPhone 16"
```

`simlock lease` does three things:

1. **It waits.** If no device is free, your request joins a queue. Then Simlock creates or starts the device if it has to. Progress goes to stderr as JSON lines:

   ```json
   {"push":"progress","stage":"queued","queuePosition":2}
   {"push":"progress","stage":"booting","etaMs":45000}
   ```

   | Stage | Means |
   | --- | --- |
   | `queued` | Waiting for a free device. |
   | `downloading` | Downloading an OS version (only with `--allow-download`). |
   | `reclaiming` | The device is being deleted, or a phone wiped, after its last holder. |
   | `provisioning` | Creating the device. |
   | `booting` | Starting the device. |

2. **It prints the grant.** When the device is ready, one JSON line goes to stdout:

   ```json
   {"device":{"id":"dev_8c1f2e7a-4b6d-4e0f-9a3c-5d2b7e1f0a64","driverDeviceId":"6F1D2A8C-3B4E-4F7A-9C2D-8E5B1A7F3C90","spec":{"physical":false,"platform":"ios","model":"iPhone 16","osVersion":"18.6"},"address":"6F1D2A8C-3B4E-4F7A-9C2D-8E5B1A7F3C90","physical":false,"mode":"full"},"environment":{"SIMLOCK_IOS_DEVICE_SET":"/Users/ana/.simlock/devices/ios"},"lease":{"id":"lse_3b9d6c1e-7f2a-4c55-9e0b-8a41d2f6c7e3","deviceId":"dev_8c1f2e7a-4b6d-4e0f-9a3c-5d2b7e1f0a64","requesterId":"claude-code:0f4c2a91-6d1e-4b8a-a3f7-92c5e8d10b46","ownerId":"claude-code:0f4c2a91-6d1e-4b8a-a3f7-92c5e8d10b46","grantedAt":1792834812000,"ttlMs":900000,"ttlDeadline":1792835712000,"lastRenewedAt":1792834812000,"idChosenByRequester":false},"timing":{"estimatedProvisionMs":0,"estimatedBootMs":42000,"estimatedReclaimMs":0,"estimatedReadyMs":42000},"role":"admin"}
   ```

   The fields you need most:

   | Field | What it is |
   | --- | --- |
   | `lease.id` | The lease id. Every later command names the lease by it. |
   | `lease.ttlDeadline` | When the lease expires if nobody renews it, in milliseconds since 1970. |
   | `device.driverDeviceId` | The simulator's UDID. On Android, use `device.address` instead: the emulator's adb serial, such as `emulator-5556`. |
   | `device.mode` | `slim` or `full`. See [Choosing a device](/simlock/docs/using-devices/choosing-a-device#choose-slim-or-full-ios). |
   | `environment` | What other tools need to reach the device. See [Working with a device](/simlock/docs/using-devices/working-with-a-device). |

3. **It holds the lease.** The command keeps running and renews the lease for you. It releases the lease when it exits: on a normal exit, on Ctrl-C or `SIGTERM`, and when its parent process exits.

So run it in the background of a shell that lives as long as your work, read the grant from stdout, and stop the process when you are done:

```sh
simlock lease --platform ios --device "iPhone 16" > lease.json &
```

## Hold a lease across separate commands

Many agents run each command in a new shell that exits right away. A `simlock lease` started there sees its parent exit and releases the device at once. Use one of these instead:

- **`--detach`** prints the grant and exits, and the lease stays. You renew and release it yourself:

  ```sh
  simlock lease --platform android --device "Pixel 8" --detach
  simlock lease renew lse_3b9d6c1e-7f2a-4c55-9e0b-8a41d2f6c7e3
  simlock release lse_3b9d6c1e-7f2a-4c55-9e0b-8a41d2f6c7e3
  ```

  Renew before `ttlDeadline`. If nobody renews it, the lease expires one TTL after the last renewal, and the device is deleted (or a phone wiped).

- **`--bind-pid <pid>`** keeps the command running, but watches the process you name instead of its direct parent. Point it at your agent's own long-running process. The lease is released when that process exits.

## Set how long a lease lasts

| | Default |
| --- | --- |
| TTL of a new lease | 15 minutes |
| Longest TTL you can ask for | 4 hours |

Ask for a different TTL with `--ttl`, for example `--ttl 30m` or `--ttl 2h`. You can use `ms`, `s`, `m`, `h` or `d`; a bare number is milliseconds. Asking for more than the maximum fails with `BAD_REQUEST` (exit 2); it isn't cut down for you. An admin can change both limits with `lease.defaultTtlMs` and `lease.maxTtlMs`.

`simlock lease renew <lease-id>` moves the deadline to now plus the lease's TTL, however much time was left. It prints the updated lease as one JSON line.

- Without `--ttl`, the lease keeps its TTL: a 2-hour lease stays a 2-hour lease.
- With `--ttl`, the new TTL applies from this renewal on.

A held `simlock lease` renews for you. You renew yourself when you used `--detach`, the HTTP API or the programmatic client.

## Release a lease

```sh
simlock release lse_3b9d6c1e-7f2a-4c55-9e0b-8a41d2f6c7e3
```

```json
{"leaseId":"lse_3b9d6c1e-7f2a-4c55-9e0b-8a41d2f6c7e3"}
```

The command returns as soon as the lease ends. Simlock then deletes the simulator or emulator in the background. A physical device is wiped and kept.

Nothing you left on the device survives: apps, files and settings are gone for the next holder. If your lease started from a baseline, the next lease gets a new copy of the baseline, not your changes.

<Aside type="caution">
`simlock release --all` ends every lease on the machine, including other agents' leases. It asks you to confirm, and without a terminal it refuses unless you pass `--yes`. An agent should release only its own lease, by id.
</Aside>

## Waiting in the queue

When every matching device is busy, or the machine is at its limit, your request waits in a first-come, first-served queue. Physical devices have their own queue, so a simulator request never waits behind a physical one.

- With no `--timeout`, the request waits as long as it takes.
- `--timeout 10m` gives up after 10 minutes with `QUEUE_TIMEOUT` (exit 10).
- `--no-wait` fails at once with `NO_CAPACITY` (exit 11) instead of waiting.

`simlock list --requests` shows every waiting request, its place in the queue, and why it is waiting.

<Aside type="caution">
Stopping `simlock lease` while it waits doesn't remove the request from the queue.

- Without `--detach`, Ctrl-C has no effect until the grant: the command keeps waiting, then releases the device as soon as it gets it.
- With `--detach`, a killed command leaves the request waiting. It is granted later, and holds the device until its TTL runs out.

Set `--timeout` if you might stop waiting.
</Aside>

## One lease per requester

By default, each requester can hold one lease, or have one request waiting, at a time. A second request fails with `REQUESTER_ALREADY_LEASED` (exit 13), and the message names the lease you already hold:

```json
{"error":{"code":"REQUESTER_ALREADY_LEASED","message":"Requester claude-code:0f4c2a91-6d1e-4b8a-a3f7-92c5e8d10b46 already holds lease lse_3b9d6c1e-7f2a-4c55-9e0b-8a41d2f6c7e3; release it (`simlock release lse_3b9d6c1e-7f2a-4c55-9e0b-8a41d2f6c7e3`) before requesting another device"}}
```

Keep using that lease, or release it first.

An admin can raise the limit with `lease.maxPerRequester`: either one number for all platforms, or a limit per platform, such as one iOS and one Android lease. With a limit per platform, the message names the platform, and you may have one request waiting per platform. Cancelling a waiting request (`lease.cancel`) then takes an optional `platform` to say which one.

### Choose your own lease id

`--lease-id <id>` sets the lease id yourself, for when your tool already has its own id for the work. Use 1 to 64 letters, digits, `-` and `_`, starting with a letter or digit. Don't reuse an id: one that an active lease or waiting request already has fails with `LEASE_ID_TAKEN` (exit 13).

## Who the requester is

The requester id decides which leases are yours, and the one-lease limit counts per requester id. `simlock lease` uses the first of these that is set:

1. `--agent-id <id>` on the command.
2. The `SIMLOCK_AGENT_ID` environment variable.
3. The agent session: `claude-code:<session id>` under Claude Code, `codex:<session id>` under Codex, `pi:<session id>` under pi. Every command and sub-agent in one session shares that id, and so shares one lease.
4. The process id of that one `simlock` command.

The id can be at most 256 characters and can't hold control characters; otherwise it fails with `BAD_REQUEST`.

<Aside type="caution">
Outside an agent session, with nothing set, each `simlock` command is a different requester, so the one-lease limit never applies between commands. When you run agents some other way, set `SIMLOCK_AGENT_ID` in each agent's environment, and give every agent its own value. Agents that share an id share one lease.
</Aside>

Over HTTP, the requester is the token, not anything the request says. See [Remote agents](/simlock/docs/using-devices/remote-agents).

## See what you hold

| Command | Shows |
| --- | --- |
| `simlock whoami` | Your requester id (as `Principal`) and your role. |
| `simlock status` | The devices, every lease with its requester, and how many requests are waiting. |
| `simlock list --leases` | Every lease, as one JSON line. |
| `simlock list --requests` | Every request waiting for a device. |

On the machine that runs the daemon, the CLI connects as admin. So these commands show everyone's leases, and `lease renew` and `release` work on any lease id from any shell. With an agent token, `simlock status` shows only your own leases and waiting requests.

## When a lease is lost

While a held `simlock lease` runs, it reports on stderr. When Simlock ends the lease, the command writes a `lease-lost` line and exits with code 14:

```json
{"push":"lease-lost","leaseId":"lse_3b9d6c1e-7f2a-4c55-9e0b-8a41d2f6c7e3","deviceId":"dev_8c1f2e7a-4b6d-4e0f-9a3c-5d2b7e1f0a64","reason":"device-lost"}
```

| `reason` | Why |
| --- | --- |
| `expired` | Nobody renewed the lease before its deadline. |
| `killed` | An operator ran `simlock release --all` or `simlock nuke`. |
| `device-lost` | The device stopped and couldn't be brought back, or a physical device was unplugged too long. |

Stop using the device and request a new lease. Your work on the old device is gone.

### When the device crashes

Simlock first tries to start the device again under the same lease. You see `device-unhealthy`, then `device-recovered` when it is back. The lease is still yours, but apps you started are no longer running.

### When the daemon stops

If the connection to the daemon breaks (the daemon stopped or crashed), the lease isn't released. `simlock lease` exits with code 1 and tells you how long the lease is still yours:

```json
{"error":{"code":"DAEMON_CONNECTION_LOST","message":"lost the daemon connection; lease lse_3b9d6c1e-7f2a-4c55-9e0b-8a41d2f6c7e3 is still yours until its ttlDeadline 1792835712000 -- renew it with `simlock lease renew lse_3b9d6c1e-7f2a-4c55-9e0b-8a41d2f6c7e3` or let it expire"}}
```

Leases survive a daemon restart: run `simlock lease renew <lease-id>` afterwards to keep yours. If your simulator or emulator is no longer running when the daemon starts again, the lease ends with `device-lost`.
