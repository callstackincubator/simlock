You only have to name the platform. Leave everything else out and you get a phone on the newest OS installed:

```sh
simlock lease --platform ios
```

Add options when you need a specific device:

```sh
simlock lease --platform ios --device "iPhone 16" --os 18.6
```

The grant always says what you actually got: the model in `device.spec.model`, the OS in `device.spec.osVersion` and, on iOS, the mode in `device.mode`.

## See what you can ask for

`simlock catalog` lists the OS versions installed on this machine, the models it knows, which OS versions each model runs, and the default model for each class:

```sh
simlock catalog --platform ios
```

```text
Platform: ios
  Runtimes: 18.6, 26.1 (default: 26.1)
  Models:
    phone (default: iPhone 17):
      iPhone 17: 26.1
      iPhone 16: 18.6, 26.1
      iPhone 16 Pro: 18.6, 26.1
    tablet (default: iPad Pro 11-inch (M5)):
      iPad Pro 11-inch (M5): 26.1
```

- A model shown with `(no paired runtime)` can't be leased until an OS version it supports is installed.
- On Android the catalog also lists the installed system images (API level, tag and CPU type) and other names a model goes by, such as its AVD id.
- Add `--json` to get the same data as one JSON line.

## Pick the platform

`--platform ios` or `--platform android` is required.

- iOS needs a Mac with Xcode.
- Android needs the Android SDK, on macOS or Linux.

If the tools for a platform are missing, a lease for it fails with `NO_DRIVER` (exit 12). Run `simlock doctor` to see what is missing.

## Ask for a model or a kind of device

Use one of these, not both:

- `--device <model>` asks for an exact model, spelled as the catalog prints it: `"iPhone 16"`, `"Pixel 8"`.
- `--class <class>` asks for a kind of device and lets Simlock pick the model: `phone`, `tablet`, `watch`, `tv`, `vision`, `auto` or `desktop`.
- With neither, you get a `phone`.

```sh
simlock lease --platform android --class tablet
```

With `--class`, you get an idle device of that class if there is one. Otherwise Simlock creates the first model on the class's list that this machine knows. For phones, that is `iPhone 17`, then `iPhone 16`, `iPhone 15` and so on on iOS, and `Pixel 9`, then `Pixel 8`, `Pixel 7` on Android. An admin can change the lists with `ios.defaultModels` and `android.defaultModels` (see [Configuration reference](/simlock/docs/reference/configuration)).

What can go wrong:

- Passing both `--device` and `--class` fails with `BAD_REQUEST` (exit 2).
- A model name longer than 256 characters fails with `BAD_REQUEST`.
- A model this machine doesn't know fails at once with `UNKNOWN_MODEL` (exit 12):

  ```json
  {"error":{"code":"UNKNOWN_MODEL","message":"Unknown ios model: iPhone 19; a newer Xcode version may add this device"}}
  ```

## Choose the OS version

Without `--os`, you get the newest OS installed for the platform. Use `--os` to ask for one version or a range:

| You write | You get |
| --- | --- |
| `--os 18.6` | exactly 18.6 |
| `--os ">=18"` | 18.0 or newer |
| `--os ">=18 <26"` | 18.0 up to, but not including, 26 |
| `--os "18 - 26"` | 18.0 up to and including every 26.x |
| `--os 35` | Android API level 35 |

Quote ranges, so your shell doesn't read `>` or `<` as a redirect.

How ranges work:

- A range is one or more of `>=`, `>`, `<=`, `<` followed by a version, separated by single spaces. Or two versions with ` - ` between them.
- A short version covers everything under it: `<=26` includes 26.1.
- With a range, you get an idle device inside the range if there is one. Otherwise Simlock creates one on the newest installed OS inside the range.
- A range never downloads anything. If no installed OS is inside it, the lease fails at once with `RUNTIME_MISSING` (exit 12).

Anything that isn't a range is read as an exact version. That is how Android names like `Baklava` or `34-ext12` work.

What is refused with `BAD_REQUEST` (exit 2):

- Other range styles: `^18`, `~18`, `18.x`, `*`, `||`.
- An exact version longer than 64 characters, or one with spaces, control characters or `;`, or one that starts with `-`.

## Choose slim or full (iOS)

A **slim** simulator has background services that agents rarely need turned off, such as widgets, Siri, Spotlight, iCloud, the App Store, Photos and Health. It uses far less memory than a **full** one.

- `--mode slim` asks for a slim simulator.
- `--mode full` asks for a normal one.
- Without `--mode`, you get the machine's default, which is `full` unless an admin changed it.

What to expect:

- A full lease never gets a slim device.
- Slim is best effort. iOS versions older than 18.5, and all Android devices, can't be slimmed, so you get a full device instead. Check `device.mode` in the grant.
- A lease only reuses an idle device of the mode it asked for. So your request may wait for a new device even while devices of the other mode sit idle.

If a test fails because a push notification, a Spotlight result, an App Store sheet or a system picker never appears, check `device.mode`. Ask for `--mode full` when your app needs those features.

### Keep a category running

When a test needs one part of what slim turns off, name its category with `--except` instead of giving up the whole saving:

```sh
simlock lease --platform ios --mode slim --except store,other
```

The simulator boots with those categories running and the rest of the slim set off, and the grant reports `device.except` beside `device.mode`:

```json
{ "device": { "mode": "slim", "except": ["store", "other"] } }
```

- `--except` needs a slim lease. With `--mode full`, a worker whose default is `full` and no `--mode`, or a full `--baseline`, it is refused with `BAD_REQUEST`. A slim baseline on a worker whose default is `full` is granted.
- A name the worker does not slim is refused with `BAD_REQUEST`, as is a name given twice, a name that is not lowercase letters, digits and `-`, and more than 16 names.
- It is for iOS simulators: `--platform android` and `--physical` are refused.
- On a runtime older than iOS 18.5 you get a `full` device with no `except`.
- A device the worker holds warm is shut down and booted again with your list before you get it, so the lease can take a little longer than one without `--except`. If that boot fails, the device is deleted and Simlock tries once more with another; a second failure is `PROVISION_FAILED`.
- Over HTTP the body takes `except` as a list, and over MCP `lease_simulator` takes the same `except`.

## Choose the system image (Android)

`--image-tag` picks the kind of Android system image, such as `google_apis_playstore` for Google Play or `default` for plain Android. You can use the tags that `simlock catalog --platform android` lists under images.

```sh
simlock lease --platform android --device "Pixel 8" --image-tag google_apis_playstore
```

- Without `--image-tag`, you get the `google_apis` image for the machine's CPU when it is installed, or another installed image for that API level.
- With `--image-tag` and no `--os`, you get the newest API level that has an image with that tag.
- An image tag never downloads anything. If no image with that tag is installed for the API level, or the image doesn't fit the model, the lease fails with `RUNTIME_MISSING` (exit 12).
- On iOS, `--image-tag` fails with `BAD_REQUEST` (exit 2).

## Start from a baseline

A baseline is a simulator or emulator an operator prepared and saved, with apps, files and settings already on it, such as your app's build or a signed-in test account. `--baseline` gives you a fresh copy of it:

```sh
simlock lease --platform android --baseline checkout
```

You can also set `SIMLOCK_BASELINE=checkout` in the environment. The flag wins over the variable, and an empty variable is ignored.

What to expect:

- You get a copy of the newest version of the baseline, including a version saved while you were waiting.
- When your lease ends, your copy is deleted. The next lease gets a new copy, without your changes.
- A lease without `--baseline` never gets a copy of a baseline.
- `simlock status` shows which baseline and version a device came from.

The baseline already sets the platform, model, OS, mode and image tag. You can still pass them, but they must match. `--device` and `--os` match as described above, so `--device "pixel 9"` and `--os ">=35"` both match a Pixel 9 baseline on Android 36.

What can go wrong:

| Error | Why |
| --- | --- |
| `BASELINE_MISMATCH` (exit 2) | An option you passed differs from the baseline. |
| `UNKNOWN_BASELINE` (exit 12) | No baseline has that name. Check `simlock baseline list`. |
| `BASELINE_STALE` (exit 12) | The OS or image the baseline was saved on has been removed from the machine. |

`--baseline` can't be combined with `--class` or `--physical`.

<Aside type="caution">
Every copy holds what the baseline holds, including a signed-in account. Don't save a baseline with credentials you wouldn't give to every agent that can name it.
</Aside>

## When the runtime is not installed

If the OS version you ask for isn't installed, the lease fails with `RUNTIME_MISSING` (exit 12), and the message says how to get it:

```json
{"error":{"code":"RUNTIME_MISSING","message":"iOS 26.2 is not installed; pass --allow-download (or set downloads.policy) to download it"}}
```

You have two options:

- Ask an admin to install it, for example with `simlock component install ios 26.2` (see [Runtimes and images](/simlock/docs/worker/runtimes-and-images)).
- Let your lease download it with `--allow-download`.

<Aside type="caution">
An OS runtime or system image is several gigabytes, and downloading it can take many minutes. Simlock never downloads one unless you ask.
</Aside>

```sh
simlock lease --platform ios --device "iPhone 16" --os 26.2 --allow-download
```

While it downloads, `simlock lease` reports a `downloading` stage on stderr, with a percentage when one is available.

What to expect:

- **One download at a time per platform.** A lease that needs a different OS waits for the current download to finish. Leases that need the same OS share one download.
- **Time limit.** The whole wait, including time spent behind another download, is limited by the machine's download timeout (20 minutes unless an admin changed it). Running out fails with `DOWNLOAD_TIMEOUT` (exit 10). The download may still be further along when you retry.
- **The machine's policy decides.** With `downloads.policy` set to `never`, nothing downloads and the lease fails with `RUNTIME_MISSING`, even with `--allow-download`. With `always`, a missing OS downloads even without the flag. The default, `on-request`, downloads only when you pass `--allow-download`.
- **Android licences.** Downloading an Android system image needs the SDK licences accepted on that machine. Until an admin sets `downloads.acceptAndroidLicenses` to `true`, it fails with `LICENSE_NOT_ACCEPTED` (exit 12).
- **Disk space.** If the download won't fit on the disk, the lease fails at once with `INSUFFICIENT_DISK_SPACE` (exit 12).
- **Impossible pairs.** An OS that can never run the model you named, such as one older than the model supports, fails at once and downloads nothing.
- **Through a gateway**, `--allow-download` does nothing. Only OS versions already installed on a worker count.

## Lease a real phone instead

`--physical` asks for a real phone or tablet that an admin has enrolled. `--mode`, `--image-tag` and `--allow-download` don't apply to it. See [Physical devices](/simlock/docs/using-devices/physical-devices).
