**Result:** an agent drives your app with [agent-device](https://github.com/callstack/agent-device) (open, read the screen as a tree of elements, tap, type, screenshot) on its own leased device, and the device is deleted when it closes.

```sh
agent-device open --platform ios --device "iPhone 16"
agent-device open com.example.myapp
agent-device snapshot
agent-device close
```

`agent-device open` takes an ordinary Simlock lease, held by the agent's token. Later commands use that lease.

## Before you start

| Where | Needs |
| --- | --- |
| Each worker | agent-device 0.21.28 or later, runnable by the user who runs the Simlock daemon. Simlock never installs or updates it. |
| Each worker | HTTP on. A standalone worker has it on by default. |
| Each agent's machine | agent-device 0.21.28 or later. |
| Each agent | Its own agent token, unless it runs on the worker's own Mac ([On the same Mac](#on-the-same-mac)). |

For agents on other machines, the worker or gateway must be reachable over HTTPS. Simlock does not serve HTTPS itself; see [Turn on the web console and HTTP](/simlock/docs/worker/console-and-http).

## Turn it on (operator)

<Steps>

1. **On a standalone worker**, agent-device is on by default. Install agent-device, then restart the daemon so it finds the command:

   ```sh
   simlock daemon stop
   simlock daemon start
   ```

   Until agent-device is installed, the worker shows it as `off`, and `simlock doctor` does not mention it.

   **On a worker that has joined a gateway**, agent-device is off. Turn it on:

   ```sh
   simlock config set capabilities.agent-device.enabled true
   ```

   Once you set it to `true` yourself, a missing `agent-device` command shows in `simlock doctor`. If `agent-device` is not on the daemon's `PATH`, set `capabilities.agent-device.command` to its full path.

2. **With a gateway**, turn it on there too. The gateway sends each agent to a worker where agent-device works:

   ```sh
   simlock --gateway config set capabilities.agent-device.enabled true
   ```

3. **Restart each daemon you changed** with `simlock daemon stop` and `simlock daemon start`.

4. **Create one agent token per agent**, on the worker, or on the gateway for a fleet:

   ```sh
   simlock token create --role agent --label ui-agent-1
   ```

   ```json
   {"secret":"slk_Qm9yZWFsaXMtNzEzMi1kZXZpY2UtdG9rZW4tZXhhbXBsZQ","token":{"id":"tok_5e0a9c3d-2f7b-4d1e-8c6a-3b9f1e7d2a50","role":"agent","label":"ui-agent-1","createdAt":1792834812000}}
   ```

   The secret is shown only once. Give it to the agent.

</Steps>

**Check:** `simlock worker list` ends each worker's line with `agent-device available`. `agent-device off` or `agent-device unavailable:` with a reason means it does not work there; `simlock doctor` says how to fix it:

```text
agent-device  fail  found 0.20.3, need 0.21.28 or later; install agent-device 0.21.28 or later, then restart the daemon (`simlock daemon stop`, then `simlock daemon start`)
```

If agent-device is missing or too old, Simlock keeps running without it, and every agent-device request answers `agent-device is not available on this simlock:` with the reason. Restart the daemon after you fix it.

## Drive an app (agent)

<Steps>

1. Connect agent-device to Simlock once. The URL is the worker's HTTP address, or the gateway's (port 4700 by default), followed by `/v1/agent-device`:

   ```sh
   export AGENT_DEVICE_DAEMON_AUTH_TOKEN=slk_Qm9yZWFsaXMtNzEzMi1kZXZpY2UtdG9rZW4tZXhhbXBsZQ
   agent-device connect proxy --daemon-base-url https://mac-studio-2.example.com/v1/agent-device
   ```

2. Name your session:

   ```sh
   export AGENT_DEVICE_SESSION=agent-1
   ```

3. Open a device, install and drive the app, and close:

   ```sh
   agent-device open --platform ios --device "iPhone 16"
   agent-device install MyApp ./build/Debug-iphonesimulator/MyApp.app
   agent-device open com.example.myapp
   agent-device snapshot
   agent-device screenshot home.png
   agent-device close
   ```

</Steps>

**Check:** while the session is open, `simlock status` on the worker shows a lease held by the agent's token.

<Aside type="caution" title="Several agents on one machine">
Each agent sets its own `AGENT_DEVICE_SESSION` (or passes `--session` on every command). Without one, a command uses the last session saved on that machine, which may be another agent's.
</Aside>

Each agent-device session holds one device. For a second device, open a second session.

## Ask for a device with `open`

`--platform ios` or `android` is required. With nothing else, you get a phone.

| Option | Asks for |
| --- | --- |
| `--device "iPhone 16"` | That model. |
| `--target mobile`, `tv` or `desktop` | A phone, a TV or a desktop device. |
| `--os` | An OS version or range: `26.0`, `>=18 <27`, `18 - 26`. A range gets the newest installed version inside it. |
| `--image-tag` | On Android, a system image tag, such as `google_apis_playstore`. |
| `--device-baseline` (`deviceBaseline` in an allocate) | A fresh copy of a saved baseline ([Lease a copy of a prepared device](/simlock/docs/using-devices/lease-a-prepared-device)). `--target` is ignored beside it, and `--physical` is refused with it. |
| `--device-mode` (`deviceMode` in an allocate) | A `full` or `slim` iOS simulator. Without it, the worker's default. Below iOS 18.5 you get full. |
| `deviceExcept` in an allocate | With `deviceMode: "slim"`, slim categories to keep running, such as `["store", "other"]`, as `simlock lease --except` does. The agent-device CLI has no flag for it; a raw allocate carries the key. `null` means absent. |
| `runId` in an allocate | The run id of the Simlock lease, so `simlock release --run <id>` ends it. A `runId` outside the rule (1 to 128 letters, digits, `.`, `_` or `-`) still goes to agent-device, and the lease has none. |
| `--physical` | An enrolled phone ([Use a real phone](#use-a-real-phone)). |

`--device-baseline` and `--device-mode` need an agent-device release that has those flags.

The reply to `open` names the model, OS and image tag you got, and the baseline name and version when you asked for one. On a simulator or emulator, `data.lease.device` in the `agent_device.lease.allocate` reply also carries `deviceMode` (`slim` or `full`).

If every matching device is taken, `open` waits up to 330 seconds, then fails with `timed out waiting for a device; nothing was leased`.

## What to expect

- **Each lease is its own.** Every lease has its own agent-device sessions, uploads and artifacts, so two runs on one token never share a session, even under the same session name. A call that names no lease, such as `session list`, sees the whole token's.
- **Commands and heartbeats keep the lease alive.** Standalone `boot` checks the lease but does not renew it. The TTL is the one agent-device asks for, or the worker's default (15 minutes). An operator can cap it with `capabilities.agent-device.leaseTtlCapMs`.
- **`close` gives the device back.** Simlock ends the lease and deletes the device; the next agent gets a new one.
- **`install` sends the app from your machine.** agent-device uploads it. A path on the worker is refused.
- **`devices` lists only your devices**, and nothing before `open`.
- **Simlock picks the device.** Do not pass `--udid` or `--serial`. After `open`, `--device` may name only the leased device: its name, its model in any letter case (an enrolled phone's model too, even when the catalog does not list it), or a catalog alias of that model. `test --device` takes only the names or ids of devices you hold. Simlock answers `boot` on a leased device itself; its `id` is the device's UDID on iOS or serial on Android. The agent-device `leaseId` is the Simlock lease id, usable with `/v1/leases/<id>/…`.
- **A `batch`** can nest at most 8 levels deep and hold at most 1000 steps in all.
- **`orientation` on an iPhone or iPad simulator** (not a foldable iPhone Duo) is done by Simlock, and replies `Rotation requested: landscape-left (unconfirmed)`: it was sent, but nothing confirms it happened. Use `portrait`, `portrait-upside-down`, `landscape-left` or `landscape-right`, or `upside-down`, `left` and `right`. On every other device, and as a `batch` step, agent-device rotates as it normally does.

### Keep a device through a close

A test runner can allocate with `retainOnClose: true` to keep its device through a bare `close`, `close <app>`, or a batch that holds a close. Release the lease when the run finishes; otherwise it expires after its TTL.

In the allocate reply JSON, `data.lease.device.udid` names an iOS device and `data.lease.device.serial` an Android device. agent-device's client drops these fields when it rebuilds the reply.

## On the same Mac

An agent on the worker's own Mac, running as the same user, needs no token of its own. This works on a standalone worker, where HTTP and agent-device are on by default.

Each time the worker starts, it writes `agent-device-profile.json` in its data folder (`~/.simlock/`), readable only by that user. Connect with it, and pass `--session` on every command:

```sh
agent-device connect --remote-config ~/.simlock/agent-device-profile.json --session s1
agent-device open --platform ios --session s1
agent-device open com.example.myapp --session s1
agent-device snapshot --session s1
agent-device close --session s1
```

- All local agents share the file's one token, so a call that names no lease, such as `devices` before `open`, sees every local agent's devices. Give each agent its own `--session` name.
- The token stays the same across restarts, so a saved connection keeps working.
- If the file changes anyway (you changed `http.port`, or revoked the token), agent-device refuses the saved connection with `Active remote connection config changed`. Run the `connect` line again with `--force`.
- The worker removes the file, and revokes its token, when you turn HTTP or agent-device off.
- A worker that has joined a gateway does not write the file.
- The file's token is labelled `agent-device on this Mac`. Do not give your own tokens that label: the worker revokes them at its next start.

## Use a real phone

`open --physical` leases an enrolled phone, and the reply names it with `physical: true`. See [Lease a real iPhone or Android phone](/simlock/docs/using-devices/lease-a-phone). Phones need setup on the worker:

- **iPhone:** set the signing team and bundle id, then restart the daemon:

  ```sh
  simlock config set capabilities.agent-device.ios.teamId <team-id>
  simlock config set capabilities.agent-device.ios.bundleId <bundle-id>
  ```

  `provisioningProfile` and `signingIdentity` are for manual signing only. Setting a provisioning profile switches agent-device to manual signing, which fails with an Xcode-managed profile.

- **Android phone:** the worker's phone support uses `adb` without Simlock's version check. Make sure it comes from the same Android SDK platform-tools as Simlock's.

If phone support cannot start, `simlock doctor` prints a line starting `phone daemon:`. Simulators and emulators keep working.

## Through a gateway

Point `connect proxy` at the gateway, with a token made on the gateway. `open` lands on a worker where agent-device works, and later calls for that lease go to the same worker. You never name a worker.

If that worker disconnects, nothing is released: requests answer `agent-device is not available on this simlock: the worker holding this device is not connected to the gateway; try again`. Once it is back, before the lease runs out, the next request works on the same device.

## When Simlock ends the lease

If the lease ends any other way than your `close` (it expired, an operator released it, or the device was lost), a heartbeat or standalone `boot` answers:

```text
lease ended by simlock; run disconnect, then open
```

Run `agent-device disconnect`, then `open`. You get a new, clean device.

<Aside type="caution" title="After an agent-device or Simlock restart">
Simlock keeps your lease, device and apps, and your next heartbeat succeeds. agent-device's own session is gone. On iOS, a command before a new `open` answers `SESSION_NOT_FOUND`, or `AMBIGUOUS_MATCH` (`<n> devices match this request equally`) while other simulators are booted on the worker; the devices it lists are not yours to pick. Run `open <app>` again on the same session: it opens on your leased device. On Android, commands go on without a new `open`. While Simlock restores the lease, a heartbeat can answer `… the lease is being restored after an agent-device restart; try again`: retry it. A lease made with `retainOnClose` loses that flag across a restart.
</Aside>

## When it fails

Errors from Simlock's agent-device front carry a reason and a `retriable` boolean. JSON-RPC replies put them at `error.data.details.reason` and `error.data.retriable`; upload, artifact and health errors put `reason` and `retriable` beside `code`.

| Reason | Retry? |
| --- | --- |
| `REFUSED_BY_SIMLOCK` | Never: the request was refused. |
| `SIMLOCK_UNAVAILABLE` | Yes when a daemon is starting or failed to start, a worker cannot serve the call right now, a forward failed, or there is no capacity. A turned-off module, a missing or too-old agent-device, an unusable state folder or a missing lease ceiling needs the operator. |
| `WORKER_UNREACHABLE` | When the lease's worker reconnects. |
| `NO_DEVICE_IN_TIME` | Yes, after the queue timed out. |
| `SIMLOCK_FAILED` | Only when Simlock could not check your leases. |
| `LEASE_ENDED_BY_HOST` | No. Open a new device. |

Sign-in errors (`UNAUTHENTICATED`, `FORBIDDEN`) and errors from outside Simlock, such as a proxy error, carry no reason. Errors from agent-device itself pass through unchanged.

| Message | Fix |
| --- | --- |
| `refused: agent-device through simlock needs an agent token` | You used an operator token. Create an agent token. |
| `refused: this agent-device is too old for simlock; upgrade it` | Update agent-device on the agent's machine. |
| `refused: this agent-device is too old to use through a gateway; update it` | Update agent-device on the agent's machine. |
| `refused: name --platform ios or android` | Pass `--platform` to `open`. |
| `refused: boot names no lease; open a device first` | Run `open` before `boot`. |
| `refused: this lease has ended; open a device` | Run `open` again. |
| `refused: simlock picks the device` | Drop `--udid`, `--serial` or a `--device` that names another device. The leased device's name or model is accepted, except by `test`, which takes names and ids only. |
| `refused: simlock chooses the device set; run disconnect, then connect proxy without --ios-simulator-device-set` | Do as the message says. |
| `refused: send the app from your machine as an upload` | Give `install` a path on your machine. |
| `No active proxy device lease for this session; run open first.` | The session has no lease, often because parallel agents share one session. Set `AGENT_DEVICE_SESSION` per agent, then `open`. |
| `refused: lease <id> is not one of yours on this gateway` | Same cause: give each agent its own `AGENT_DEVICE_SESSION`, then `open`. |
| `refused: malformed physical` | `physical` must be true or false. |
| `refused: unknown --target <value>; use mobile, tv or desktop` | Use one of those. |
| `refused: malformed osVersion`, `refused: malformed imageTag`, `refused: malformed deviceBaseline` | Pass text. |
| `refused: a batch nests more than 8 levels deep`, `refused: a batch has more than 1000 steps` | Split the batch. |
| `Unknown orientation <name>; use portrait, portrait-upside-down, landscape-left or landscape-right` | Use one of those; `auto` is refused. |
| `refused by simlock: <message>` | Simlock refused the lease, for example an unknown model, an OS range it cannot read, an image tag on iOS, a `deviceMode` other than `slim` or `full`, or a bad `deviceExcept`. Fix what the message names. |
| `refused by simlock: No worker in the fleet can currently serve this request` | Every worker that serves agent-device is drained. Ask the operator to bring one back, or wait. |
| `agent-device is not available on this simlock: <reason>` | agent-device is missing, too old, starting or crashed on the worker. Ask the operator. |
| `agent-device is not available on this simlock: phone daemon: <message>` | Phone support on the worker is starting or down. Simulator leases keep working. |
| `INPUT_UNAVAILABLE` message from `orientation` | Simlock could not send the rotation. Retry. |

Every `capabilities.agent-device.*` key: [Configuration reference](/simlock/docs/reference/configuration#optional-modules).
