[agent-device](https://github.com/callstack/agent-device) is Callstack's command-line tool for driving mobile apps: it opens an app, reads the screen as a tree of elements, taps, types and takes screenshots. With Simlock, `agent-device open` leases a simulator or emulator from Simlock, and every later command goes to that device. Each agent gets its own device, and a device is wiped when the agent closes it.

Simlock runs two agent-device daemons on each worker and watches both: one over the simulators and emulators Simlock leases, and a phone daemon beside it that sees the phones plugged into the host. For an iPhone the phone daemon needs `teamId` and `bundleId`, set with `simlock config set capabilities.agent-device.ios.teamId <id>` (and `bundleId`). `provisioningProfile` and `signingIdentity` are for manual signing only: setting a provisioning profile switches agent-device to manual signing, which an Xcode-managed profile fails. The setting takes effect on daemon restart. If it cannot start, `simlock doctor` prints a line starting `phone daemon:`; the simulator daemon and the worker's agent-device status are not affected. Agents lease a phone through it with `--physical`. Agents reach agent-device over HTTP, on the worker or through a gateway, with a Simlock agent token.

## Before you start

On each worker:

- agent-device 0.21.28 or later, installed so the daemon's user can run `agent-device`. Simlock never installs or updates it.
- HTTP on, since agents reach agent-device over HTTP. A standalone worker has it on by default.

On each agent's machine:

- agent-device 0.21.28 or later. An older CLI is refused with `refused: this agent-device is too old for simlock; upgrade it`.
- Its own Simlock agent token, unless it runs on the worker's Mac (see [On the same Mac](#on-the-same-mac)). Simlock tells agents apart by token: two agents that share a token share one agent-device session and see each other's devices.

agent-device through Simlock drives simulators, emulators and, with `--physical`, phones enrolled in Simlock (see [Physical devices](/simlock/docs/using-devices/physical-devices)). `open --physical` leases an enrolled phone: the command goes to the phone daemon and the reply names the device with `physical: true`. Simlock picks the phone, so name no `--udid` or `--serial`.

Each agent-device session is its own requester and holds one device. To use a second device, open a second session.

The phone daemon runs `adb` without Simlock's version check, so its `adb` must come from the same Android SDK (platform-tools) as Simlock's.

## Turn it on

<Steps>

1. A standalone worker serves agent-device by default, with HTTP on `127.0.0.1:4701`: there is nothing to turn on. Install agent-device so the daemon's user can run it, then restart the worker (`simlock daemon stop`, then `simlock daemon start`); the worker looks for the command only when it starts. Until agent-device is installed, the worker's agent-device capability is `off` and `simlock doctor` says nothing. A worker that joins a gateway has agent-device off, and HTTP off for good; turn on only agent-device there:

   ```sh
   simlock config set capabilities.agent-device.enabled true
   ```

   For agents on other machines, set `http.host` and put a reverse proxy with TLS in front; Simlock does not do HTTPS itself (see [Configuration reference](/simlock/docs/reference/configuration)). If `agent-device` is not on the daemon's `PATH`, set `capabilities.agent-device.command` to its full path. Setting `capabilities.agent-device.enabled` to `true` yourself makes a missing command show up as a `simlock doctor` finding.

2. With a gateway, turn agent-device on there too. The gateway runs no agent-device of its own; it sends each agent to a worker where agent-device is available:

   ```sh
   simlock --gateway config set capabilities.agent-device.enabled true
   ```

3. Restart each daemon you changed:

   ```sh
   simlock daemon stop
   simlock daemon start
   ```

4. Check it. `simlock worker list` ends each worker's line with `agent-device available`, `agent-device off`, or `agent-device unavailable:` and the reason. `simlock doctor` reports the same problem with how to fix it:

   ```text
   agent-device  fail  found 0.20.3, need 0.21.28 or later; install agent-device 0.21.28 or later, then restart the daemon (`simlock daemon stop`, then `simlock daemon start`)
   ```

5. Create one agent token per agent, on the worker, or on the gateway for a fleet:

   ```sh
   simlock token create --role agent --label ui-agent-1
   ```

   ```json
   {"secret":"slk_Qm9yZWFsaXMtNzEzMi1kZXZpY2UtdG9rZW4tZXhhbXBsZQ","token":{"id":"tok_5e0a9c3d-2f7b-4d1e-8c6a-3b9f1e7d2a50","role":"agent","label":"ui-agent-1","createdAt":1792834812000}}
   ```

   The secret is shown once. Give it to the agent.

</Steps>

If agent-device is missing or too old, Simlock runs on without it, and every agent-device request answers `agent-device is not available on this simlock:` with the reason. After you fix it, restart the daemon.

## Drive an app

On the agent's machine, connect agent-device to Simlock once, then use it as usual:

```sh
export AGENT_DEVICE_DAEMON_AUTH_TOKEN=slk_Qm9yZWFsaXMtNzEzMi1kZXZpY2UtdG9rZW4tZXhhbXBsZQ
agent-device connect proxy --daemon-base-url https://mac-studio-2.example.com/v1/agent-device

agent-device open --platform ios --device "iPhone 16"
agent-device install MyApp ./build/Debug-iphonesimulator/MyApp.app
agent-device open com.example.myapp
agent-device snapshot
agent-device screenshot home.png
agent-device close
```

The URL is the worker's HTTP address, or the gateway's (port 4700 by default), followed by `/v1/agent-device`.

- **`open` takes a lease.** `--platform ios` or `android` is required. `--device "iPhone 16"` asks for that model. `--target mobile`, `tv` or `desktop` asks for a phone, TV or desktop device. `--os` names an OS version or a range (`26.0`, `>=18 <27`, `18 - 26`; a range gets the newest installed version in it), and on Android `--image-tag` names a system image tag such as `google_apis_playstore`. With none of these, Simlock leases a phone. The reply to `open` names the model, OS and image tag you got. If every match is taken, `open` waits in Simlock's queue for up to 330 seconds, then fails with `timed out waiting for a device; nothing was leased`.
- **The lease is an ordinary Simlock lease.** `simlock status` and the console show it, held by the token. Its id is the one agent-device chose.
- **Commands keep the lease alive.** agent-device renews it before each command and while a command runs. An agent that stops sending commands loses the device one TTL later. The TTL is the one agent-device asks for, or the worker's default (15 minutes) when it asks for none. An admin can cap it with `capabilities.agent-device.leaseTtlCapMs`.
- **`close` gives the device back.** Simlock ends the lease and wipes the device for the next agent.
- **`install` sends the app from your machine.** The path is on the agent's machine, and agent-device uploads it. A path on the worker is refused with `refused: send the app from your machine as an upload`.
- **`devices` lists only your devices**, and an empty list before `open`.

## On the same Mac

On a standalone worker, where HTTP and agent-device are on by default, an agent on the same Mac, running as the same user, needs no token of its own. At each start the worker writes `agent-device-profile.json` in its data directory (`~/.simlock/` for a user session), readable only by its user. It holds the worker's agent-device URL and one agent token, labelled `agent-device on this Mac`. Connect with that file:

```sh
agent-device connect --remote-config ~/.simlock/agent-device-profile.json --session s1
agent-device open --platform ios --session s1
agent-device snapshot --session s1
agent-device close --session s1
```

Pass `--session` on every command. All local agents share the profile's one token, so they share one Simlock identity: give each agent its own `--session` name, or two agents will see each other's devices.

The worker keeps the same token across restarts, so a saved connection keeps working. If the file changes anyway (you changed `http.port`, or revoked the token with `simlock token revoke`), agent-device refuses the saved connection with `Active remote connection config changed`. Run `agent-device connect --remote-config ~/.simlock/agent-device-profile.json --session s1 --force` to refresh it. The worker removes the file and revokes the token when HTTP or agent-device is turned off (`http.enabled` or `capabilities.agent-device.enabled` set to `false`). A worker that joins a gateway writes none. Do not give your own tokens the label `agent-device on this Mac`: the worker revokes them at the next start.

## Through a gateway

Point `connect proxy` at the gateway and use a token created on the gateway. `open` lands on a worker whose agent-device is available, and every later command for that device goes to the same worker. You never name a worker.

If that worker disconnects, requests for your device answer `agent-device is not available on this simlock: the worker holding this device is not connected to the gateway; try again`. Nothing is released. Once the worker is back, before the lease runs out, the next request works on the same device.

## When Simlock ends the lease

If the lease ends for any reason other than your `close` (it expired, an admin released it, the device was lost, or the worker's daemon or agent-device restarted), the next command answers:

```text
lease ended by simlock; run disconnect, then open
```

Run `agent-device disconnect`, then `open` again. You get a new, clean device; anything on the old one is gone.

<Aside type="caution">
Restarting a worker's daemon ends every agent-device lease on that worker, even though ordinary Simlock leases survive a restart.
</Aside>

## Messages you may see

| Message | Meaning |
| --- | --- |
| `refused: agent-device through simlock needs an agent token` | You used an operator token. Create an agent token. |
| `refused: name --platform ios or android` | `open` needs `--platform`. |
| `refused: simlock picks the device` | A `--udid`, `--serial` or `--device` names a device that is not the one Simlock leased to you. |
| `refused: simlock chooses the device set; run disconnect, then connect proxy without --ios-simulator-device-set` | Simlock decides which devices agent-device sees. |
| `refused: malformed physical` | `physical` was not true or false. |
| `refused: unknown --target <value>; use mobile, tv or desktop` | `--target` named a device class Simlock does not map. |
| `refused: malformed osVersion`, `refused: malformed imageTag` | `--os` or `--image-tag` was not a string. |
| `refused by simlock: <message>` | Simlock refused the lease, for example a model it does not know, an OS range it cannot read, or an image tag on iOS. |
| `refused: this agent-device is too old to use through a gateway; update it` | Upgrade the agent's agent-device. |
| `agent-device is not available on this simlock: <reason>` | agent-device is missing, too old, starting or crashed on the worker. |
| `agent-device is not available on this simlock: phone daemon: <message>` | `open --physical`, or a command on a phone lease, found the phone daemon starting or down. Simulator leases keep working; `simlock doctor` prints the phone daemon's finding. |
| `refused by simlock: No worker in the fleet can currently serve this request` | `open` (a new allocate) found every worker that can serve agent-device drained. Undrain a worker, or wait for one to take the request. Leases already held keep working. |
