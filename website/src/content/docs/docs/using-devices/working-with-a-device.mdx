Once you hold a lease, run your `simctl` and `adb` commands through `simlock simctl` and `simlock adb`. They take the same arguments, print the same output and exit with the same code as the real tools, but point them at Simlock's devices.

You need these wrappers because Simlock keeps its devices apart from your own, so other tools and agents can't wipe them by accident. As a result, a plain `xcrun simctl` or `adb` doesn't see the device you leased.

The exception: when an admin sets `drivers.ios.deviceSet` to `default`, iOS simulators live alongside your own simulators in Xcode, and a plain `xcrun simctl` sees them. Android is the same under either setting. To build your own app for the device, see [Build and run your app](/simlock/docs/using-devices/build-and-run).

## Find your device in the grant

Take these from the grant line `simlock lease` prints (see [Lease lifecycle](/simlock/docs/using-devices/lease-lifecycle#get-a-device-and-keep-it)):

| Platform | Your device | Grant field | Example |
| --- | --- | --- | --- |
| iOS | Simulator UDID | `device.driverDeviceId` | `6F1D2A8C-3B4E-4F7A-9C2D-8E5B1A7F3C90` |
| Android | Emulator serial | `device.address` | `emulator-5556` |

<Aside type="caution">
Always name your device by this id. Other agents' devices run alongside yours, so `booted` in a `simctl` command, or an `adb` command without `-s`, can reach a device that isn't yours.
</Aside>

## Install and launch an app

<Tabs syncKey="platform">
  <TabItem label="iOS">

```sh
UDID=6F1D2A8C-3B4E-4F7A-9C2D-8E5B1A7F3C90
simlock simctl install "$UDID" ./build/Debug-iphonesimulator/MyApp.app
simlock simctl launch "$UDID" com.example.myapp
simlock simctl io "$UDID" screenshot home.png
```

  </TabItem>
  <TabItem label="Android">

```sh
SERIAL=emulator-5556
simlock adb -s "$SERIAL" install app/build/outputs/apk/debug/app-debug.apk
simlock adb -s "$SERIAL" shell am start -n com.example.myapp/.MainActivity
simlock adb -s "$SERIAL" exec-out screencap -p > home.png
```

  </TabItem>
</Tabs>

`simlock adb -s "$SERIAL" shell` with no command opens an interactive shell.

## Let other tools reach the device

When a build tool or test runner calls `xcrun simctl` or `adb` itself, give it the lease's environment. Every grant has an `environment` object:

| Variable | When it is set | What it is |
| --- | --- | --- |
| `SIMLOCK_IOS_DEVICE_SET` | iOS simulator, unless `drivers.ios.deviceSet` is `default` | Folder of Simlock's simulators, for `simctl --set` |
| `ANDROID_ADB_SERVER_PORT` | Android | Port of the adb server that sees the device. `adb` reads it by itself. |
| `SIMLOCK_DEVICE_UDID` | Physical iPhone or iPad | The device's UDID |
| `ANDROID_SERIAL` | Physical Android phone | The phone's serial. `adb` reads it by itself. |

`--export-env` prints these as shell `export` lines instead of the JSON grant, ready for `eval`:

```sh
eval "$(simlock lease --platform android --device "Pixel 8" --detach --export-env)"
adb -s emulator-5556 shell getprop ro.build.version.release
```

With `--export-env`, stdout holds only the export lines. Find the lease id afterwards with `simlock status`, so you can renew and release it.

`simctl` doesn't read any variable for its device set, so pass the folder yourself:

```sh
xcrun simctl --set "$SIMLOCK_IOS_DEVICE_SET" list devices
```

When `drivers.ios.deviceSet` is `default`, there is no such variable, and a plain `xcrun simctl list devices` lists your simulator.

The paths and ports in `environment` only work on the machine that owns the device. They are no use on another machine, for example when you lease through a gateway.

## Run commands through a gateway

When you lease through a gateway (`simlock --gateway ...`), the device is on a worker. `simlock simctl` and `simlock adb` run your command on that worker and stream the output back:

```sh
simlock --gateway simctl --lease 3f81a2c4-9b7d-4e21-8a55-1c0e6f2d7b93.lse_9f2c6a1d listapps 6F1D2A8C-3B4E-4F7A-9C2D-8E5B1A7F3C90
```

- `--lease <lease-id>` says which lease the command runs under. Put it right after `simctl` or `adb`. You can leave it out when you hold exactly one lease. Without a gateway, it is accepted and ignored.
- File paths in the arguments are paths on the worker, not on your machine. `simctl install` needs the app to be on the worker already.
- Commands that need a terminal, such as a bare `adb shell`, are refused. Input you pipe to the command is sent once.

<Aside type="caution" title="Right after a worker restarts">
For up to about a minute after a worker restarts, a command without `--lease` can fail with `No lease is held by <your id>`, even though your lease still stands. Don't request a new device on that message. Wait a minute and run the command again, or pass `--lease <lease-id>`: then the command waits for the worker to finish starting and runs.
</Aside>

## Commands Simlock refuses

Some commands would break a device behind Simlock's back, or hit every agent at once. `simlock simctl` and `simlock adb` refuse them with exit 2 and a message that says what to run instead:

| Tool | Refused | Why |
| --- | --- | --- |
| simctl | `create`, `erase`, `delete` | Simlock creates and deletes devices itself. |
| simctl | `shutdown all` | Stops every agent's device. `shutdown <udid>` on your own device is allowed. |
| simctl | `runtime delete` | Deletes an OS version other devices use. |
| simctl | `--set` or `--profiles` before the subcommand | Simlock chooses where simulators live. |
| adb | `kill-server` | Disconnects every leased emulator. |
| adb | `disconnect`, with or without an address | Drops other leases' emulators. (`adb shell echo disconnect` still runs.) |
| adb | `emu kill`, `emu avd stop` | Stops a device Simlock thinks is running. |
| adb | `emu avd snapshot`, except `list` | Can replace or delete the snapshot Simlock starts the device from. |
| adb | any option before the subcommand except `-s`, `-t`, `-d`, `-e` | `-P`, `-H`, `-L` and others would point adb at another server. |

```json
{"error":{"code":"USAGE","message":"Refusing `simlock simctl erase`: it changes a device's lifecycle behind Simlock's registry, which would report the device as drifted on the next reconcile. Use `simlock release` (which deletes the device for you) or `simlock cleanup` instead."}}
```

To get a clean device, release the lease and request a new one. Every lease starts on a new simulator or emulator.

## Rules for agents

Give your agent these rules. Simlock keeps devices apart from careless tools; it doesn't stop an agent that sets out to reach another device.

- **Use only the device your lease names.** Name it by its UDID or serial in every command. Never use `booted`, or an `adb` command without `-s`, when other agents may be running.
- **Never erase, delete, create or shut down devices yourself.** Release the lease instead. Simlock deletes the device and gives the next agent a new one.
- **Never stop or restart the adb server, and never point `adb` or `simctl` at another server or simulator folder.**
- **Release the lease when you are done.** A lease nobody releases holds the device until its TTL runs out, while other agents wait.
- **Don't rely on anything surviving a release.** Apps, files, settings and logs go with the device.

<Aside>
Physical devices aren't kept apart at all: every tool on the machine sees them. See [Physical devices](/simlock/docs/using-devices/physical-devices).
</Aside>
