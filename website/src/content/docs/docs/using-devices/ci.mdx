A CI job can run a mobile test suite on a Simlock farm without a Mac or an emulator on the runner. The job holds a farm URL and an agent token, leases one device per test worker, installs the app on it, runs the tests, and gives the devices back.

This page uses the [`e2e` runner](https://www.npmjs.com/package/@e2e-dev/mobile) (`@e2e-dev/mobile`) and the `@simlock/e2e` device provider as the worked example. For any other runner, see [Other runners](#other-runners).

## Before you start

- A farm: a [gateway](/simlock/docs/gateway/routing) or a worker whose HTTP API the CI runner can reach, over HTTPS (see [Remote agents](/simlock/docs/using-devices/remote-agents)).
- The [agent-device module](/simlock/docs/using-devices/agent-device) on, on the farm. The provider talks to its address, `<url>/v1/agent-device`.
- A project that already runs with `@e2e-dev/mobile`.

## Make a token and store it as a CI secret

<Steps>

1. **Create an agent token** on the worker, or on the gateway for a fleet:

   ```sh
   simlock token create --role agent --label ci-runner-3
   ```

   The secret is shown once. See [Get an agent token](/simlock/docs/using-devices/remote-agents#get-an-agent-token).

2. **Store the secret and the farm URL** as secrets of your CI system, as `SIMLOCK_TOKEN` and `SIMLOCK_URL`. Pass them to the job as environment variables. Never put the token in a file in the repository.

3. **Raise the token's lease limit.** A token holds one lease at a time by default, and a run with `workers: 4` holds four. Ask the operator to raise `lease.maxPerRequester` to at least the number of workers (see [Configuration reference](/simlock/docs/reference/configuration)).

</Steps>

## Run simlock commands from a job

A job that is not an `e2e` run can use the `simlock` commands with the same two secrets, from a machine with no daemon. Set `SIMLOCK_AGENT_ID` to a value that is the same for every step of the job, such as the job id, so `simlock adb` and `simlock simctl` find the lease the job took:

```sh
export SIMLOCK_AGENT_ID="$CI_JOB_ID"
simlock lease --platform android --detach
simlock adb shell getprop ro.build.version.release
```

See [Use the CLI](/simlock/docs/using-devices/remote-agents#use-the-cli).

## Install the provider

```sh
npm install --save-dev @simlock/e2e agent-device
```

`agent-device` is a peer dependency, at version 0.21.37 or newer: the provider uses your own copy of its client. `@e2e-dev/mobile` 0.12.5 or newer is the other peer dependency. The package has the same version number as the Simlock release it was built and tested with, so use the version that matches your farm.

## Configure the runner

```ts
// e2e.config.ts
import { mobile } from "@e2e-dev/mobile";
import { simlockDevices } from "@simlock/e2e";

export default {
  targets: [
    {
      name: "ios",
      engine: mobile({
        platform: "ios",
        device: simlockDevices({
          url: process.env.SIMLOCK_URL!,
          token: process.env.SIMLOCK_TOKEN!,
          platform: "ios",
          device: "iPhone 17 Pro",
        }),
      }),
      app: { bundleId: "com.example.app", appPath: "build/Example.app" },
    },
  ],
  workers: 4,
};
```

Each worker gets its own device from the farm. The provider uploads the build named by `appPath` and installs it, then installs each of `extraApps`. A target with no `appPath` gets only the `extraApps`.

## Options

`simlockDevices(options)` checks every option when the config loads. A bad value throws at once with the option's name, and so does an option the provider does not know.

| Option | Default | Meaning |
| --- | --- | --- |
| `url` | required | The farm: an `http://` or `https://` URL of the gateway or worker, without `/v1`. A trailing slash is dropped. |
| `token` | required | An agent token. |
| `platform` | required | `"ios"` or `"android"`. It must match the target's platform. |
| `device` | required | A device model the farm lists, such as `iPhone 17 Pro`. See [Choose a device](/simlock/docs/using-devices/choosing-a-device). |
| `osVersion` | the farm's choice | An OS version or range. |
| `imageTag` | the farm's choice | An Android system image tag, such as `google_apis_playstore`. |
| `deviceMode` | the farm's default | `"slim"` or `"full"`, for iOS. See [Choose slim or full iOS](/simlock/docs/using-devices/choosing-a-device#choose-slim-or-full-ios). |
| `deviceBaseline` | none | The name of a saved baseline to start from. |
| `extraApps` | `[]` | Paths of more apps (`.app`, `.apk`) to install on every device, after the app under test. |
| `ttlMs` | `180000` | The lease time in milliseconds, at least `30000`. The provider renews each lease every third of it. |
| `queueMs` | `1200000` | How long a worker waits for a free device, in milliseconds. |
| `installConcurrency` | `3` | How many app installs run at once from this machine. |

The provider sends `deviceMode` and `deviceBaseline` only when you set them, and they need an agent-device client that sends them (0.21.37 or newer).

## Workers and the size of the farm

The runner asks for one device per worker, all at once. A farm with room for two iOS devices serves `workers: 4` two at a time: the other two workers wait for a device (see [A full farm](#a-full-farm)). Set `workers` to the number of devices you want to hold for the run, and make sure the farm and the token's `lease.maxPerRequester` allow at least that many.

## A full farm

When no device is free, the provider does not fail. It asks again every 10 to 15 seconds, with a new lease id each time, and logs `simlock: no free ios device on the farm; waiting for one` once. A worker waits up to `queueMs`, 20 minutes by default. After that the run fails with `simlock: no free ios device on the farm within 20 min`.

A request that the farm refuses at once, such as one with a bad token, fails the run without waiting. See [Error reasons](/simlock/docs/using-devices/agent-device#error-reasons).

## A device that cannot be set up

If the install on a device fails, the provider gives that device back and leases one other, once. A second failure fails the run with `simlock: could not set up a device after 2 tries: <message>`. An upload that was cut, or an answer saying a retry may work, sends the install again to the same device, up to three tries, and does not swap the device.

## Releases and killed jobs

When the run ends, fails or is interrupted, the runner calls the provider, which gives every device back at once. Closing a test session does not release a device; only the provider's release does.

While the run lives, the provider renews each lease every third of `ttlMs`. A job that is killed cannot release or renew, so its leases run out by themselves within `ttlMs`: 3 minutes by default. Other jobs wait that long on a full farm. Keep `ttlMs` short for that reason, and no shorter than `30000`.

If the farm ends a lease while the run lives (an operator released it), the provider logs `simlock: lease <id> was ended by the farm; failures on its device are infrastructure, not tests`.

## The proxy time limit on uploads

An app upload is one request. If the CI runner reaches the farm through a proxy or tunnel that cuts long requests, such as Cloudflare at 100 seconds, a large app on a slow link fails to upload. The provider sends a cut upload again up to three times, and then the run fails.

Keep the app small, run the job close to the farm, or reach the farm without a proxy that limits request time. `installConcurrency` limits how many uploads share the link.

## Other runners

The provider is for the `e2e` runner. A Maestro, Detox or Appium job can lease a device with the same calls through the agent-device address or the HTTP API: make a token as above, lease a device, run the tests against it, renew the lease while they run, and release it at the end. A lease you do not renew ends after its TTL.

- [Remote agents over HTTP](/simlock/docs/using-devices/remote-agents) lists the lease, renew and release calls, and how to make a token.
- [agent-device](/simlock/docs/using-devices/agent-device) describes the address `<url>/v1/agent-device`, the 330 second wait, and the error reasons.
