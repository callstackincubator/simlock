`--physical` leases a real phone or tablet plugged into a worker, instead of a simulator or emulator. The lease works the same way otherwise: it has a TTL, you renew it, and you release it.

```sh
simlock lease --platform ios --physical --device "iPhone 15"
```

<Aside type="danger">
When a physical lease ends, Simlock uninstalls every app that wasn't on the device when it was enrolled. Don't lease a device that holds an app you want to keep, unless that app was on it at enrolment. See [What is removed when the lease ends](#what-is-removed-when-the-lease-ends).
</Aside>

## Before you start

- **The device is enrolled.** An admin enrols it on the worker it is plugged into. Simlock never leases a device that isn't enrolled. See [Enrolling physical devices](/simlock/docs/worker/enrolling-physical-devices).
- **The device is ready to use.** It is plugged in by USB, trusted, and usable when the lease is granted. A device that isn't is skipped, and your request waits for it.
- **An iPhone or iPad is unlocked.** One that asks for its passcode counts as not there.

## See which devices are enrolled

`simlock status` lists the enrolled devices. One that can't be used shows as `absent`, with the reason: `locked`, `untrusted` or `not-present`.

An agent can find them too:

- **Over MCP**, `list_devices` returns them as `physicalDevices`.
- **Over HTTP**, read `GET /v1/status` and keep the devices with `physical: true` and a state other than `deleted` (a removed phone stays in the answer). Through a gateway, also keep only those on a worker that is connected and not drained.

Neither says who holds a leased phone, and the list can be out of date a moment later. Whether you get a device is decided when you lease.

## Ask for a device

Your request matches an enrolled device of that platform:

- **`--device`** matches the model name, in any letter case.
- **`--class`** is `phone` or `tablet`. An iPad is a `tablet`; every Android device is a `phone`. With neither `--device` nor `--class`, you get a `phone`.
- **`--os`** matches exactly. `--os 18` doesn't match a device on 18.4.1; for any 18.x, write `--os ">=18 <19"`. On Android, the OS is the API level, such as `--os 34`.

`--mode`, `--image-tag` and `--allow-download` don't apply to physical devices. Passing any of them with `--physical` fails with `BAD_REQUEST` (exit 2). A lease without `--physical` never gets a physical device.

The grant is the same JSON line as for a simulator, with `device.physical` set to `true`, a `device.class`, and no `device.mode`.

## When no device fits or all are busy

| Situation | What happens |
| --- | --- |
| No enrolled device could ever match | Fails at once with `UNKNOWN_MODEL` (exit 12). It never waits. |
| A device matches, but it is leased, being cleaned, or absent | Your request waits for it. |
| Same, with `--no-wait` | Fails at once with `NO_CAPACITY` (exit 11). |

```json
{"error":{"code":"UNKNOWN_MODEL","message":"no enrolled physical device can match ios model iPhone 15 os 18; --os is exact, for any 18.x write --os \">=18 <19\""}}
```

Physical requests have their own queue. A simulator request never waits behind a physical one, and a request for one phone model never waits behind a request for another.

## Use the device

`simlock simctl` and `simlock adb` only reach simulators and emulators. For a physical device, use the platform's own tools with the values from the grant's `environment`.

<Tabs syncKey="platform">
  <TabItem label="iPhone and iPad">

The `environment` holds `SIMLOCK_DEVICE_UDID`. Pass it to `devicectl`:

```sh
eval "$(simlock lease --platform ios --physical --device "iPhone 15" --detach --export-env)"
xcrun devicectl device install app --device "$SIMLOCK_DEVICE_UDID" ./build/Debug-iphoneos/MyApp.app
xcrun devicectl device process launch --device "$SIMLOCK_DEVICE_UDID" com.example.myapp
```

  </TabItem>
  <TabItem label="Android">

The `environment` holds `ANDROID_SERIAL` and `ANDROID_ADB_SERVER_PORT=5037`. Plain `adb` reads both, so it reaches your phone and never one of Simlock's emulators:

```sh
eval "$(simlock lease --platform android --physical --detach --export-env)"
adb install app/build/outputs/apk/debug/app-debug.apk
adb shell am start -n com.example.myapp/.MainActivity
```

  </TabItem>
</Tabs>

From another machine, run commands through `exec` over HTTP: `devicectl` for an iPhone or iPad, `adb` for an Android phone. Simlock adds the device to the command for you. See [Remote agents](/simlock/docs/using-devices/remote-agents).

<Aside type="caution">
Physical devices aren't kept apart from the rest of the machine the way simulators are. Every tool on the worker sees them, so an agent can reach a phone it didn't lease. Tell agents to use only the device their lease names.
</Aside>

## What is removed when the lease ends

When a physical lease is released or expires, Simlock uninstalls every app it can see that wasn't on the device when it was enrolled:

- On iOS, apps installed by Xcode or `devicectl`.
- On Android, user-installed apps.

It does **not**:

- touch App Store or TestFlight apps on iOS;
- reset settings, files, accounts or keychain items;
- clear the data of an app that was there at enrolment;
- reinstall an app from enrolment that has gone missing. It is reported, not put back.

To keep an app you installed on purpose, ask an admin to run `simlock device add` for the device again, so the app is added to its list.

If the cleanup fails while the device is plugged in, the device is set aside and retried later. It can't be leased until then.

A physical lease survives a daemon restart.

## When the device is unplugged

A device that has been missing for about a minute becomes `absent`. A locked iPhone counts as missing. A lease on an absent device ends: a held `simlock lease` prints a `lease-lost` line with reason `device-lost` and exits with code 14.

When the device is back, Simlock cleans it and it can be leased again. A request waiting for it is granted then.

- To watch a physical device's screen in the console, see [Watching the screen](/simlock/docs/using-devices/watching-the-screen). A physical iPhone needs iOS 27 or later.
