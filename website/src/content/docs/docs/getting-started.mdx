Simlock leases iOS simulators and Android emulators to your coding agents, one device each. Start on one machine; add more behind a gateway when one is not enough.

## Requirements

- Node.js, for the `simlock` CLI.
- **iOS** (macOS only): Xcode, installed and selected, with its license accepted and its first-launch setup done.
- **Android** (macOS or Linux): an Android SDK with the command-line tools, the `emulator` and `platform-tools` packages, and a JDK with `JAVA_HOME` set.

A platform whose tools are missing is unavailable. `simlock doctor` names what is missing and how to install it. The full list is in [Prerequisites](/simlock/docs/cli#prerequisites).

## Lease a device

<Steps>

1. Install the CLI:

   ```sh
   npm i -g simlock
   ```

2. Ask for a device. The daemon starts on demand, so there is no setup step:

   ```sh
   simlock lease --platform ios --device "iPhone 16"
   ```

   The lease result is one JSON line on stdout, and progress (queueing, provisioning, boot) streams as JSON lines on stderr. `simlock lease` stays running, renewing the lease on a timer and releasing it when it exits. Add `--detach` to get the lease and renew it yourself.

3. Use the device through Simlock's passthrough, which sees the devices Simlock manages:

   ```sh
   simlock simctl install booted ./MyApp.app
   ```

4. Release it, or let the TTL run out:

   ```sh
   simlock release --all
   ```

</Steps>

## Give it to your agent

<Tabs syncKey="way-in">
  <TabItem label="CLI">

Tell the agent to lease a device with `simlock lease` and to use only devices a lease hands it. Under Claude Code and Codex, the CLI takes the agent's identity from its session, so each session gets its own lease.

```sh
simlock lease --platform android
```

  </TabItem>
  <TabItem label="MCP">

`simlock mcp` is a local stdio MCP server with four tools: `list_devices`, `lease_simulator`, `release_simulator` and `lease_status`. It renews its session's lease itself.

```json title=".mcp.json"
{
  "mcpServers": {
    "simlock": {
      "command": "simlock",
      "args": ["mcp"],
      "env": { "SIMLOCK_AGENT_ID": "agent-1" }
    }
  }
}
```

Under Claude Code the server takes the session's id with no setup. Under other clients, give each agent session its own `SIMLOCK_AGENT_ID`.

  </TabItem>
  <TabItem label="Client">

`simlock/client` is the typed client the CLI and the MCP server are built on.

```ts
import { connectSimlock } from 'simlock/client';

const client = await connectSimlock({ principal: 'agent-1' });
const grant = await client.requestLease({ platform: 'ios', model: 'iPhone 17 Pro' });

await client.releaseLease({ leaseId: grant.lease.id });
await client.close();
```

  </TabItem>
</Tabs>

## Grow into a fleet

A **gateway** is a Simlock daemon that owns no devices and fronts the **workers** that join it. Workers dial out to the gateway, so a machine behind NAT joins without an inbound port. Agents and the console point at one URL.

<Steps>

1. On the gateway machine, turn on the gateway and its HTTP API, and mint a join token:

   ```sh
   simlock config set mode gateway
   simlock config set http.enabled true
   simlock token create --role worker
   ```

2. On each worker, a Mac or a Linux machine, point it at the gateway:

   ```sh
   simlock config set gateway.url wss://gw.example:4700
   simlock config set gateway.token slk_...
   ```

3. Mint a token for each agent with `simlock token create --role agent`, and lease over HTTP:

   ```sh
   curl -X POST https://gw.example/v1/lease-requests \
     -H "Authorization: Bearer $SIMLOCK_TOKEN" \
     -d '{"platform":"ios","device":"iPhone 17 Pro"}'
   ```

</Steps>

The HTTP listener binds to `127.0.0.1` by default. Reaching it from other machines goes through your own tunnel or reverse proxy, since Simlock does no TLS termination. See [Modes: gateway and worker](/simlock/docs/configuration#modes-gateway-and-worker) and the [HTTP API](/simlock/docs/http-api).
