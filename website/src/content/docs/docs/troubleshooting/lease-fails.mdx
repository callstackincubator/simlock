Find what you see below. Each table gives the cause and the fix. Every code with its exit code and HTTP status: [Errors and exit codes](/simlock/docs/reference/errors).

## Read the error

A failed `simlock` command prints one JSON line on stderr and exits with a code that says what kind of failure it was:

```json
{"error":{"code":"QUEUE_TIMEOUT","message":"Timed out waiting for a device: req_7d1a0c4e-2b9f-4e63-8a15-c3f0d6b8e241"}}
```

- In a script, check the exit code or `code`, never the message: the message is for people and can change.
- The HTTP API returns the same codes inside `{"error":{"code":...,"message":...}}`, and the Node client throws them as a `SimlockError`.
- Exit `2` means the command was wrong: running it again unchanged will not help. Exit `10` means it ran out of time, `11` that nothing is free now: retry later.

## The lease waits and never starts

`simlock lease` prints `queued` progress and stays there. Without `--timeout`, it waits until a device frees up, however long that takes. How the queue works: [Queue and capacity](/simlock/docs/concepts/queue-and-capacity).

| Error | Exit | Cause | Fix |
| --- | --- | --- | --- |
| (no error, still waiting) | | Every device that fits is in use, or one is booting for you. | Wait, or ask the worker's operator. They can see why with `simlock list --requests`: see [A lease waits and never starts](/simlock/docs/troubleshooting/worker#a-lease-waits-and-never-starts). |
| `QUEUE_TIMEOUT` | 10 | The request waited longer than `--timeout` and got no device. | Retry later, with a longer `--timeout`, or ask for more kinds of device, such as `--class phone` or an `--os` range. |
| `NO_CAPACITY` | 11 | Nothing is free and you passed `--no-wait`. Through a gateway: no worker takes requests at all, for example every worker is drained or disconnected. | Drop `--no-wait` to queue. Over HTTP, wait for the `Retry-After` seconds. Through a gateway, ask an operator which workers are up. |
| `DAEMON_UPDATING` | 1 | The worker is updating Simlock and takes no new leases until its leases end. | Retry after the update. |

## You already hold a lease

The request was refused before it queued.

| Error | Exit | Cause | Fix |
| --- | --- | --- | --- |
| `REQUESTER_ALREADY_LEASED` | 13 | Your requester id already holds or waits for its limit of leases, or, with a limit per platform, has a request waiting on that platform. The message names the lease. | Keep using that lease, or release it with `simlock release <lease-id>`. If two agents collide, give each its own identity. See [Use several devices at once](/simlock/docs/using-devices/several-devices). |
| `LEASE_ID_TAKEN` | 13 | The `--lease-id` you chose belongs to an active lease or a waiting request. | Use a new, unique id. |
| `LEASE_ENDED` | 13 | The `--lease-id` you chose belonged to a lease that ended in the last 24 hours (`lease.endedIdRetentionMs`). The message says when. | Use a new, unique id. |

## The machine cannot give you that device

These fail at once and never wait. Run `simlock catalog` to see what you can ask for. How to ask for a model, OS or image: [Lease a specific model or OS](/simlock/docs/using-devices/lease-a-specific-device).

| Error | Exit | Cause | Fix |
| --- | --- | --- | --- |
| `UNKNOWN_MODEL` | 12 | The machine does not know the model, or has no model for the class. Also when `ios.virtualDevices` or `android.virtualDevices` is `false` and you did not pass `--physical`, or with `--physical` no enrolled device could ever match. | Check the spelling against `simlock catalog`. On a phones-only worker the message names the key: ask again with `--physical`. With `--physical`, `--os` is exact. An operator can name a model for a class in `ios.defaultModels` or `android.defaultModels`. |
| `RUNTIME_MISSING` | 12 | The OS version or Android image is not installed. An OS range or `--image-tag` never downloads. | Pick an installed version from `simlock catalog`, pass `--allow-download` for an exact version, or ask an operator to install it. |
| `MODE_UNAVAILABLE` | 12 | The worker serves only some iOS modes (`ios.modes`) and the lease needs another: you asked for it, a baseline is that mode, or iOS below 18.5 cannot be slim and the worker has no full mode. | Ask for the mode the message names (`--mode slim` or `--mode full`). For an older iOS, ask for 18.5 or newer. |
| `NO_DRIVER` | 12 | The platform is not available: its tools are missing, or no worker in the fleet has it. | Ask for the other platform, or ask an operator to run `simlock doctor`. |
| `CAPABILITY_MISSING` | 12 | No worker that could serve the request has a feature it needs on, such as agent-device. | Ask an operator to turn the feature on for a worker. |
| `UNKNOWN_BASELINE` | 12 | `--baseline` names a baseline this machine does not have. | Check the name with `simlock baseline list`. |
| `BASELINE_MISMATCH` | 2 | `--baseline` came with a platform, model, OS, mode or image tag that differs from the baseline. The message names the first that differs. | Drop that option: the baseline decides it. |
| `BASELINE_STALE` | 12 | The OS or image the baseline was saved on has been removed, or an iOS baseline was saved by an older Simlock that shared folders between simulators. | Ask an operator to install it again, or save the baseline again. |
| `LICENSE_NOT_ACCEPTED` | 12 | An Android download needs the SDK licences, and this machine has not accepted them. | An operator accepts them. See [Accept the Android SDK licences](/simlock/docs/worker/runtimes-and-images#accept-the-android-sdk-licences). |
| `INSUFFICIENT_DISK_SPACE` | 12 | The download does not fit on the disk. The message says how much is needed and free. | Ask for an installed version, or an operator frees disk. |
| `DOWNLOAD_TIMEOUT` | 10 | The download, waiting behind another one included, took longer than the machine allows. | Retry; the download may be further along. Or ask an operator to install the runtime. |

## The gateway refused the request

| Error | Exit | Cause | Fix |
| --- | --- | --- | --- |
| `ADMISSION_DENIED` | 16 | The gateway's admission policy refused the request. The message ends with the policy's reason. | Read the reason; it is the operator's policy. Do not retry unchanged. |
| `ADMISSION_FAILED` | 16 | The admission policy could not decide, so the gateway refused the request. The message says why. | Tell the gateway's operator. The same request can pass once the policy is fixed. |

A gateway also fails a request at once when no connected worker could serve it, with the code one worker would give, such as `NO_CAPACITY` or `RUNTIME_MISSING`. See [Workers and gateways](/simlock/docs/concepts/workers-and-gateways).

## The device does not start

| Error | Exit | Cause | Fix |
| --- | --- | --- | --- |
| `PROVISION_FAILED` | 1 | Simlock could not create or start the device. The message carries the tool's error. Through a gateway: every worker that tried failed. | Retry once. If it keeps failing, ask an operator to check `simlock doctor` and `simlock daemon logs`. See [A device will not boot or reset](/simlock/docs/troubleshooting/worker#a-device-will-not-boot-or-reset). |

## You lost the lease

How a lease ends: [Leases and requesters](/simlock/docs/concepts/leases).

| Error | Exit | Cause | Fix |
| --- | --- | --- | --- |
| `lease-lost` line | 14 | A held `simlock lease` lost its lease: it expired, an operator ended it, or the device was lost. | Stop using the device and request a new lease. |
| `UNKNOWN_LEASE` | 1 | The lease id does not exist, or the lease has ended. Over HTTP: `404`. | Request a new lease. Check your ids with `simlock status`. |
| `FORBIDDEN` | 1 | The lease or request belongs to someone else, or the command needs the admin role. Over HTTP: `403`. | Use your own lease. Run admin commands on the daemon's machine as the user that runs it, or pass an operator token with `--token`. |
| `WORKER_UNREACHABLE` | 1 | Through a gateway, the worker that holds your device is not connected. | Retry. The lease is yours until it expires. |

## A command on the device fails

How to run commands on a device: [Run simctl or adb on a device](/simlock/docs/using-devices/run-commands).

| Error | Exit | Cause | Fix |
| --- | --- | --- | --- |
| `USAGE` | 2 | `simlock simctl` or `simlock adb` refused a command that would break the device or affect every agent, such as `erase` or `kill-server`. Over HTTP and the Node client the code is `PASSTHROUGH_REFUSED` (`422`). | Do what the message says, usually `simlock release` and lease a clean device. |
| `UNKNOWN_PASSTHROUGH_TOOL` | 2 | `exec` named a tool no platform on that machine has, such as `xcodebuild`. The CLI reports it as `USAGE`. | Use `simctl` or `adb`, or `devicectl` on a physical iPhone or iPad. `simctl` on a physical lease and `devicectl` on a simulator are refused with `PASSTHROUGH_REFUSED`. |
| `EXEC_TIMEOUT` | 10 | The command ran longer than the machine allows (10 minutes by default) and was stopped. | Split the work, or ask an operator to raise `exec.timeoutMs`. |

## The CLI cannot reach the daemon

| Error | Exit | Cause | Fix |
| --- | --- | --- | --- |
| `DAEMON_STARTUP_FAILED` | 1 | The CLI started the daemon and it did not come up. The message says why. | Fix what the message names, then run the command again. See [The daemon will not start](/simlock/docs/troubleshooting/worker#the-daemon-will-not-start). |
| `USAGE` | 2 | A wrong value in `config.json` stops the CLI from starting the daemon. | Fix the key the message names. See [Change a setting](/simlock/docs/worker/change-a-setting#when-a-value-is-refused). |
| `DAEMON_CONNECTION_LOST` | 1 | The daemon stopped or crashed while the command talked to it. A held lease is not released. | Run the command again; the daemon starts on demand. Renew a held lease with `simlock lease renew <lease-id>`. |
| `DAEMON_STOPPING` | 1 | The daemon is shutting down. | Wait a moment and run the command again. |
| `SERVICE_FAILED` | 1 | A start through the login service could not finish. The message names the command and its first error line. | See [Start, stop and update the daemon](/simlock/docs/worker/daemon#when-it-fails). |
| `GATEWAY_NOT_PRESENT` | 2 | You passed `--gateway`, but no gateway has run on this machine. | Drop `--gateway`, or start one with `simlock --gateway daemon start`. |
| `PROTOCOL_VERSION_UNSUPPORTED` | 1 | The CLI and the running daemon are versions that cannot work together. | After an upgrade, restart the daemon: `simlock daemon stop`, then any command. |

If the CLI cannot read the admin credential, it says so on stderr and connects as an agent. Admin-only commands then fail with `FORBIDDEN`.

## Over HTTP

| Status | Code | Cause | Fix |
| --- | --- | --- | --- |
| `401` | `UNAUTHENTICATED` | No token, or a token the daemon does not know. | Check the `Authorization` header. |
| `404` | `UNKNOWN_LEASE_REQUEST` | No such lease request, or it finished more than 10 minutes ago. | Send a new request. |
| `409` | `REQUEST_NOT_CANCELLABLE` | The request can no longer be cancelled: device work has started, or it was granted. | Release the lease instead. |

More HTTP answers: [Lease over the HTTP API](/simlock/docs/using-devices/http-api).
