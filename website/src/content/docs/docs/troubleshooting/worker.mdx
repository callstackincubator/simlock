Find what you see below. Each entry gives the cause and the fix. If nothing matches, start with the log and `simlock doctor`.

## Read the log first

The daemon writes what it does, and every failure, to `daemon.log` in the data folder (`~/.simlock/daemon.log`; a gateway uses `~/.simlock/gateway/daemon.log`). Look at the `error` and `warn` lines near the time of the problem:

```sh
simlock daemon logs | grep -E '"level":"(error|warn)"'
```

```json
{"timestamp":1761037412907,"level":"warn","module":"daemon.events","message":"History read failed; replaying from memory","fields":{"error":"database disk image is malformed","path":"/Users/dana/.simlock/history.db"}}
```

- For more detail, set `log.level` to `debug` and restart the daemon. See [Read the daemon log](/simlock/docs/worker/monitoring#read-the-daemon-log).
- `simlock events --since 1h` shows every lease and device change in the last hour.
- Every CLI error is one JSON line on stderr with a `code` and a `message`; the exit code tells the kind of failure. Every code: [Errors and exit codes](/simlock/docs/reference/errors).

## Check the machine with doctor

```sh
simlock doctor
```

`doctor` checks that the platform tools are installed, and that Simlock's records match the devices that really exist. It prints a JSON report on stdout, `{"findings":[...]}`. Anything you need to act on also prints as one line on stderr:

```text
Missing [android] android-emulator: The Android emulator package is not installed in /Users/dana/Library/Android/sdk. Run `sdkmanager --install emulator`.
Service broken: com.callstack.simlock.worker (launchd) names missing /Users/dana/.nvm/versions/node/v22.13.0/bin/node. Run `simlock daemon install` again.
```

`simlock doctor --fix` makes the fixes that are safe. It never touches a leased device, never installs anything, and never deletes a device Simlock has no record of.

| Finding | What it means | What `--fix` does |
| --- | --- | --- |
| `prerequisite-missing` | A tool a platform needs is missing, such as Xcode, its licence, the Android SDK, the emulator, `adb` or a JDK. The message names it and how to install it. | Nothing. Install it, then [restart the daemon](#a-platform-is-missing). |
| `service-broken` | The login service names a Node or Simlock that is gone, so the daemon will not start at login. The finding carries `manager`, `name`, the `missing` paths and the remedy. | Nothing. Run `simlock daemon install` again. |
| `registry-device-missing` | Simlock has a record of a device that no longer exists, for example one you deleted with `simctl delete`. | Marks the device deleted, unless it is leased. |
| `foreign-state-change` | A device was booted or shut down outside Simlock. | Updates the record to match, unless the device is leased. |
| `expired-live-lease` | A lease ran out but its device is still marked leased. | Ends the lease. |
| `stalled-transition` | A device has been creating or resetting far longer than it should. | Takes the device out of service and retries the reset. |
| `foreign-provenance-change` | A device no longer carries the marks that show Simlock made it, for example after it was erased by hand. | Nothing. Check the device; delete it if it is not yours. |
| `orphan-device` | A device sits in Simlock's device folder with no record. | Nothing. See [Orphaned devices](#orphaned-devices). |
| `orphan-process` | A simulator or emulator runs that Simlock has no record of. | Nothing. |
| `warm-pool-target-unreachable` | A warm pool target can never be filled: its runtime is not installed, its model is unknown, `<platform>.virtualDevices` is `false`, its mode is not in `ios.modes` (`mode-unavailable`), or it asks for more than capacity allows. | Nothing. Fix or remove the target. See [Make leases start faster](/simlock/docs/worker/warm-pool#when-it-fails). |
| `driver-unavailable` | A platform's driver was refused at start, so the platform is off. It carries a `reason` and a `detail` that says what to run, and prints as `Unavailable [<platform>] <reason>: <detail>` on stderr. | Nothing. See [iOS or Android stays off](#ios-or-android-stays-off). |
| `driver-advisory` | A platform tool reported something worth knowing that is not a fault. The code is in the message: [`default-image-tag-not-installed`](#default-image-tag-not-installed), or `adb-protocol-mismatch`, where the running adb is another version than the SDK's and every physical Android phone shows as not present (see [No Android phone is seen](/simlock/docs/worker/enrol-phones#no-android-phone-is-seen)). | Nothing. |
| `module-unavailable` | An optional feature that is on cannot run on this machine. The remedy says why. | Nothing. |
| `module-advisory` | An optional feature works and tells you something worth acting on. It prints as `Warning [<module>] <message> <remedy>`, for example [`fseventsd` using too much memory](#fseventsd-uses-too-much-memory). | Nothing. |
## The daemon will not start

**Symptom.** A command fails with `DAEMON_STARTUP_FAILED`:

```json
{"error":{"code":"DAEMON_STARTUP_FAILED","message":"The daemon could not start: ..."}}
```

| The message says | Cause | Fix |
| --- | --- | --- |
| A key name, such as `lease.defaultTtlMs` with `at most lease.maxTtlMs` (code `USAGE`, exit 2) | The config file is wrong. The CLI checks it before starting the daemon. | Fix the key with `simlock config set`, or edit the file. See [Change a setting](/simlock/docs/worker/change-a-setting#when-a-value-is-refused). |
| `Invalid JSON in config file` | `config.json` is not valid JSON. | Fix the file. |
| A `mode` key | A key left from an older Simlock. | Remove it. |
| `Found ~/.simlock/state.json, which this Simlock no longer reads` | State from an older Simlock. | Follow [From a version that used state.json](/simlock/docs/worker/daemon#from-a-version-that-used-statejson). |
| `state.db is locked by another process` | Another daemon for the same data folder still runs. | Stop it with `simlock daemon stop`, then try again. |
| `another Simlock worker runs for this user` | A worker from another `SIMLOCK_HOME` runs. The message prints the command that stops it. | Run that command. One worker per user. |
| `state.db is damaged (...)` | The state file is damaged. | Move `state.db` somewhere else and start again. Simlock forgets every device and lease it had on record; the devices stay on disk. Then [delete orphans](#orphaned-devices). |
| `... is at version 7; this Simlock knows up to 6` | A newer Simlock wrote the state. | Install the newer version again, or move `state.db` away. |
| `node:sqlite is not available; Simlock needs Node 22.13 or later.` | Node is too old. | Upgrade Node. |
| `Timed out starting simlock daemon` | The daemon did not answer within 20 seconds. | Read `simlock daemon logs` for the line that says why. |
| An error about the HTTP address or port | Another program listens on `http.port`, or `http.host` is not an address of this machine. | Pick another port or address, or stop that program. |

Service problems (`Service: not loaded`, `Service: broken`, `SERVICE_FAILED`): see [Check whether it runs](/simlock/docs/worker/daemon#check-whether-it-runs).

## A platform is missing

**Symptom.** Leases for iOS or Android fail with `NO_DRIVER` (exit 12), or `simlock catalog` does not list the platform.

**Cause.** A tool the platform needs was missing when the daemon started. The daemon looks for tools only when it starts, so installing one later is not enough.

<Steps>

1. Run `simlock doctor` and install what each `Missing` line names.
2. Restart the daemon: `simlock daemon stop`, then `simlock daemon start`.

</Steps>

**Check:** `simlock catalog` lists the platform. If `doctor` says `Every prerequisite is present, but the daemon started without this platform`, only the restart is needed.

## iOS or Android stays off

**Symptom.** `simlock doctor` prints `Unavailable [ios] <reason>: <detail>`.

| Reason | Cause | Fix |
| --- | --- | --- |
| `invalid-device-set` | `drivers.ios.deviceSet` is not `simlock` or `default`; or it is `default` and `drivers.ios.deviceRoot` is set too; or `ios.simulator.headless` is `false` without `drivers.ios.deviceSet` set to `default`. | Fix the keys. See [Watch iOS simulators in a window](/simlock/docs/worker/change-a-setting#watch-ios-simulators-in-a-window). |
| `device-set-changed` | You switched device sets while simulators were left in the old one. | Follow the steps the message lists. See [iOS device sets](/simlock/docs/concepts/ios-device-sets). |
| A folder reason, such as `missing-marker` or `wrong-permissions` | Simlock refused the device folder. | See [Move the device folders](/simlock/docs/worker/free-disk#move-the-device-folders). |

Restart the daemon after a fix.

## A lease waits and never starts

**Symptom.** `simlock lease` prints `queued` progress and stays there.

**Cause.** No device can start for it. A request with no `--timeout` waits until one can, however long that takes.

**Fix.** See why it waits:

```sh
simlock list --requests
```

```text
Request req_3c8e1f52-9a4d-4b7e-8f20-6d1a5c9e3b74: codex:7a1d4e9b-2c3f-4e8a-b6d0-1f5c8a3e9d27, ios iPhone 16 18.4, queued at 2, waiting 312s — full: running limit for iOS
```

| Reason | Cause | Fix |
| --- | --- | --- |
| `full: running limit`, `full: running limit for iOS` | As many devices run as the limit allows. | End leases nobody uses with `simlock release <lease-id>` (find them in `simlock status`), or [raise the limits](/simlock/docs/worker/capacity). |
| `full: device limit` | The worker has as many devices as it may keep. | The same. |
| `full: RAM budget` | Booting another device would go over the RAM budget. | The same, or lower the RAM sizes. |
| `full: host memory pressure` | The host is short of memory and has paused new devices. | Free memory on the host. See [Memory pressure](/simlock/docs/concepts/queue-and-capacity#memory-pressure). |
| `behind an earlier request` | Another request for the same kind came first. | Wait. It starts when the one ahead of it does. |
| `a matching device is starting` | A device is booting for it. A cold boot or a first-time device can take minutes. | Wait. |
| `every matching device is leased or absent` | Every enrolled phone that matches is in use, or unplugged, locked or not trusted. | Free or reconnect a phone. See [An enrolled device shows as absent](/simlock/docs/worker/enrol-phones#an-enrolled-device-shows-as-absent). |

To stop waiting forever, the agent passes `--timeout 5m` (fails with `QUEUE_TIMEOUT`, exit 10) or `--no-wait` (fails at once with `NO_CAPACITY`, exit 11). A request refused with `REQUESTER_ALREADY_LEASED` (exit 13) did not queue: see [A lease fails or never starts](/simlock/docs/troubleshooting/lease-fails).

## A device will not boot or reset

**Symptom.** A lease fails with `PROVISION_FAILED`, or `simlock status` shows a device as `quarantined (purge retry 2, next retry at ...; purge failed: ...)`.

**Cause.** Xcode or the Android tools failed to create, boot or clean up the device. A device Simlock cannot clean up is quarantined: nobody can lease it, and Simlock tries again up to `warmPool.quarantine.maxRetries` times (3 by default). If it still fails, Simlock deletes the device.

<Steps>

1. Read the reason on the status line and in `simlock daemon logs`.
2. Check that the platform tools work on their own: `simlock simctl list devices` or `simlock adb devices`.
3. Run `simlock doctor`. For a `stalled-transition` finding, run `simlock doctor --fix`.
4. If one runtime or system image keeps failing, remove it and install it again. See [Install iOS runtimes and Android images](/simlock/docs/worker/runtimes-and-images).

</Steps>

**Check:** `simlock status` shows no `quarantined` device, and a new lease is granted.

Two Android warnings in the daemon log explain slow or failed boots:

- `Android snapshot boot fell back to a cold boot`: an emulator took more than three times as long as expected to start from its snapshot, so the snapshot is probably damaged.
- `Android device profile source could not be read`: the Android `devices.xml` file exists but could not be read. The `path` and `reason` fields say which file and why.

## An emulator exits at once or hangs on boot

**Symptom.** Android leases fail with `PROVISION_FAILED`: the emulator exits as soon as it starts, or boots until `android.bootTimeoutMs` (5 minutes by default) runs out.

| Cause | Fix |
| --- | --- |
| No hardware acceleration. This is the first thing to check. | Run `emulator -accel-check`. Anything but `... is installed and usable` means acceleration is off. See [Install on Linux](/simlock/docs/getting-started/linux) or [Install on Windows](/simlock/docs/getting-started/windows). |
| The emulator is too old for the options Simlock starts it with. `simlock doctor` reports it. | Run `sdkmanager --install emulator`. |
| An emulator too old to know `-crash-report-mode never`. Simlock passes that option only to an emulator whose `emulator -help` lists it, so a crash dump from an earlier run can open a dialog that holds the boot. | Update the emulator with `sdkmanager --install emulator`. |

## An Android device drops off adb

**Symptom.** An emulator or phone disappears from `simlock adb devices` mid-lease, or an `adb` call fails with `device offline` or `device not found`.

**Cause.** adb lost its connection to the device. Simlock runs its own adb for its emulators, which writes to `logs/adb-server.log` in the data folder. The file starts empty each time that adb starts, and by default does not say why a connection closed.

<Steps>

1. Stop the daemon: `simlock daemon stop`.
2. Start it with adb's trace on: `ADB_TRACE=all simlock daemon start`. `ADB_TRACE=transport,usb` is quieter. The daemon passes it to the adb server it starts.
3. Make the drop happen again, then read `logs/adb-server.log`.
4. Restart the daemon without `ADB_TRACE`. The trace is large.

</Steps>

This does not cover physical phones: they use the machine's normal adb, not Simlock's.

## Android licence not accepted

**Symptom.** A lease or `simlock component install android 35` fails with `LICENSE_NOT_ACCEPTED` (exit 12).

**Fix.** Accept the licences with `sdkmanager --licenses`, or set `downloads.acceptAndroidLicenses` to `true`. See [Accept the Android SDK licences](/simlock/docs/worker/runtimes-and-images#accept-the-android-sdk-licences).

## default-image-tag-not-installed

**Symptom.** `simlock doctor` prints `Warning [android] default-image-tag-not-installed`, and Android leases that name no image tag get the same image as without `android.defaultImageTag`.

**Cause.** No installed system image built for this machine's CPU has the tag the setting names, for example after a typo, or with an image installed only for another CPU. The message lists the tags installed for this CPU, or `none`.

**Fix.** Install an image with that tag, such as `sdkmanager "system-images;android-35;google_apis_playstore;arm64-v8a"` (use your CPU's ABI), or correct `android.defaultImageTag`.

**Check:** `simlock doctor` no longer prints the warning.

## fseventsd uses too much memory

**Symptom.** On a macOS worker, `simlock doctor` prints `Warning [fseventsd] fseventsd uses 28.0 GB of memory, over the 2 GB limit`, and the Mac swaps while leases churn.

**Cause.** Under heavy device churn the macOS service `fseventsd` can grow to tens of GB. It is a macOS bug; Simlock's own processes are fine. Turn the check off with `capabilities.fseventsd.enabled` set to `false`.

See the size yourself:

```sh
top -l 1 -pid "$(pgrep -x fseventsd)" -stats pid,mem,command
```

**Fix.** Restart `fseventsd`; macOS starts it again at once. Simlock does not do this itself, because it needs root.

```sh
sudo killall fseventsd
```

To restart it every hour, install a launchd job. Every restart makes programs that watch files, such as editors and build tools, rescan once an hour.

```sh
sudo tee /Library/LaunchDaemons/local.fseventsd-restart.plist >/dev/null <<'EOF'
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>Label</key><string>local.fseventsd-restart</string>
  <key>ProgramArguments</key>
  <array><string>/usr/bin/killall</string><string>-TERM</string><string>fseventsd</string></array>
  <key>StartInterval</key><integer>3600</integer>
</dict>
</plist>
EOF
sudo chown root:wheel /Library/LaunchDaemons/local.fseventsd-restart.plist
sudo chmod 644 /Library/LaunchDaemons/local.fseventsd-restart.plist
sudo launchctl bootstrap system /Library/LaunchDaemons/local.fseventsd-restart.plist
```

To remove it:

```sh
sudo launchctl bootout system/local.fseventsd-restart
sudo rm /Library/LaunchDaemons/local.fseventsd-restart.plist
```

## The disk is full

**Symptom.** A download fails with `INSUFFICIENT_DISK_SPACE`, such as `Not enough free disk space to install a ios component: needs ~8.5 GiB free, only 3.1 GiB available`, or `simlock events` shows `disk.pressure-detected`.

**Fix.** Run cleanup now, remove runtimes, baselines and orphans you do not need. See [Free disk space and reset a machine](/simlock/docs/worker/free-disk).

## Orphaned devices

**Symptom.** `simlock doctor` reports `orphan-device`, or sources with `orphan: true`.

**Cause.** Devices in Simlock's device folder that it has no record of, left by a daemon that stopped while creating one, or after you moved `state.db` away.

**Fix.** `simlock doctor --purge-orphans`. See [Delete orphaned devices](/simlock/docs/worker/free-disk#delete-orphaned-devices).

## A simulator is left behind by a failed step

**Symptom.** `daemon.log` has a `warn` line such as `could not delete simulator 3F1C9A52-7D44-4B0E-9C2A-5E8B1D6A0F77 left by a failed seed make: <error>`. The step name is `provision`, `baseline save` or `seed make`. The step's own error reaches the caller as usual.

**Cause.** A simulator or baseline step failed, and Simlock could not delete the simulator it had made for it. The line names that simulator by its UDID.

**Fix.** Run `simlock doctor --purge-orphans`. Or delete the UDID in the line by hand. See [Orphaned devices](#orphaned-devices).

## Clipboards cross between simulators

**Symptom.** `simlock doctor` prints `Warning [ios] simulator-app-clipboard-sync`, or a copied value shows up in another lease's simulator.

**Cause.** Under `drivers.ios.deviceSet: default`, Simulator.app was running. It syncs the Mac clipboard into every simulator it shows, and Simlock's DeviceHub setting does not stop that.

**Fix.** Quit Simulator.app, or turn off Simulator > Edit > Automatically Sync Pasteboard. Doctor checks when it runs, so run it again after a Simulator.app opens later.

## The event history is not written

**Symptom.** `simlock status` shows a `History:` line, such as `History: the event history is not being written; see daemon.log.`, or `simlock stats` fails with `HISTORY_UNAVAILABLE`.

| The line says | Cause | Fix |
| --- | --- | --- |
| `not being written`, or `figures could not be rebuilt` | `history.db` could not be opened or written, often because the disk is full. The log line says why. | Fix what the log names, such as [freeing disk](/simlock/docs/worker/free-disk). |
| `was damaged and set aside at ...; a fresh one was started` | Simlock moved the damaged file aside and started a new one. | Nothing. Older events and figures are gone from `events` and `stats`; nothing else is lost. |

`simlock stats` failing with `HISTORY_NOT_KEPT` means the window ends before the oldest figures the worker keeps. Ask for a later window.

## Start over

When the machine is in a state you cannot untangle, `simlock nuke --delete-devices` ends every lease, cancels every waiting request and deletes every device Simlock made. See [Reset a machine with nuke](/simlock/docs/worker/free-disk#reset-a-machine-with-nuke).

<Aside type="danger">
Agents using this machine lose their devices mid-task. Read the nuke section before you run it.
</Aside>
