An event is a fact Simlock records after it happens: a lease was granted, a device booted, a worker
disconnected. Events are for watching and auditing. They never change anything.

## Watch events

All three ways need admin rights: the CLI on the same machine as the daemon, or an operator token
over HTTP.

### From the CLI

```sh
simlock events                 # recent events kept in memory
simlock events --since 2h      # events from the last 2 hours, from the event history
simlock events --follow        # recent events, then new ones as they happen; Ctrl-C to stop
```

Add `--gateway` to watch a gateway: `simlock --gateway events --follow`.

`--since` takes a number and a unit: `ms`, `s`, `m`, `h` or `d` (`90s`, `30m`, `7d`). With
`--since` and no `--follow`, the command reads the history file even when the daemon is not running.

Each line is one event as JSON:

```json
{"id":"evt_4b1e9c2a-7f3d-4e8a-9c61-2d5f0a8b7e14","seq":212,"timestamp":1792575843120,"event":"lease.granted","payload":{"leaseId":"lse_9a3f6c1e-2b7d-4f80-8e15-c4d2a7b96f03","deviceId":"dev_51c8e2a4-0d9b-4e6f-a7c3-8b1f2e5d9a60","requester":"claude-code:6f2e8d14-93a7-4c5b-b0e1-7d4a2c9f8e36","requestId":"req_0e7b4d92-6a1c-4f38-9d25-e8c3b1a7f450","source":"warm","platform":"ios"},"module":"lease-lifecycle"}
```

With `--follow`, each line that arrives live wraps the event in an `event` field next to a
`subscriptionId`.

### Over HTTP

| Request                       | Returns                                                                                       |
| ----------------------------- | --------------------------------------------------------------------------------------------- |
| `GET /v1/events`              | `{"events": [...]}`: the recent events kept in memory.                                        |
| `GET /v1/events?since=2h`     | `{"events": [...]}`: events from the history, same duration format as the CLI.                |
| `GET /v1/events/stream`       | A server-sent event stream. Each message's `event` is the event name and its `data` the event as JSON. |

```sh
curl -N -H "Authorization: Bearer $SIMLOCK_TOKEN" https://simlock-gw.example.com/v1/events/stream
```

### In the console

The **Events** screen lists the last hour and adds new events as they arrive. Filter by Leases,
Devices, Workers, Components or Other. See [Console](/simlock/docs/worker/console).

## What every event carries

| Field       | Meaning                                                                                                    |
| ----------- | ---------------------------------------------------------------------------------------------------------- |
| `id`        | `evt_` and a unique suffix. Names the event for good, across restarts and on a gateway that relays it.     |
| `seq`       | Order number within one daemon run. Starts again at 1 after a restart.                                     |
| `timestamp` | When it happened, in milliseconds since the Unix epoch.                                                    |
| `event`     | The event name from the tables below.                                                                      |
| `payload`   | The fields listed for that event.                                                                          |
| `module`    | The part of Simlock that recorded it.                                                                      |

A payload may gain fields over time. A field list such as `reason` may gain values. Ignore what you
do not know.

## Where events are kept

| Store          | Holds                                                         | Survives a restart | Setting                                               |
| -------------- | ------------------------------------------------------------- | ------------------ | ----------------------------------------------------- |
| Memory         | The most recent events, 1000 by default                        | No                 | `eventBuffer.capacity`                                |
| `history.db`   | Every event, for 7 days by default, up to 256 MiB of events    | Yes                | `eventLog.retention`, `eventLog.maxBytes`             |

`history.db` sits next to the daemon's `config.json`. See
[Configuration](/simlock/docs/reference/configuration#logging-and-history).

## Events on a gateway

A gateway records its own events about the fleet, and relays every event from each connected worker:

- A relayed event keeps the worker's `id`, `timestamp`, name and `module`, and gets `workerId` added to
  its payload. `seq` is the gateway's own.
- A gateway relays only what happens while the worker is connected. Events from before it connected,
  or while it was away, stay on the worker.
- A relayed event's time is the worker's clock, so a worker whose clock is off shows that in the
  gateway's order.
- A gateway writes relayed events to its own `history.db`, so `simlock --gateway events --since`
  covers them.

The **Gateway** column below says what a gateway shows for each event:

- **Relayed**: only from workers, with `workerId`.
- **Own and relayed**: the gateway records it for its own fleet queue (no `workerId`), and also relays
  each worker's (with `workerId`).
- **Own**: recorded by the gateway only. A worker never records it.

## Leases

| Event | When it fires | Payload | Gateway |
| --- | --- | --- | --- |
| `lease.requested` | A lease request was accepted and stored. | `requestId`, `requestSpec` (the request as sent), `requester`, `waitPolicy` (`wait` or `no-wait`), `fleetRequestId` on a worker when the request came from a gateway | Own and relayed |
| `lease.queued` | No device was free, so the request started waiting. | `requestId`, `queuePosition` (counted among requests of the same kind: physical requests wait in a line of their own) | Own and relayed |
| `lease.granted` | A device was handed to a request. | `leaseId`, `deviceId`, `requester`, `requestId`, `source` (`warm`: ready device; `booted`: shut-down device booted; `provisioned`: device created), `platform`, `fleetRequestId` when it served a gateway | Relayed |
| `lease.renewed` | A lease was renewed. | `leaseId`, `newDeadline` | Relayed |
| `lease.released` | A lease ended because someone or something ended it. | `leaseId`, `deviceId`, `reason` (`explicit`: released; `killed`: `release --all` or `nuke`; `device-lost`: the device crashed and could not be brought back, or a physical device went away), `ownerId` | Relayed |
| `lease.expired` | A lease reached its deadline without a renew. | `leaseId`, `deviceId`, `ownerId` | Relayed |
| `lease.rejected` | A request ended without a device. A worker records it only for its own requests. | `requestId`, `requester`, `requestSpec`, `reason` (`timeout`, `no-wait`, `unresolvable-spec`, `no-worker`, `already-leased`, `lease-id-taken`, `boot-timeout`, `killed`, `cancelled`, `daemon-restarted`, `worker-failed`), and on `worker-failed` the error `code` and the `worker` | Own and relayed |
| `lease.declined` | A worker refused or failed a request a gateway sent it. The gateway may try another worker. | `requestId`, `fleetRequestId`, `requester`, `requestSpec`, `reason` (the `lease.rejected` values) | Relayed |
| `request.granted` | The gateway handed a worker's grant to the caller. | `requestId`, `worker`, `leaseId` (the gateway's), `workerLeaseId` | Own |
| `request.dispatched` | The gateway sent a queued request to a worker and the worker took it. | `requestId`, `workerId`, `requesterId`, `platform`, `model` or `class` when named, `mode` when named, `physical` for a physical request, `reason` (`warm-hit` or `free-capacity`), `stage`, `queuedMs` | Own |

A request refused before it was stored (`killed`, `already-leased`, `lease-id-taken`) has a
`lease.rejected` and no `lease.requested`. Closing the connection that took a lease is not a
release and records nothing.

## Capacity and queue

| Event | When it fires | Payload | Gateway |
| --- | --- | --- | --- |
| `capacity.changed` | The worker's running figures changed, and once at start. | `ios`, `android`, `global`, each with `running`, `maxRunning`, `reserved`, `warm`; `ramBudget` (`usedBytes`, `limitBytes`) under the `resource` strategy | Relayed |
| `queue.changed` | A request joined or left the queue, and once at start. | `depth` (requests waiting in that line), `physical: true` when the physical line changed | Own and relayed |
| `warm-pool.target-missed` | A `warmPool.targets` entry went short and the pool could do nothing about it. Once per time it goes short. | `platform`, `model`, `osVersion`, `mode`, `count`, `ready`, `reason` (`no-driver`, `runtime-missing`, `unknown-model`, `unresolvable`, `boot-failed`, `device-limit`, `running-limit`, `reserve`, `ram-budget`) | Relayed |

## Devices

| Event | When it fires | Payload | Gateway |
| --- | --- | --- | --- |
| `device.provisioned` | A simulator or emulator was created. | `deviceId`, `spec`, `driver`, `duration` | Relayed |
| `device.ready` | A device finished booting and is ready to use. | `deviceId`, `bootDuration`, `platform` | Relayed |
| `device.slimmed` | A slim iOS simulator came up with its chosen services turned off. | `deviceId`, `address`, `platform`, `categories`, `labelCount`, `durationMs`, `signature`, `unknownLabels` | Relayed |
| `device.reclaimed` | A device was cleaned after a lease and can be leased again. | `deviceId`, `strategy` (`erase`, `snapshot`, `wipe`, `uninstall`), `duration`, `missingApps` for a physical device | Relayed |
| `device.purge-failed` | Cleaning a device after a lease failed. `device.quarantined` follows. | `deviceId`, `leaseId`, `attemptedStrategy`, `duration`, `error` | Relayed |
| `device.quarantined` | A device was set aside: it is not leased and cleanup is retried. | `deviceId`, `maxRetries`, `nextRetryAt`, `platform`, `kind` (`purge-failed`, `shutdown-failed`, `delete-failed`, `stalled`), `stalledState` or `message` | Relayed |
| `device.quarantine-recovered` | A retry cleaned a quarantined device; it is back in use. | `deviceId`, `attempts`, `strategy`, `platform`, `missingApps` for a physical device | Relayed |
| `device.quarantine-abandoned` | A quarantined device ran out of retries and was deleted, or unenrolled if physical. | `deviceId`, `attempts`, `platform` | Relayed |
| `device.quarantine-stranded` | A quarantined device ran out of retries and could not be deleted either. It needs a person. | `deviceId`, `attempts`, `error`, `platform` | Relayed |
| `device.crash-detected` | A leased device stopped running outside Simlock. | `deviceId`, `leaseId`, `platform`, `observed` | Relayed |
| `device.recovered` | A crashed leased device was rebooted and the lease goes on. | `deviceId`, `leaseId`, `attempts`, `duration`, `platform` | Relayed |
| `device.recovery-failed` | A crashed leased device could not be brought back; its lease ends as `device-lost`. | `deviceId`, `leaseId`, `attempts`, `reason`, `error`, `platform` | Relayed |
| `device.shutdown` | A device was shut down and kept on disk. | `deviceId`, `initiator` (who did it, such as `cleanup-reaper`, `warm-pool` or `nuke`) | Relayed |
| `device.deleted` | A device was removed: deleted from disk, or forgotten if physical. | `deviceId`, `initiator` (such as `lease-end`, `cleanup-reaper`, `lease-engine`, `doctor`, `nuke`, `operator`, `quarantine`), `physical` | Relayed |
| `device.enrolled` | `simlock device add` enrolled a physical device. | `deviceId`, `platform`, `driverDeviceId`, `model`, `osVersion`, `class` (`phone` or `tablet`), `appCount`, `reenrolled` | Relayed |
| `device.absence-detected` | An enrolled physical device went away. | `deviceId`, `previousState` (`ready`, `leased`, `reclaiming`), `absentReason` (`locked`, `untrusted`, `not-present`) | Relayed |
| `device.returned` | An absent physical device is back; it is cleaned before its next lease. | `deviceId`, `osVersion` | Relayed |
| `device.stalled-transition-detected` | A device has been creating or cleaning up far longer than expected. | `deviceId`, `platform`, `state` (`provisioning` or `reclaiming`), `ageMs`, `thresholdMs` | Relayed |
| `device.foreign-state-detected` | A check found a device running when Simlock expected it stopped, or the other way round. | `deviceId`, `platform`, `expected`, `observed` | Relayed |
| `device.foreign-provenance-detected` | A check found a device whose marks no longer prove Simlock made it. | `deviceId`, `platform`, `detail` | Relayed |
| `device.orphan-purged` | `simlock doctor --purge-orphans` deleted a device Simlock had no record of. | `driverDeviceId`, `platform`, `deviceRoot` | Relayed |

## Components

| Event | When it fires | Payload | Gateway |
| --- | --- | --- | --- |
| `component.install-started` | A runtime or system image download started. Once per install, however many requests share it. | `platform`, `componentId`, `requesterId` when known | Relayed |
| `component.installed` | An install finished and the component is confirmed present. | `platform`, `componentId`, `version`, `alreadyPresent`, `durationMs`, `requesterId` when known | Relayed |
| `component.install-failed` | An install failed, ran out of `downloads.timeoutMs`, or was cut short by a daemon stop. | `platform`, `componentId`, `durationMs`, `error`, `requesterId` when known | Relayed |
| `component.removed` | `simlock component remove` removed a component. | `platform`, `componentId`, `version`, `sizeBytes` when known, `residue` when something stayed on disk, `requesterId` | Relayed |

## Workers

| Event | When it fires | Payload | Gateway |
| --- | --- | --- | --- |
| `worker.connected` | A worker joined and the gateway can send it requests. | `workerId`, `label`, `version` | Own |
| `worker.disconnected` | A worker's connection closed. | `workerId`, `label`, `leaseCount` (leases it still held) | Own |
| `worker.rejected` | A worker was turned away: `unauthenticated` (missing or unknown join token) or `forbidden` (a token whose role is not `worker`). | `reason`, `workerId` and `label` as the worker claimed them, `count` when several identical refusals were folded into one | Own |
| `worker.removed` | The gateway forgot a disconnected worker. | `workerId`, `label`, `reason` (`operator`: `simlock worker remove`; `retention`: `gateway.disconnectedRetentionMs` passed) | Own |
| `worker.drain-started` | `simlock worker drain` stopped new requests going to a worker. | `workerId`, `label` | Own |
| `worker.drain-ended` | `simlock worker undrain` let requests go to the worker again. | `workerId`, `label` | Own |

A worker whose Simlock version cannot talk to the gateway records no `worker.connected`. It shows
as `incompatible` in `simlock --gateway worker list`.

## Daemon and maintenance

| Event | When it fires | Payload | Gateway |
| --- | --- | --- | --- |
| `daemon.started` | The daemon finished starting. | `version`, `configSnapshot` (tokens, alert URLs and secrets shown as `[redacted]`) | Own (a worker records its own before the gateway starts listening to it, so it is not relayed) |
| `daemon.stopping` | The daemon began to stop. | `reason` | Own and relayed |
| `doctor.reconciled` | Simlock compared its records with the devices on disk (at start and on `simlock doctor`). | `driftFindings` | Relayed |
| `cleanup.executed` | Cleanup shut down or deleted an idle device. | `ruleName` (`idle-shutdown` or `idle-destroy`), `action` (`shutdown` or `destroy`), `target`, `reason` | Relayed |
| `disk.pressure-detected` | Free disk space fell below `diskPressure.freeBytesThreshold`. Once per crossing. | `freeBytes`, `threshold` | Relayed |
| `driver.root-rejected` | A device folder failed its ownership check, so that platform did not start. | `platform`, `root`, `reason` | Relayed |
| `driver.adb-server-rejected` | Simlock's own adb server could not start, so Android did not start. | `port`, `reason` (`occupied`, `start-failed`, `invalid-port`) | Relayed |

<Aside>
Running a command on a device and watching its screen record no event. The daemon log records
each stream.
</Aside>

To have a gateway post some of these events to a webhook, see [Alerts](/simlock/docs/gateway/alerts).
