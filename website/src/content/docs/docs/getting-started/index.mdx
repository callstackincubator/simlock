At the end of this page Simlock is installed and you know which platforms your machine can run.

You need Node.js 22.13 or later, plus Xcode for iOS or the Android SDK for Android. The full list is in [Requirements](/simlock/docs/introduction/requirements).

## For agents

<Aside type="tip" title="For agents">
`setup` checks the machine itself, so there is no separate `simlock doctor` step.

```sh
npm i -g simlock
simlock setup --project --tool claude-code --mcp --json   # or --user, --tool codex, --no-mcp
simlock lease --platform ios --detach                      # prints the lease
simlock release <lease-id>
```
</Aside>

## Install Simlock

<Steps>

1. Install the CLI globally:

   ```sh
   npm i -g simlock
   ```

2. Check that it runs:

   ```sh
   simlock --help
   ```

</Steps>

You do not need to start anything else. Simlock's background process, the daemon, starts by itself the first time a command needs it, and keeps running afterwards. Simlock keeps its data, devices and configuration in `~/.simlock`.

The daemon does not start at login unless you set that up. See [Run the daemon](/simlock/docs/worker/running-the-daemon).

## Check your machine

Run:

```sh
simlock doctor
```

`simlock doctor` checks the tools each platform needs and looks for problems with the devices Simlock manages. It prints a JSON report on stdout, and one line on stderr for each thing you need to fix.

When everything is fine, stderr is empty and the report has no findings:

```json
{"findings":[]}
```

When a tool is missing, doctor says which one and how to get it. On a Mac with Xcode and no Android SDK, it reports Android as missing, and iOS still works:

```text
Missing [android] android-sdk: No Android SDK found; searched: /Users/dana/Library/Android/sdk. Install Android Studio (https://developer.android.com/studio), or the command-line tools (https://developer.android.com/studio#command-line-tools-only), and set ANDROID_HOME to the SDK directory.
```

If you only want iOS, ignore the Android lines.

<Aside type="caution" title="Restart the daemon after you install a tool">
Simlock looks for each platform's tools only when its daemon starts. After you install Xcode, the Android SDK or a JDK, run `simlock daemon stop`, then run `simlock doctor` again. The next command starts the daemon with the new tools.
</Aside>

## Fix what doctor finds

```sh
simlock doctor --fix
```

`--fix` brings Simlock's own records back in line with the machine. For example, it forgets a device that was deleted outside Simlock, and ends a lease whose TTL ran out but is still marked active. It never touches a leased device.

`--fix` does not install Xcode, the Android SDK or a JDK. Install those yourself with the commands doctor prints.

Doctor can also report **orphans**: devices in Simlock's folders that Simlock has no record of, usually left behind when the daemon stopped while creating one. `--fix` leaves them alone. To delete them, run `simlock doctor --purge-orphans`. It asks you to confirm first.

<Aside type="note">
Run `simlock doctor` on a worker. On a gateway it fails with `UNSUPPORTED_IN_GATEWAY_MODE`; run it on each worker instead.
</Aside>
