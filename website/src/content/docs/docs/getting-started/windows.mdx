## Before you start

| You need | For |
| --- | --- |
| Windows 11 and PowerShell | Every command on this page. Written for Windows PowerShell 5.1, the one Windows ships. |
| Node.js 22.13 or later | The `simlock` CLI |
| The Android SDK command-line tools, `emulator` and `platform-tools` | Android emulators |
| A JDK 17 or later | Running `sdkmanager` |
| The Windows Hypervisor Platform, and virtualization on in the PC's firmware | Starting the emulator |
| About 2 GiB free disk per Android system image | Installing an OS |
| One user account on the machine | Simlock's data is not protected from other accounts on Windows. See [The data folder](#the-data-folder). |

Install the tools **before** you run any `simlock` command except `--help`. The daemon looks for them only when it starts.

## 1. Install Simlock

<Steps>

1. Install Node.js with the installer from [nodejs.org](https://nodejs.org/en/download). Open a new PowerShell and check:

   ```powershell
   node --version
   ```

2. Let PowerShell run npm's scripts, for your account only. Under the default policy, Windows refuses them with `npm.ps1 cannot be loaded because running scripts is disabled on this system`:

   ```powershell
   Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
   ```

   To leave the policy as it is, write `npm.cmd` and `simlock.cmd` wherever this site says `npm` and `simlock`.

3. Install Simlock:

   ```powershell
   npm i -g simlock
   simlock --help
   ```

</Steps>

**Check:** `simlock --help` prints the command list.

## 2. Turn on the Windows Hypervisor Platform

The emulator does not start without it. In a PowerShell opened as administrator:

```powershell
Enable-WindowsOptionalFeature -Online -FeatureName HypervisorPlatform
```

Restart when it asks. Virtualization must also be on in the PC's firmware settings (often called Intel VT-x, AMD-V or SVM).

## 3. Set up Android emulators

<Steps>

1. Install the Android SDK. Install [Android Studio](https://developer.android.com/studio), which puts the SDK in `%LOCALAPPDATA%\Android\Sdk`. Simlock looks there when `ANDROID_HOME` and `ANDROID_SDK_ROOT` are not set.

   Without Android Studio: unpack the [command-line tools](https://developer.android.com/studio#command-line-tools-only) so that `sdkmanager.bat` is at `<sdk>\cmdline-tools\latest\bin`, and tell Simlock where the SDK is:

   ```powershell
   [Environment]::SetEnvironmentVariable("ANDROID_HOME", "D:\Android\Sdk", "User")
   ```

2. Add the SDK's tool folders to your `Path`. Neither Android Studio nor the command-line tools do it. Change `$sdk` if your SDK is elsewhere:

   ```powershell
   $sdk = "$env:LOCALAPPDATA\Android\Sdk"
   $tools = "$sdk\cmdline-tools\latest\bin;$sdk\platform-tools;$sdk\emulator"
   $path = [Environment]::GetEnvironmentVariable("Path", "User")
   [Environment]::SetEnvironmentVariable("Path", "$path;$tools", "User")
   ```

3. Install a JDK, for example from [adoptium.net](https://adoptium.net), and point `JAVA_HOME` at its folder. Use the folder name your JDK installed. Open a new PowerShell:

   ```powershell
   [Environment]::SetEnvironmentVariable("JAVA_HOME", "C:\Program Files\Eclipse Adoptium\jdk-17.0.13.11-hotspot", "User")
   ```

4. Install the emulator and platform tools, and accept the Android SDK licences. Simlock cannot install a system image until you do:

   ```powershell
   sdkmanager --install emulator platform-tools
   sdkmanager --licenses
   ```

</Steps>

**Check:** the emulator can use the Hypervisor Platform:

```powershell
emulator -accel-check
```

It prints a line like `WHPX(10.0.22631) is installed and usable.` Anything else means step 2 is not done.

## 4. Check the machine

```powershell
simlock doctor
```

**Check:** stderr is empty and stdout is:

```json
{"findings":[],"sources":[]}
```

Each problem prints one line on stderr with the fix. Run the fix, then `simlock daemon stop`, then `simlock doctor` again: the daemon looks for tools only when it starts. For `android-sdk`, set `ANDROID_HOME` (step 3, item 1); for `android-jdk`, set `JAVA_HOME` (step 3, item 3).

## 5. Install an OS and lease

Doctor does not check for a system image. Install one:

```powershell
simlock component install android 35
```

Then lease an emulator. The first lease on a new data folder also makes the emulator Simlock copies every later one from, and can take four minutes. Later leases are quicker, and a warm one takes seconds.

```powershell
$lease = simlock lease --platform android --detach | ConvertFrom-Json
simlock adb -s $lease.device.address shell getprop ro.build.version.release
```

```text
15
```

`device.address` is the emulator's `adb` serial. Release the lease when you finish:

```powershell
simlock release $lease.lease.id
```

**Check:** the `adb` command printed the Android version.

## Write JSON values in Windows PowerShell 5.1

Windows PowerShell 5.1 drops the `"` inside a single-quoted argument it passes to a program, so a JSON value reaches Simlock without its quotes and is refused. Write each `"` as `\"`:

```powershell
simlock config set gateway '{\"url\":\"wss://gateway.example.com\",\"token\":\"slk_...\",\"label\":\"win-worker\"}'
```

PowerShell 7.3 and later take plain quotes, as the rest of this site shows.

A Windows PC can join a gateway on any system, or run a gateway itself. To join one, set `gateway` as above, in one command (setting `gateway.url` and `gateway.token` one at a time is refused), then restart the daemon with `simlock daemon stop` and `simlock daemon start`. See [Add a worker](/simlock/docs/gateway/add-a-worker).

## The data folder

Simlock keeps its files in `%USERPROFILE%\.simlock`, or in the folder `SIMLOCK_HOME` names:

```powershell
$env:SIMLOCK_HOME = "D:\simlock"
```

The CLI reaches the daemon over a named pipe whose name comes from the data folder's path; there is no `daemon.sock`.

If other users can open the data folder, the daemon log says so at each start, with the `icacls` command that closes it:

```text
data directory D:\simlock is accessible to other users (BUILTIN\Users); run icacls "D:\simlock" /inheritance:r /grant:r "*S-1-5-21-...:(OI)(CI)F" "*S-1-5-18:(OI)(CI)F" "*S-1-5-32-544:(OI)(CI)F"
```

Read the log with `simlock daemon logs` and run the command it prints.

<Aside type="caution">
Run Simlock on Windows only on a machine that one user account uses. The folder's permissions do not protect the named pipe.
</Aside>

<Aside type="note" title="The daemon on Windows">
`simlock daemon install` starts the daemon at login and after a crash, through Task Scheduler. Without it, a daemon started in an SSH session stops when that session ends. See [Start, stop and update the daemon](/simlock/docs/worker/daemon).
</Aside>

## What works on Windows

| Works | Notes |
| --- | --- |
| Android emulator leases | Cold and warm. |
| `simlock adb`, `simlock release`, `simlock nuke`, `simlock update` | `simlock update` needs Simlock installed with `npm i -g simlock`. |
| `simlock component install android <api-level>` | Installs a system image through `sdkmanager`. |
| A gateway, and a Windows worker joined to one | See [Write JSON values](#write-json-values-in-windows-powershell-51). |
| The web console | The worker's and the gateway's. |
| Screen streaming | Watching an emulator's screen in the console, also through a gateway. |
| Tunnels | `simlock tunnel` with `emulator adb`, `forward` and `reverse`. |
| agent-device | Through the worker's local profile. |
| `simlock setup` and `simlock mcp` | The skill file and the MCP server. |
| Start at login | `simlock daemon install` registers a Task Scheduler task. |

| Does not work | What you see |
| --- | --- |
| iOS simulators and iPhones | A lease for iOS fails with `NO_DRIVER` (exit 12). |

| Not checked on Windows | |
| --- | --- |
| Physical Android phones | Nobody has enrolled one on Windows. |
| `simlock cleanup` | Not run on Windows. |
| `simlock setup --mcp` registering Simlock with Claude Code or Codex | The skill file is written; the registration has not been run on Windows. |

## When it fails

| What you see | Cause | Fix |
| --- | --- | --- |
| `npm.ps1 cannot be loaded because running scripts is disabled` | PowerShell's execution policy. | [Step 1](#1-install-simlock), item 2. |
| `emulator -accel-check` does not say `is installed and usable` | The Hypervisor Platform or firmware virtualization is off. | [Step 2](#2-turn-on-the-windows-hypervisor-platform). |
| `LICENSE_NOT_ACCEPTED` on install | The SDK licences are not accepted. | `sdkmanager --licenses`, then install again. |
| `RUNTIME_MISSING` on lease | No system image for that API level. | [Step 5](#5-install-an-os-and-lease). |
| The emulator does not boot | Usually the Hypervisor Platform. | Run `emulator -accel-check`. More: [A worker misbehaves](/simlock/docs/troubleshooting/worker). |
| `another Simlock worker runs for this user` | A second daemon from another `SIMLOCK_HOME`. A machine runs one worker per user. | Stop the first one with the command the message prints. |
