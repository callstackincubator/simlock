The gateway serves the same web console as a worker, with the whole fleet in it: every worker that joined, every lease on those workers, and the fleet queue. This page covers what is different on a gateway. Signing in, finding your way and the parts every page shares are in [Web console](/simlock/docs/worker/console).

From the console you can update a worker; see [Update a worker](/simlock/docs/worker/console#update-a-worker). To drain, undrain or remove a worker, use the CLI; see [Manage workers](/simlock/docs/gateway/managing-workers).

## Open the console

A gateway always serves the console. Open the gateway's address: `https://gateway.example.com` behind a reverse proxy, or `http://127.0.0.1:4700/` on the gateway machine. `simlock --gateway daemon start` and `simlock --gateway status` print it as `Console:`.

Sign in with an operator token made on the gateway:

```sh
simlock --gateway token create --role operator --label alex-laptop
```

A worker's operator token doesn't work on the gateway. To sign people in through your company's sign-in proxy instead, see [Access control](/simlock/docs/gateway/access-control#sign-in-to-the-console-through-a-sign-in-proxy).

## Overview

On a gateway the overview adds up the fleet:

- The **Workers** tile shows how many workers are connected, of all the workers the gateway knows, for example `3` `of 4`.
- **Leased** counts the leases on every worker the gateway knows. It shows `—` until every worker has reported, and **Capacity · all workers** says how many workers have not reported yet.
- The **Workers** panel has one row per worker: its status and name, device slots, CPU, memory, and its lease count. Up to ten slots appear as squares; above ten, a meter shows the leased/total fraction. Slot state counts are available to screen readers. Unavailable load is not shown as zero.

## Fleet

**Fleet** lists every worker the gateway knows, by label, or by id when it has no label. Each row shows how many devices it runs out of its limit. A worker that isn't connected shows `—` instead, since the numbers it last reported may be out of date.

The status shows the worst of the worker's states. Besides the states a single worker can show, a gateway adds:

| Word | Colour | What it means |
| --- | --- | --- |
| `disconnected` | Red | The worker's connection to the gateway closed. The gateway shows what it last reported. |
| `incompatible` | Red | The worker is connected, but its Simlock version cannot talk to the gateway's. It gets no requests. |
| `updating` | Amber | The worker is updating and takes no new leases. Under the word, the row says `waiting for 2 leases`, `installing` or `restarting`. |
| `drained` | Amber | The worker takes no new leases from the gateway. Its leases keep running. |
| `starting` | Amber | The worker is starting up. |

**Issues** narrows the list to workers whose status is not green, and **Busy** to workers using three quarters or more of their device slots.

Select a worker to see its tabs. On a gateway:

- A **disconnected** worker shows "No reading while disconnected" instead of its load, and its devices and capacity as it last reported them.
- An **incompatible** worker shows only **Protocol**, with the version ranges of the gateway and the worker, so you can tell which one to update.
- **Host** shows the connection, `connected`, `disconnected` or `incompatible`, and `drained` beside it when the worker is drained.

A disconnected worker stays in the list for 24 hours by default (`gateway.disconnectedRetentionMs`), and for as long as it holds a lease made through the gateway. Remove one sooner with `simlock --gateway worker remove`.

## Leases

**Leases** lists the leases on every worker, both those made through the gateway and those agents on a worker machine took directly from it. Each lease's **Worker** field names and links the worker that holds it. A lease made through the gateway has an id made of the worker's id, a dot, and the worker's own lease id, unless the agent chose the id.

## Baselines

**Baselines** lists every worker's baselines. On a gateway it adds a **Worker** column that names the worker holding each one.

## Why a request waits

On **Queue**, a request's **Queue** field says where it waits: `the gateway's queue` while the gateway looks for a worker. Under it, the console names each worker and why that worker did not take the request:

| It says | What it means |
| --- | --- |
| Full, or Full: and a limit | The worker has no room under that limit. |
| Busy with its own queue | Requests wait in the worker's own queue, for example from agents on that machine. |
| Not chosen this time | The worker could take it, but the gateway gave that worker to another request first. |
| Drained | The worker is drained. |
| Not connected | The worker is disconnected. |
| Protocol mismatch | The worker is incompatible. |
| Not ready yet | The worker has not finished reporting its devices since it connected. |
| Not running | The worker's daemon isn't healthy. |
| Model not offered | The worker does not offer the model or device class asked for. |
| OS not installed | The worker offers the model, but has no matching OS version installed. |
| No iOS support, No Android support | The worker does not support the platform. |
| Missing capability | The worker lacks an optional capability the request needs. |
| Cannot keep these slim categories | The request names `except` categories the worker does not slim, or the worker would not give a slim device (its default mode is full and the request names no mode, or the baseline is full). |

How the gateway picks a worker is in [How requests are routed](/simlock/docs/gateway/routing).

## Inbox

On a gateway, **Inbox** also lists workers:

| Item | Colour | What to do |
| --- | --- | --- |
| `disconnected` | Red | Check the worker machine and its log with `simlock daemon logs`. When it is gone for good, remove it. |
| `incompatible` | Red | Update the older of the worker and the gateway. |
| `drained` | Amber | Undrain the worker when its maintenance is done. |
| `update failed` | Amber | Select **Update…** to try again, or read the failure's **Stage** and message first. The worker runs its old version. |

A worker that is both disconnected and drained shows as two items, because each clears on its own.

## Usage

On a gateway, **Usage** adds a **Per worker** table: for each worker, the requests, grants, rejections and the 95th-percentile wait in the chosen range. To get a message when something in the fleet goes wrong, see [Alerts](/simlock/docs/gateway/alerts).
