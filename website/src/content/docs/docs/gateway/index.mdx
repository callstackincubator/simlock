---
title: When you need a gateway
description: Decide whether you need a gateway, see how it fits with your worker machines, and know which daemon each simlock command reaches.
---

A gateway puts many worker machines behind one address. Your agents ask the gateway for a device, the gateway picks a worker that can serve the request, and the device runs on that worker.

You need a gateway when one machine is not enough:

- Your agents need more devices than one Mac or Linux machine can run at once.
- Your agents run on several machines, or in CI, and should share one pool of devices.
- You want one place to see every machine, lease and waiting request.

If one machine runs all the devices your agents need, you don't need a gateway. Run a worker on its own and skip this section.

## How workers and the gateway fit together

- **Workers own the devices.** A worker is the same Simlock daemon you run on a single machine. It holds the simulators, emulators and physical devices. After it joins a gateway, it keeps serving agents on its own machine too.
- **The gateway owns no devices.** It needs Node.js 22.13 or later, and no Xcode or Android SDK. You can run it on its own machine or on one of the workers.
- **Workers connect out to the gateway.** Workers need no open inbound port and no public address. Only the gateway must be reachable, by the workers and by your agents.
- **Agents use only the gateway's address.** Everything an agent does with a lease, such as renewing it, releasing it or running a command on the device, goes through the gateway to the worker that holds the lease.

The gateway keeps its own configuration, tokens, log and usage history in `~/.simlock/gateway`, apart from any worker on the same machine. One machine can run a worker and a gateway side by side.

## How agents use a gateway

Agents use the same commands and HTTP calls as with a single worker:

- **On the gateway machine**, add `--gateway` to the CLI command, for example `simlock --gateway lease --platform ios --device "iPhone 16"`.
- **On any other machine**, use the gateway's HTTP API with an agent token made on the gateway. See [Remote agents](/simlock/docs/using-devices/remote-agents).

Through a gateway, `simlock simctl` and `simlock adb` run on the worker that holds the device. A file path in the command is a path on that worker, not on your machine. So `simlock --gateway simctl install ./MyApp.app` fails unless `MyApp.app` exists on the worker.

## What a gateway doesn't do

- **It never downloads a runtime or system image while granting a lease.** A request for an OS version that no worker has installed fails with `RUNTIME_MISSING`. Install it on the workers first; see [Install runtimes and images on workers](/simlock/docs/gateway/managing-workers#install-runtimes-and-images-on-workers).
- **It doesn't run the commands that manage one machine's devices.** `simlock cleanup`, `nuke`, `doctor`, `device add`, `device remove`, `component list`, `component remove`, `warm forget`, and `component install` without `--worker` or `--all-workers` fail on a gateway with `UNSUPPORTED_IN_GATEWAY_MODE` (exit 2). Run them on the worker.

## Send a command to the gateway or the worker

Every `simlock` command talks to one daemon on the machine where you run it. Two flags choose which one. Each can go anywhere on the command line.

| You run | It reaches |
| --- | --- |
| `simlock --gateway <command>` | The gateway on this machine. |
| `simlock --local <command>` | The worker on this machine, even when only a gateway has run here. |
| `simlock <command>` | The worker, unless this machine has a gateway and has never run a worker. Then it reaches the gateway. |

You can't use `--gateway` and `--local` together.

The pages in this section put `--gateway` in every command meant for the gateway, so each one works on any machine.

### If the command reaches the wrong daemon

- `--gateway` on a machine with no gateway stops before it connects, for every command except `daemon start`, `config set` and `mcp`:

  ```json
  {"error":{"code":"GATEWAY_NOT_PRESENT","message":"No gateway on this machine. Start one with: simlock --gateway daemon start"}}
  ```

- On a machine that runs both, a gateway-only command such as `simlock worker drain` sent to the worker fails with `UNSUPPORTED_IN_WORKER_MODE`. The message ends with "A gateway also runs on this machine: run the command again with --gateway."
