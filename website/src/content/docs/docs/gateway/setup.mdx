**Result:** workers and agents reach your gateway at an `https://` address, and you hold an operator token for it. How workers and a gateway fit together: [Workers and gateways](/simlock/docs/concepts/workers-and-gateways).

## Before you start

- A machine with Node.js 22.13 or later and Simlock (`npm i -g simlock`). It needs no Xcode and no Android SDK. It can be one of your workers.
- A host name your workers and agents can reach, such as `gateway.example.com`, if they run on other machines.
- Run every command on this page on the gateway machine, as the user who runs the gateway.

## 1. Start the gateway

<Steps>

1. Start the gateway daemon:

   ```sh
   simlock --gateway daemon start
   ```

   ```text
   Daemon running
   Console: http://127.0.0.1:4700/
   ```

   The gateway keeps its configuration, tokens, log and usage history in `~/.simlock/gateway`, apart from any worker on the same machine.

2. Start it at login, so it comes back after a reboot:

   ```sh
   simlock --gateway daemon install
   ```

   ```text
   Service installed: com.callstack.simlock.gateway (launchd)
   Daemon running
   To start after a reboot, turn on automatic login for this user.
   ```

   The service manager is `launchd` on macOS, `systemd` on Linux and Task Scheduler on Windows. What each needs to start after a reboot: [Start, stop and update the daemon](/simlock/docs/worker/daemon).

</Steps>

**Check:** `curl http://127.0.0.1:4700/v1/healthz` prints `{"ok":true}`.

A gateway always serves HTTP: agents and workers reach it that way. By default it listens on `127.0.0.1`, port `4700`, so only this machine reaches it until you put HTTPS in front.

## 2. Put HTTPS in front

Simlock does no TLS. Keep the gateway on `127.0.0.1` and run a reverse proxy in front of it on the same machine. The proxy must:

- **Pass WebSocket upgrades.** Each worker keeps a WebSocket open to `/v1/uplink`.
- **Pass streamed responses on as they arrive, unbuffered.** Lease progress, events, command output and the live screen are streamed.
- **Keep long requests open.** A command on a device may run up to 11 minutes, and a request waiting for a lease may wait for minutes.

This [Caddy](https://caddyserver.com/) configuration does all three, and gets and renews a certificate for the host name:

```text title="Caddyfile"
gateway.example.com {
	reverse_proxy 127.0.0.1:4700 {
		flush_interval -1
	}
}
```

Caddy passes WebSocket upgrades with no extra setting. `flush_interval -1` sends each streamed response on at once. When Caddy reloads its configuration it closes open WebSockets; workers reconnect within 30 seconds.

**Check:** `curl https://gateway.example.com/v1/healthz` from another machine prints `{"ok":true}`.

Workers then join with `wss://gateway.example.com`; agents and the console use `https://gateway.example.com`.

<Aside type="caution">
You can instead set `http.host` to `0.0.0.0` and let workers and agents connect to port 4700 directly. Every token, the workers' join tokens included, then crosses the network in plain text. Do this only on a network you trust completely, such as a private VPN.
</Aside>

## 3. Make your operator token

```sh
simlock --gateway token create --role operator --label alex-laptop
```

```json
{"secret":"slk_Qm9vdHN0cmFwIHRoZSBjb25zb2xlIGFuZCBzaWduIGl","token":{"id":"tok_3f9c2a1e-7b4d-4e8a-9c61-2d5f0b7a8e14","role":"operator","label":"alex-laptop","createdAt":1792569600000}}
```

Copy the `secret`: it is printed once. Paste it into the console at the gateway's address.

**Check:** the console at `https://gateway.example.com` signs you in.

## Change a gateway setting

Set a value, then restart the gateway. The value is read as JSON when it is valid JSON, else as a string:

```sh
simlock --gateway config set http.port 4800
simlock --gateway daemon stop
simlock --gateway daemon start
```

```text
Updated http.port in /Users/alex/.simlock/gateway/config.json; takes effect on daemon restart.
```

The settings you are most likely to change:

| Key | What it sets | Default |
| --- | --- | --- |
| `http.host`, `http.port` | Where the gateway listens. | `127.0.0.1`, `4700` |
| `lease.defaultTtlMs`, `lease.maxTtlMs` | Lease time to live for every lease made through the gateway. | 15 min, 4 h |
| `lease.maxPerRequester` | Leases one requester may hold across the fleet: a number, or a limit per platform. | `1` |
| `gateway.disconnectedRetentionMs` | How long a disconnected worker stays listed. A worker that holds a lease made through the gateway stays as long as the lease. | 24 h |
| `gateway.leaseRequestTimeoutMs` | How long the gateway waits for a worker to grant a lease it asked for. | 5 min |
| `gateway.execTimeoutMs` | How long the gateway waits on one command on a worker's device. Keep it above the workers' `exec.timeoutMs`. | 11 min |

Keep the gateway's `lease.maxTtlMs` at or below every worker's: the worker's own cap still applies, and the gateway logs a warning when a worker's is lower.

Sign-in through a proxy, alerts and the admission command have their own pages: [Sign people in through a sign-in proxy](/simlock/docs/gateway/sign-in-proxy), [Send alerts](/simlock/docs/gateway/alerts), [Rank or refuse requests](/simlock/docs/gateway/admission). Every key: [Configuration](/simlock/docs/reference/configuration).

Device settings, such as `capacity`, `warmPool` or `ios`, belong on the workers. A gateway ignores them, starts anyway and logs a warning for each, such as `Ignoring "capacity": it configures a worker, and this daemon runs in gateway mode.`

## When it fails

| What you see | Cause | Fix |
| --- | --- | --- |
| `Invalid config value for "http.enabled": expected true in gateway mode (a gateway is reached over HTTP)` | `http.enabled` is `false` in the gateway's `config.json`. | Set it to `true`, or remove it. |
| `"mode" is no longer a config key. …` | A `mode` key left from an older Simlock. | Remove `mode` from `config.json`. A daemon started with `--gateway` is a gateway. |
| `DAEMON_STARTUP_FAILED` (exit 1), the message names the port | Something else holds `http.port`. | Stop it, or set another `http.port`. |
| `GATEWAY_NOT_PRESENT` (exit 2) | A `--gateway` command on a machine where no gateway has started. | Run `simlock --gateway daemon start` first. |
| Workers do not join through the proxy | The proxy does not pass WebSocket upgrades to `/v1/uplink`. | Fix the proxy, then see [Add a worker](/simlock/docs/gateway/add-a-worker#when-it-fails). |
| Lease progress or command output arrives all at once | The proxy buffers responses. | Turn buffering off (Caddy: `flush_interval -1`). |
