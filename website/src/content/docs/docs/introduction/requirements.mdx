Simlock uses the platform tools already on your machine. It never installs Xcode, the Android SDK or a JDK for you. If one platform's tools are missing, that platform is not available on that machine; the other one still works.

## At a glance

| You want | Runs on | You need |
| --- | --- | --- |
| The `simlock` CLI | macOS or Linux | Node.js 22.13 or later |
| iOS simulators | macOS only | Xcode, selected, with its license accepted and its first-launch setup done |
| Android emulators | macOS or Linux | The Android SDK with the command-line tools, `emulator` and `platform-tools`, and a JDK with `JAVA_HOME` set |
| A gateway | macOS or Linux | Node.js 22.13 or later. A gateway runs no devices, so it needs no Xcode or Android SDK. |

## Set up iOS simulators

1. Install Xcode and select it:

   ```sh
   sudo xcode-select -s /Applications/Xcode.app
   ```

2. Accept the Xcode license:

   ```sh
   sudo xcodebuild -license accept
   ```

3. Run Xcode's first-launch setup:

   ```sh
   sudo xcodebuild -runFirstLaunch
   ```

4. Install at least one iOS runtime. Simlock creates simulators only on runtimes that are already installed, unless you allow a download. See [Runtimes and system images](/simlock/docs/worker/runtimes-and-images).

To watch a simulator's screen in the console, you need macOS 14 or later.

## Set up Android emulators

1. Install the Android SDK. Simlock looks in `ANDROID_HOME`, then `ANDROID_SDK_ROOT`, then `~/Library/Android/sdk`, and uses the first one that has every tool it needs. Linux has no default location, so set `ANDROID_HOME` there.
2. Install the SDK command-line tools (`sdkmanager` and `avdmanager`), from Android Studio or the [command-line tools download](https://developer.android.com/studio#command-line-tools-only). Unpack them to `$ANDROID_HOME/cmdline-tools/latest`.
3. Install the `emulator` and `platform-tools` packages:

   ```sh
   sdkmanager --install emulator platform-tools
   ```

4. Install a JDK that `sdkmanager` can run on, and point `JAVA_HOME` at it.

Before Simlock can install Android system images, you must accept the Android SDK licenses in Simlock's configuration. Until you do, an install fails with `LICENSE_NOT_ACCEPTED`. See [Runtimes and system images](/simlock/docs/worker/runtimes-and-images).

<Aside type="caution" title="An old emulator exits at once">
An emulator that is too old does not accept some of the options Simlock starts it with, and exits as soon as it starts. `simlock doctor` reports it. Run `sdkmanager --install emulator` to update it. The one exception is `-crash-report-mode never`: Simlock checks `emulator -help` and passes it only to an emulator that lists it, so an older emulator still runs Android leases without it. There a crash dump from an earlier run can open a dialog that holds the boot for 180 s.
</Aside>

## Use physical devices

An iPhone or iPad needs:

- iOS or iPadOS 17 or later.
- A USB cable to the Mac. A device you can reach only over the network cannot be enrolled.
- "Trust This Computer" accepted for this Mac, and Developer Mode on.
- To stay unlocked. A device that asks for its passcode counts as not present.

An Android phone needs a USB cable, with USB debugging allowed for this machine.

See [Enrol physical devices](/simlock/docs/worker/enrolling-physical-devices).

## Check your machine

Run:

```sh
simlock doctor
```

It prints one line on stderr for each missing tool, with the command that fixes it:

```text
Missing [ios] xcode-license: The Xcode license is not accepted. Run `sudo xcodebuild -license accept`.
Missing [android] android-emulator: The Android emulator package is not installed in /Users/dana/Library/Android/sdk. Run `sdkmanager --install emulator`.
```

`simlock doctor` checks iOS only on macOS. It checks Android everywhere. If you only want one platform, ignore the lines for the other.

<Aside type="caution" title="Restart the daemon after you install a tool">
Simlock looks for each platform's tools only when its daemon starts. After you install a missing tool, stop the daemon, then check again. The next command starts the daemon with the new tool:

```sh
simlock daemon stop
simlock doctor
```
</Aside>

`simlock doctor --fix` does not install anything. See [Install and check your machine](/simlock/docs/getting-started) for what it does fix.
