Simlock gives each of your coding agents its own iOS simulator, Android emulator or enrolled phone. An agent asks for a device and gets one that no other agent touches until it gives it back.

## The problem it solves

Run two or three coding agents on one Mac and they all see the same simulators. Each one picks whatever `simctl` or `adb` lists. Sooner or later two agents pick the same device: one installs its build over the other's, erases it mid-test, or shuts it down. Neither agent knows the other exists, so the failures look random.

## What your agent gets

Your agent asks for a device, for example "an iPhone 16 on iOS 18.4". It gets back a **lease**: a device that is booted, checked and its alone.

- If a matching device is free, the agent gets it at once.
- If none is free, Simlock creates one, as long as the machine has room.
- If the machine is full, the request waits in a queue until a device frees up.
- When the agent releases the device, Simlock deletes it. The next agent gets a fresh one.
- If the agent crashes without releasing, the lease runs out on its own after its time to live (TTL), so the device never stays stuck.

<Aside type="note" title="Simlock relies on your agents' cooperation">
Simlock does not hide other devices or block `xcrun simctl`. It works because you tell your agents to use only the device their lease gives them. [Connect your coding agent](/simlock/docs/getting-started/connect-your-agent) shows how.
</Aside>

## One machine or a fleet

- **One machine.** Install Simlock on the Mac, Linux or Windows machine where your agents run. A background process, the daemon, starts by itself the first time you run a command. This machine is a **worker**: it owns its devices.
- **A fleet.** When one machine is not enough, run a **gateway** and join several workers to it. Agents use the gateway's one address, and the gateway sends each request to a worker that can serve it.

Which one you need: [Pick your setup](/simlock/docs/introduction/pick-your-setup).

## How your agents reach Simlock

| Use | When |
| --- | --- |
| CLI (`simlock lease`, `simlock release`) | Your agent can run shell commands, or you are at a terminal. On another machine, the CLI talks to the farm with a token. |
| MCP server (`simlock mcp`) | Your agent uses the Model Context Protocol. Its tools lease and release a device and run commands on it. |
| HTTP API | Your tool runs on another machine and makes its own HTTP calls. It needs a token from the operator. |
| Node client (`simlock/client`) | You write a Node.js tool and want to lease devices without the CLI. |

A web console shows devices, leases and the queue in your browser. See [Turn on the web console and HTTP](/simlock/docs/worker/console-and-http).
