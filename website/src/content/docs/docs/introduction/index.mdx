Simlock gives each of your coding agents its own iOS simulator or Android emulator. An agent asks for a device and gets one that no other agent touches until it gives it back.

## The problem it solves

Run two or three coding agents on one Mac and they all see the same simulators. Each one picks whatever `simctl` or `adb` lists. Sooner or later two agents pick the same device: one installs its build over the other's, erases it mid-test, or shuts it down. Neither agent knows the other exists, so the failures look random.

## What your agent gets

Your agent asks Simlock for a device, for example "an iPhone 16 on iOS 18.4". It gets back a **lease**: a device that is booted, checked and its alone.

- If a matching device is free, the agent gets it at once.
- If none is free, Simlock creates one, as long as your machine has room.
- If the machine is full, the request waits in a queue until a device frees up.
- When the agent releases the device, Simlock deletes it. The next agent gets a fresh one.
- If the agent crashes without releasing, the lease runs out on its own after its time to live (TTL), so the device never stays stuck.

<Aside type="note" title="Simlock relies on your agents' cooperation">
Simlock does not hide other devices or block `xcrun simctl`. It works because you tell your agents to use only the device their lease gives them. [Connect your agent](/simlock/docs/getting-started/connect-your-agent) shows how.
</Aside>

## One machine or a fleet

**One machine.** Install Simlock on the Mac or Linux machine where your agents run. Simlock runs a background process, the daemon, which starts by itself the first time you run a command. This machine is a **worker**: it owns its devices.

**A fleet.** When one machine is not enough, run a **gateway** and join several workers to it. Agents talk to the gateway's single address, and the gateway sends each request to a worker that can serve it. Workers connect out to the gateway, so they need no open inbound port. See [When you need a gateway](/simlock/docs/gateway).

## How your agents reach Simlock

| Use | When |
| --- | --- |
| CLI (`simlock lease`, `simlock release`) | Your agent can run shell commands, or you are at a terminal. |
| MCP server (`simlock mcp`) | Your agent uses the Model Context Protocol. Its tools list, lease and release devices and run commands on them. |
| HTTP API | Your agent runs on another machine. It needs a token from the operator. |
| Programmatic client (`simlock/client`) | You write a Node.js tool on the same machine and want to lease devices without the CLI. |

Simlock also has a web console that shows devices, leases and the queue. See [Web console](/simlock/docs/worker/console).
